# D-110. One board, and it is not in this repo

**What changed.** Every document in this repository that functioned as a queue
of work not yet done was deleted, and every open GitHub issue was closed. 100
files went:

| Set                            | Count | What it was                                                                                                                                                                                                                           |
| ------------------------------ | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Root files                     | 6     | `LAUNCH_BLOCKERS.md`, `POST_LAUNCH_BACKLOG.md`, `PRELAUNCH_AUDIT_2026-06-16.md`, `SPINOUT_AUDIT_2026-07-26.md`, `TASK_RUNNER_DESIGN.md`, `listening-docs-setup-prompt.md`                                                             |
| `docs/development/plans/`      | 11    | the roadmap tree — custom domains, referrals, LATAM expansion, Stripe modernization, student acquisition, material editing, captions-agent delivery, Oracle box consolidation, lesson-insights taxonomy, Alicia Moreno product issues |
| `docs/architecture/*_AUDIT.md` | 5     | video architecture, LiveKit captions, Cloudflare platform, teacher-onboarding activation, video-call PostHog — each headed "Report — not yet a decision"                                                                              |
| `docs/archive/`                | 72    | the whole tree: audits (incl. `TECH_DEBT.md`), auth migration plans, product plans, GTM collateral, the launch record, lesson-insights phase docs                                                                                     |
| `docs/deployment/`             | 6     | `SECURITY_PLAN.md`, `GOOGLE_PLAY_PUBLISHING.md`, `GOOGLE_SIGNIN_SETUP.md`, `SES_PROVISIONING.md`, `STUDENT_LAUNCH.md`, `LESSON_INSIGHTS_ENABLEMENT.md`                                                                                |

From now on the single home for an open SpiralClass action is the board in the
maintainer's private planning repository, tagged to the `spiralclass` stream. The
only spiralclass items on it are the three sourced from the 2026-08-05
pre-launch findings review.

GitHub Issues are not a personal backlog either. They are reserved for
machine-filed reports (the Sentry integration) and for anything a pull request
closes with `Closes #N` — things whose state changes without a human
remembering to edit a list.

**Why it likely changed.** Three homes existed for the same thing and the
markdown one rotted fastest, because nothing closes a bullet in a file.

- `POST_LAUNCH_BACKLOG.md` was last refreshed 2026-06-07. Two months later it
  cited 11 documentation paths that had not existed since the 2026-07-24
  reorg, carried a struck-through "upgrade to Supabase Pro" item that D-89 had
  made meaningless, and pointed at `docs/engineering/TECH_DEBT.md`, which had
  moved into `docs/archive/audits/`.
- `LAUNCH_BLOCKERS.md` had already been marked a historical snapshot by its own
  header and still told the reader to check the Vercel dashboard and Supabase
  migrations — both decommissioned in D-89.
- That board decided on 2026-08-05 that it is the single board, and a drift
  check there exists to catch second copies. It missed both of
  these: its shadow-backlog check counts `- [ ]` checkboxes, and these files
  used plain bullets. The two largest second backlogs in the tree were
  invisible to the script written to find them.

Deleting beat migrating. Migrating ~40 deferred engineering items onto the
board would have drowned a board whose purpose is deciding what a fortnight
contains, and re-homing them in Issues would have created a 40-item list that
nobody reads either. The items that mattered survive as decisions, tests, and
CI gates; the rest were a menu, and the menu was two months stale.

Archiving beat nothing either — `docs/archive/` was 72 files that its own
README had to warn readers not to treat as policy. Git history is an archive
that cannot be mistaken for current policy, so the archive tree went with the
rest.

**What was affected.**

- **`mkdocs.yml`** — the `redirects` map lost 28 of its 30 entries. Only
  `engineering/ERD.md` and `engineering/multi-teacher-students.md` still had
  live targets; the rest redirected to deleted or already-nonexistent pages,
  which is a 404 with extra steps. Nav is generated by `awesome-nav` from the
  folder tree, so no nav list needed pruning.
- **96 dangling references across 85 files** were repaired: dead markdown links
  collapsed to plain text, dead parentheticals dropped, and dead paths in code
  comments replaced with a plain-language descriptor so the rationale still
  reads. `scripts/check-leaks.baseline.json` lost 3 entries for deleted files.
- **Agent context** — `CLAUDE.md`, `docs/README.md`,
  `docs/development/documentation.md` and the four section READMEs now
  state the no-backlog rule rather than describing the deleted trees.
- **Applied Prisma migrations were not touched.** A few of their comments point
  at deleted docs; editing them would break `prisma migrate deploy`'s
  checksums, and CLAUDE.md already sanctions leaving them.

**Unresolved risks.**

- **Operational knowledge went with the runbooks.** `GOOGLE_PLAY_PUBLISHING.md`,
  `GOOGLE_SIGNIN_SETUP.md` and `SES_PROVISIONING.md` documented how to do
  things that will have to be done again, and their checkboxes were procedure
  steps rather than work owed. This was a deliberate operator choice on
  2026-08-08 with the tradeoff stated. Recover from git history if a Play
  Store submission or an SES re-provision comes up; do not restore the files
  wholesale.
- **The lesson-insights enablement checklist is gone.**
  `LESSON_INSIGHTS_ENABLEMENT.md` held the phase-by-phase detail; it is tracked
  outside this repository now.
- **~440 references to pre-2026-07-24 doc paths (`docs/engineering/…`,
  `docs/ops/…`, `docs/product/…`, `docs/launch/…`) remain in code comments.**
  They were already stale before this change and are out of its scope, but they
  are the same failure in a different costume and will mislead an agent that
  trusts them.
- **Nothing enforces this yet.** The rule lives in `CLAUDE.md` and this
  decision. That drift check should be taught to report on bullet density
  in a file whose name matches its shadow-backlog pattern, not only on
  checkboxes, or the next `BACKLOG.md` will be just as invisible as the last
  one.
