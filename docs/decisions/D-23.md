# D-23. Admin sees lesson-insights pipeline STATUS, never voice-derived content (operational view only)

**Status: Active.** Scopes what the super-admin panel may surface for the
lesson-insights tables. Builds on the controller framing in [D-05](./D-05.md) and
the voice-data posture in [D-21](./D-21.md) / [D-22](./D-22.md).

**What was decided.** The admin panel gets a purpose-built **pipeline-health**
view (`/admin/lesson-insights`, superadmin-gated) that shows row **statuses,
counts and timestamps only** — capture → transcript → insights → profile → brief
funnel, stuck/failed callouts, recent-capture metadata. It deliberately does
**NOT** render any voice-derived **content**: no transcript utterances, no
pronunciation scores, no insight text/evidence quotes, no learning-profile text,
no links to the raw audio. A generic "browse every table" admin grid was
explicitly rejected.

**Why.** Those tables hold the most sensitive data in the system — voice-derived
personal data, possibly a minor's (D-21/D-22). A passive super-admin content viewer would be a new,
broad access path that cuts against the minimization posture, and the data is
teacher-owned (D-05) and excluded from the student data export. The operational
_status_ (is the pipeline flowing? where did it stall?) carries the real
day-to-day value — it answers "captures land but no transcript" at a glance —
while carrying essentially none of the sensitivity. So the split is: status yes,
content no.

**What was affected.** New `app/admin/lesson-insights/page.tsx` (counts/statuses/
timestamps), a nav entry gated to `superadmin`. No content columns are read. No
change to the pipeline itself or to tenant data.

**Unresolved risks / future work.** If reading real content platform-side is ever
needed (AI quality QA, the Deepgram/Azure bake-off), it must be a **deliberate,
audited capability** — surfaced through the admin audit trail, not the default
grid. Reading real students' transcripts platform-side is the same exposure the
consent gate exists to contain. The existing
audited super-admin **impersonation** path is the right shape if a single-case
look is required before then. Do not add transcript/insight/profile content to
this operational view.
