# D-78. Teacher-configurable AI material style (tone, learner age, language variety, free-text note)

**What changed.** Teachers get an account-level **"AI material style"** setting
that tunes how the AI writes every material they generate. Four controls, all
optional and all nullable (unset = today's behavior, byte-for-byte):

- **Tone / register** — `casual | friendly | neutral | academic`. The headline
  fix for "the AI writes too academically": a teacher picks _Casual_ and every
  future material is informal.
- **Learner age** — `kids | teens | adults`, pitched into tone and examples.
- **Language variety** — free text (e.g. "Mexican Spanish", "British English"),
  steering vocabulary/spelling/cultural references in the taught language.
- **Custom instructions** — a bounded free-text note appended to the prompt for
  every material ("the prompt is editable" without exposing the raw prompt).

New columns on `teachers`: `material_tone`, `material_learner_age`,
`material_language_variety`, `material_custom_instructions` (migration
`20260719000000_add_teacher_material_style`, additive + nullable).

**Why it likely changed.** A teacher reported the generated materials were too
academic and wanted a _persistent_ fix across all materials, not a per-generation
tweak. Making it account-level (read server-side) means one setting restyles
class content, library materials, streamed generation, and Edit-with-AI refine
alike — and every surface inherits it without changing any generation call.

**What was affected.**

- **Prompt builder** (`apps/web/src/lib/materials/prompt.ts`): four directive
  builders (`toneDirective`/`learnerAgeDirective`/`languageVarietyDirective`/
  `customInstructionsDirective`) append lines to the `system` array of
  `buildMaterialPrompt` (all four) and `buildMaterialRefinePrompt` (tone,
  variety, custom). They are placed AFTER, and worded to defer to, the D-72
  language-axis and the student-name-discipline rules — a hostile custom note
  can't reintroduce the "French teacher gets a Spanish lesson" or wrong-student
  bugs.
- **The one funnel** (`lib/materials/handlers.ts#resolveSubject`): its `select`
  and return now carry the four style fields, so every generation path picks
  them up (the same "read once from the teacher" pattern it already used for
  `target_language`).
- **Shared** (`packages/shared`): `materialStyleSchema(locale)` validator (used
  by the server action), `MaterialStyleSettings` API type, and a
  `materialStyle` NavItem in the `content` group (surfaces on the "Materiales"
  menu).
- **Web UI**: a dedicated `/settings/materials` page + `material-style-form.tsx`,
  linked from the Materials hub header; `saveMaterialStyleAction`; catalog copy.
  Generation request payloads are unchanged.
- **Decision on editability**: presets + an appended free-text note, NOT a fully
  editable raw system prompt — the language-axis and name safeguards must always
  win, and exposing the raw prompt would let a teacher break them.

**Unresolved risks.** The end-to-end flow re-saves the loaded style unchanged
(shared-fixture cleanliness) rather than asserting a tone flip; a real pass is
the confirmation. Tone directives are English instruction strings
regardless of the material's output language (consistent with the rest of the
system prompt) — fine for the model, but not localized. The prompt effect itself
is only observable by generating a material and reading it (there's no unit test
that asserts the _model_ actually writes more informally, only that the directive
is present).
