# D-83. Teacher → Student invitation & onboarding flow

**What changed.** Teachers can now invite the students they already teach onto
the platform, and those students can join with minimal friction. This is an
acquisition-of-known-contacts flow, not a marketplace (holds the D-24 line).

New surface:

- **Data.** One new table, `student_invitations` (+ `InvitationStatus` enum),
  each row tied to a roster `Student` (provisioned with an onboarding hold, like
  the manual add-student flow) and a teacher. The emailed link carries a 256-bit
  token; only its SHA-256 hash is stored. A partial unique index enforces at most
  one **pending** invitation per `(teacher, email)`.
- **Lib.** `apps/web/src/lib/invitations/**` — token mint/hash, effective-status
  derivation (expiry is computed, never written), advisory-locked provisioning,
  resend (token rotation), cancel, idempotent acceptance, bulk parse/validate,
  the branded email builder, the dashboard aggregator, and the pending-invite
  nudge. Benefit copy keys are shared cross-platform via
  `@spiralclass/shared/invitations`.
- **Acceptance** delegates linking to the existing `resolveLinkedStudent`
  (honouring the one-login-binds-the-oldest-rostered-row identity-set
  invariant), enforces an inbox-match hijack guard, refuses a Teacher identity,
  and is idempotent. It reuses the existing email-OTP / Google auth rails and the
  existing sign-in `next`/`email` params for resume-after-login — no new auth.
- **Web UI.** `/i/[token]` accept page (public, deep-link target) and a teacher
  invitation dashboard at `/dashboard/students/invitations` (funnel stats +
  filterable roster + resend/cancel/copy-link) with a single / paste-CSV /
  multi-select-roster invite form and a confirmation screen.
- **Email.** A branded invitation email (teacher name + photo, benefits, accept
  CTA), sent one-off via the existing Resend/SES rail (not the dispatcher — the
  recipient isn't a platform user yet). The `EmailHtmlContent` shell gained
  optional `avatarUrl` + `bullets`.
- **Reminders.** A daily Inngest cron nudges teachers about still-pending
  invitations after 3 days (once per invite; standalone email, off the Tier-2
  dispatcher exhaustiveness surface).
- **Analytics.** The full funnel is instrumented on the existing PostHog
  `ServerEvent` union (`invitation_created/sent/resent/cancelled`,
  `invitation_bulk_completed`, `invitation_opened/accepted/existing_account_linked`).

**Why it likely changed.** Teachers primarily bring existing students; the
platform had roster provisioning + silent onboarding but no way to actually
invite a student to claim their account. The invite is the missing introduction
step between "staged on the roster" and "logged-in student".

**What was affected.** New table + migration
`20260721000000_add_student_invitations`; `Teacher`/`Student` gained an
invitations relation; the email shell, the AASA universal-link component list,
the shared validators + i18n catalog, the analytics
union, and the Inngest function registry all extended. No existing behaviour
changed. Acceptance rides on `resolveLinkedStudent` and the existing sign-in, so
no auth-provider change. Tier-2 paths touched (inngest/**, prisma/**) → shipped
via PR.

**Unresolved risks.**

- **Deferred deep link after install.** A brand-new device that taps the link,
  installs, then opens cold does not yet resume the specific
  invite (nothing persists the inbound token across an install). The link itself
  keeps working — the student re-taps it after install — but there's no
  install-referrer capture. Follow-up.
- **Bulk send is inline + sequential** (cap 200). Fine at current volumes; a
  very large paste is bounded by the cap (surfaced, not silently dropped) and
  could be moved to a background fan-out later.
- **Copy-link rotates the token** (the stored hash is overwritten), so copying a
  link invalidates any previously-emailed link for that invitation. Intended
  (the copied link is always the canonical current one) but worth knowing.
- **`app_installed_from_invitation`** analytics is specced but not emitted (no
  install-referrer wiring yet).
