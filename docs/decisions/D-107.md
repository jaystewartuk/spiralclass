# D-107. Materials opens on a level picker, not on every material at once

**What changed.** The teacher's Materials surface (`/dashboard/materials`) now
opens on a **level picker** — one row per
level in her ladder plus an "All materials" escape hatch — instead of the flat,
fully-populated list it has always opened on. Selecting a level opens that
level's **shelf**, where the complete existing control set (category / type /
visibility filters, sort, search, active-vs-archived, pagination) is unchanged.

The three-way state (picker / one shelf / all levels) is resolved by one shared
pure function, `resolveMaterialsBrowseMode()` in
`packages/shared/src/materials-browse.ts`, so the two platforms cannot drift.
Web encodes it in the **existing** `?level=` param — absent = picker,
`?level=<id>` = shelf, `?level=all` = flat list — so every existing deep link
keeps working.

Explicitly **not** folders. No new table, no migration, no `parentId`, no move
operation, no drag-and-drop. A shelf is a view over `LibraryMaterial.levelId`,
which every library material already carries.

**Why it likely changed.** Early user research: a teacher thinks
_"what do I have for A2?"_ first and only then thinks about filtering.
The page inverted that — it opened on everything and demoted level to the third
of four peer chip rows, defaulting to "All".

That instinct is structural, not merely a Google Drive habit. `levelId` is the
only axis on a material that is simultaneously **mandatory** (every library row
has one; the add form requires it), **single-valued**, and **totally ordered**
(`Level.position`) — so it can partition the library. Focus tags are optional
and many-per-item (a material can be grammar + format + theme at once), so they
can only ever narrow a set. The rest of the product already treats level as
primary: the student browse ceiling is level-based, the three `visibility` modes
are _defined relative to_ level, and the class page's auto-surface shelf is "at
their level". The flat list was the outlier.

Folders were rejected because they would duplicate `Level` as a second
hierarchy, require move semantics and empty-folder handling, and destroy the
many-categories-per-item property that makes the tag taxonomy worth keeping.
Re-tagging a material to B1 re-homes it here with no drag and no orphaned
folder.

The same level-first idea reaches the class-detail page's
**attach-from-library** picker, but in a different shape. That control is a
multi-select inside a larger form, so a hub-and-spoke drill-down would either
drop a selection made under another level or hide that one exists. It instead
keeps one list, grouped under level headings in ladder order
(`groupMaterialsByLevel`), with an optional single-level narrowing and the
checked set held outside the list so a cross-level selection survives narrowing
and still submits. It is deliberately **not** defaulted to the class student's
level — the class page already has a separate opt-in "at their level" shelf
doing that, and the two shouldn't collapse into each other.

**What was affected.**

- New: `packages/shared/src/materials-browse.ts` (+ tests),
  `apps/web/src/lib/library/materials-href.ts` (+ tests, extracted from four
  near-identical inline closures in the page),
  and `apps/web/src/app/(app)/dashboard/materials/level-hub.tsx`.
- Six new catalog keys across all three locales.
- `useLibraryBrowser` gained an optional `enabled` flag (defaults true) so the
  picker fetches nothing. The in-call "My library" browser
  (`CallMaterialsPanel`) deliberately keeps the **flat** list — mid-lesson a
  two-tap drill-down is a cost, not a feature — and is untouched by this.
- The hub costs **zero** material queries and mints no signed URLs, so landing
  on Materials is cheaper than before.

Three sub-decisions were taken by the teacher directly, not inferred:
a shelf shows **only** materials filed at that level (not the student-facing
`at_or_below` view); the picker shows **no per-level counts**; and there is
**no** sub-grouping by `unit` inside a shelf — the existing filters suffice.
`LibraryMaterial.unit` therefore remains stored-but-unsurfaced, as before.

**Unresolved risks.**

- The picker assumes a manageable level ladder (the seeded CEFR six). There is
  still **no level-management UI** on either platform, so a teacher cannot
  rename/add/reorder levels — that gap now sits on a surface where levels are
  the primary navigation rather than one filter row among four, which raises
  its priority.
- A shelf being _exact-level_ means a teacher hunting for "something an A2
  student could use" must check A1 and A2 separately, since her students see
  `at_or_below`. This was her explicit preference; if it chafes, the
  level-and-below toggle is a small additive change (`visibleLevelIds()` in
  `lib/levels.ts` already computes the id set).
- Only one teacher was observed. The design is reversible — the flat list is
  still one click away at `?level=all` and nothing about the data model or the
  filter layer changed — but the landing-view choice itself is a bet on an
  n=1 observation.
