# D-43. Rename the non-prod "staging" tier to "preview"

**What changed.** The non-production deployment tier was renamed from **staging**
to **preview** everywhere, and the legacy product slug **`clases-estructuradas`**
was unified to **`spiralclass`**. Concretely:

- **Domain:** `staging.spiralclass.com` → `preview.spiralclass.com` (Supabase
  project renamed `spiralclass-staging` → `agendaprofe-preview`; the immutable
  project **ref `utersxembwkpcuhpwegb` is unchanged**, so the `sync-preview`
  host-guard still holds).
- **Web:** `isProductionDeployment()` / CSP `vercelLiveEnabled()` domain fallback
  keys on `"preview"` instead of `"staging"` — the rename otherwise made a
  preview deploy mis-read as production. `appName` non-prod label → `AP Preview`.
- **Inngest:** app id `clases-estructuradas` → `agendaprofe` (`inngest/client.ts`).
- **CI:** `staging-inngest-sync.yml` → `preview-inngest-sync.yml` (it polled
  the old domain — a live break the rename also fixed).
- **Scripts:** `pick-staging-update.mjs` → `pick-preview-update.mjs`;
  `apps/web/scripts/sync-staging/` → `sync-preview/` (`sync:staging` →
  `sync:preview`, `SYNC_STAGING_SKIP_HOST_GUARD` → `SYNC_PREVIEW_SKIP_HOST_GUARD`).
- **Seed identities:** `@spiralclass-staging.invalid` → `@spiralclass-preview.invalid`
  and `@clases-estructuradas.test` → `@spiralclass.test` (seed + E2E).

**Why it changed.** The tier is Vercel's **Preview** environment — calling it
"staging" created a channel/branch/env
name mismatch that repeatedly caused confusion (which bucket does `staging`
read?). "preview" removes the mismatch. `clases-estructuradas` was a pre-rename
product name with no reason to persist as an identifier.

`apps/web/src/lib/{env.ts,csp.ts,auth/server.ts,inngest/client.ts}`,
`apps/web/scripts/{seed.ts,sync-preview/}`, the E2E specs, and operational docs
(`CLAUDE.md`, `DEVELOPMENT_WORKFLOW.md`, `RELEASE_AND_STAGING.md`, orientation,
the Google-Sign-In runbooks). The **`main` git branch
was deliberately NOT renamed** — a branch (code line) and an environment (where
it deploys) are different axes; `main` → preview, `production` → production
stays.

**Unresolved risks / follow-ups.**

- **DB re-seed required.** Seed identity domains changed, so the preview DB must
  be re-seeded before the E2E authenticated flows pass.
- **Inngest app re-registers.** The `agendaprofe` app registers fresh on next
  sync; the old `clases-estructuradas` app + its run history are orphaned.
- **GitHub branch protection.** Required-status-check names that referenced the
  old workflow filenames must be updated in repo settings.
- **Local dev.** Rename `apps/web/.env.staging.local` → `.env.preview.local`.
- **Applied migration left intact.** `20260704020000_…/migration.sql` still
  comments `scripts/sync-staging/` — not edited (Prisma checksums migrations).
- **Historical decision records** such as [D-26](./D-26.md) keep their original
  "staging" language; this D-43 is the current-policy label of record.

**Post-incident (2026-07-07) — what the rename actually broke.** Two silent
outages on preview traced back to this rename; both would recur on any future
rename of the same identifiers if the checklist below is skipped.

1. **Total notification outage (email + push).** Renaming the Inngest app id
   `clases-estructuradas → spiralclass` orphaned every registered function.
   Inngest does **not** auto-re-sync a renamed app — events kept arriving with
   **zero subscribers**, so `dispatchNotificationFn` (the single fan-out to both
   email and push) never ran and all notifications sat in `status='queued'`.
   Fixed by a **manual re-sync** in the Inngest dashboard (`.../api/inngest`) for
   the affected environment. Guarded now by `tests/inngest/app-id.test.ts` (a
   tripwire on `INNGEST_APP_ID`).
2. **Push silently down (fell back to email).** Renaming the preview package
   created a brand-new registration with no push credential attached, so every
   push returned `InvalidCredentials`; the dispatcher logged it, fell back to
   email, and (before the hardening below) wrote **no error on the row** — so
   the DB looked healthy. Now the dispatcher persists `metadata.pushError` on
   non-retryable push failure so this is visible in the DB, not just logs.

**Rename checklist (env tier / app id).** Before shipping a
rename of any of these identifiers, do all of:

- [ ] **Inngest app id** — after deploy, **manually re-sync** the app in the
      Inngest dashboard for **prod AND preview**; archive the stale app. Update
      `INNGEST_APP_ID` + its tripwire test.
- [ ] **Preview DB re-seed** orphans `device_tokens` (their `recipient_id`s point
      at the old student/teacher UUIDs). Test devices must **re-register** (reopen
      the app) before push tests pass — an orphaned token silently resolves to
      email-only, not an error.
- [ ] Verify a real push end-to-end after the above (a direct send to a
      freshly-registered token is the fastest check).
