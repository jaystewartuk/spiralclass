# D-203. The class transcript is kept whether or not subtitles are shown; the captions switch is only the display

**Status.** Active · reverses the "insights only run for a captioned class"
trade-off and the rejected-alternative "a second recogniser independent of the
captions toggle" in [D-189](./D-189.md) · narrows [D-185](./D-185.md) (a
browser recognises for the transcript, not only for captions) · keeps
[D-21](./D-21.md) and [D-22](./D-22.md) as they were.

**What changed.** The teacher's captions switch no longer decides whether a
class's transcript is kept. Recognition runs, and every finished line is kept,
whenever the class's session says `transcriptCapture` — the flag plus the
pairing's recorded insights consent (guardian's for a minor, the buyer's
confirmation for a class for two), still decided on the server in
`lessonTranscriptCaptureOk`. The switch now controls the DISPLAY only: with it
off, the recognisers run but nothing is translated, published or shown.
Concretely, `BrowserCaptions.sync` starts recognisers when `captionsOn ||
session.transcriptCapture`; the call fetches the session on connect for both
roles rather than at the first toggle; `transcriptKept` (the "Learning notes
on" indicator and the start notice) follows `transcriptCapture`, not the
switch; and `/api/captions/stt-token` warrants the phone-to-phone Deepgram
stream when the transcript is kept, with the switch off.

**Why.** The premise of D-189 was that one visible switch is the price of no
silent capture, and that "insights only run for a captioned class" was an
acceptable trade. Measured in use, it is not. The teacher turns subtitles off
by default so students make the effort to understand, and turns them on only
at a comprehension block (22 Oct 2026 call). A student who no longer needs
subtitles therefore gets no transcript, no findings and no learning profile at
all — the students who have progressed furthest are the ones the profile
starves. The failure is invisible: nothing errors, the profile simply never
appears.

**What was considered and rejected.**

- **Tell the teacher to leave subtitles on.** Defeats the teaching method that
  produced the progress, and shows the student the translation she is trying to
  do without.
- **A separate "keep notes" toggle.** Another switch to forget; the failure
  would just move. Consent is already recorded per pairing, which is the
  decision that matters; the teacher's switch never was one.
- **Audio capture.** Unchanged from D-189: text only, never audio.

**What it constrains.**

- **Consent is still decided on the server, per class, for both speakers.**
  `lessonTranscriptCaptureOk` is the one place. A class without recorded
  consent runs no recogniser for the transcript and keeps nothing; the tests
  assert both halves (`tests/captions/browser-captions.test.ts`,
  `use-browser-captions.test.tsx`).
- **A student's speech is recognised only with her captions consent as well**
  (D-22's separate consent for sending her speech to a recogniser). Transcript
  capture does not widen that: `assignRecognizers` still returns nothing for
  her without it, so a pairing with insights consent but no captions consent
  gets a teacher-side transcript only, as before.
- **The indicator is not optional.** Recognition running with subtitles hidden
  is exactly the case D-21 warns about, so `transcriptKept` renders while the
  session says the transcript is kept, for both participants, whether or not a
  caption is on screen. The notice now appears when the call connects, not
  when the switch is flipped.
- **The switch must stay display-only.** A change that makes capture depend on
  it again reopens this record. Flipping it mid-class never restarts a
  recogniser.
- **No translation without display.** With the switch off, no line is sent to
  the translation route or the on-device translator.

**What was affected.** `lib/captions/browser-captions.ts`,
`lib/captions/use-browser-captions.ts`, `components/video/class-call.tsx`,
`app/api/captions/stt-token/route.ts`, `packages/shared/src/caption-recognition.ts`
(`cloudRecognitionRefusal`), `packages/shared/src/legal/privacy-policy.ts`,
`docs/features/{lesson-insights-reports,live-calls-video}.md`, and the tests
above.

**Trade-offs accepted, and unresolved risks.**

- **Cost.** A phone-to-phone class (no browser able to recognise) now streams
  both speakers to Deepgram for every consenting class, not only captioned
  ones: about $0.48–0.77 a class at $0.0048 a minute, against the free credit
  (D-189). Desktop-Chrome classes cost nothing. Not measured since this
  change; watch Deepgram usage after the first week.
- **Capture is quieter.** With no caption on screen, the top-bar icon and the
  start notice are the only sign. They were judged sufficient by D-189 for the
  captioned case; this is the same indicator in a case with less else on the
  screen. Revisit if a student or guardian is surprised.
- **The privacy policy changed.** Three sentences said "where a teacher has
  live captions on"; they now describe capture by consent alone. Jay approves
  the wording before it ships.
- **`LIVE_CAPTIONS_ENABLED` and the translate key still gate the whole
  feature**, including a transcript with no captions shown. Decoupling them is
  not done here.
- **An extra config read per class** (the session is fetched on connect for
  both roles). A student who never has captions or a transcript costs one
  request.
