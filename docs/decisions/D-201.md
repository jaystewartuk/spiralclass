# D-201. A model call site ships with an eval set, and the teacher's verdict on its output is a figure the admin can read

**Status.** Active. Narrows [D-87](./D-87.md): a model constant still moves by
call shape and cost, but from now on it moves with a before-and-after eval run
in the PR.

**What changed.** Two things, one rule.

1. **Every surface that asks a model for words is registered**
   (`apps/web/src/lib/evals/registry.ts`), and a guard holds the registry to
   the tree. A surface is one prompt shape — one builder, one parser, one place
   the output lands. Two surfaces have an eval set today, lesson insights and
   the homework review draft; the other eight are a named list that may only
   shrink. A new prompt shape arrives with its cases and its checker or the
   gate fails.
2. **The verdicts teachers already give are read back as a figure.** A lesson
   insight is confirmed or dismissed; a homework draft is the one a sent
   feedback started from or one a regenerate marked discarded. The admin
   overview shows kept-over-decided for each, counts only, test accounts out.
   The homework half needed two writes that the schema had columns for and no
   code ever made: `HomeworkFeedback.aiDraftId` and
   `HomeworkAiReviewDraft.discardedAt`.

The rule: **a change to a prompt builder or a model constant quotes the eval
run before and after**, from `pnpm evals` with `--out` and `--baseline`. The
run is never part of the gate.

**Why.** Six files send Messages requests and every test of them mocks the
client. Whether the output was any good was a claim nothing verified, which is
the fourth rule of `CLAUDE.md` describing a claim that is eventually false.
D-87 moved five model defaults on cost alone and was revised before production
because one of them would have 400'd every call; the quality half of that move
was never measured at all, before or since. The teachers' verdicts were already
in two tables, unread.

**What was considered and rejected.**

- _A model judging the model._ Rejected as the first layer. A rubric judge is
  cheap to write and calibrated against nothing; it reports its own taste as a
  score. The checks that ship are the prompt's stated rules as functions —
  evidence is a student's words that were actually said, a timestamp lands on
  the cited line, a pronunciation finding without audio scores needs a teacher
  signal, a quoted span in a homework correction appears in the submission.
  A judge can come later, calibrated against the confirm/dismiss record this
  decision starts reading.
- _Running evals in the gate._ Rejected: a live run spends money, needs a key
  and the network, and scores rather than passes. The gate stays hermetic
  (D-157). What the gate holds is the registry and the shape of the
  cases, which cost nothing.
- _Committing real lesson material as cases._ Rejected: transcripts are
  personal data (D-22). The committed cases are synthetic; real ones live
  outside the repository and are pointed at with `EVAL_CASES_DIR`.
- _A `model` column on `LessonInsight` so the live figure splits by model._
  Deferred. It is a migration, only one migration-bearing branch is in flight
  at a time, and the offline run is the before/after measure for a model
  change. The live figure is for drift, and drift is visible without it.

**What it constrains.**

- A file that sends a Messages request is in `AI_CALL_SITES` or the gate
  fails. Retire the entry with the call.
- `ALLOWED_PENDING` in `tests/config/ai-evals.test.ts` only loses lines.
- A PR that edits a prompt builder, a `*_MODEL` constant or the
  `anthropicModel()` default quotes its eval run. A reviewer who does not see
  two numbers asks for them.
- Committed cases name nobody. The guard rejects an email address or a phone
  number in `evals/cases/`.
- The acceptance figure stays counts only (D-22). It never shows an insight's
  text, a student's words or a teacher's name.

**What was affected.**

- `apps/web/src/lib/evals/` — registry, case schema, checks, report.
- `apps/web/scripts/evals.ts`, `pnpm evals`.
- `apps/web/evals/cases/` — five synthetic cases.
- `apps/web/src/lib/ai/quality-metrics.ts` and the admin overview.
- `apps/web/src/lib/homework/feedback.ts`, `ai-review.ts` — the two writes.
- `generateInsights` takes an optional model, for the runner only.
- `tests/config/ai-evals.test.ts`.
- `docs/development/testing.md`, "Model evals".

**Trade-offs accepted, and unresolved risks.**

- The homework runner restates the request `generateHomeworkAiReview` sends,
  because that module is `server-only` and cannot load outside Next. The
  guard holds the default model id in step; it does not hold `max_tokens` or
  the tool definition. A divergence there would make the eval measure a
  request production does not send.
- "The draft this feedback started from" is inferred server-side as the latest
  live draft for the attempt when feedback is sent. A teacher who read the
  draft, ignored it and wrote her own counts as having used it. The rate is
  therefore a ceiling on draft usefulness, and the card's wording says "used",
  not "approved".
- Five synthetic cases are a smoke test, not a benchmark. The figure that
  means something arrives when the private case directory holds real,
  pseudonymised lessons and the teacher's confirm/dismiss record is large
  enough to calibrate against. Nothing checks that either has happened.
- No language check. Whether findings came back in the teacher's reading
  language rather than English is the failure that has already shipped twice
  (D-72) and the checks cannot see it without a language detector. It is
  the first thing a judge layer should do.
