# D-65. R2 buckets split preview/production, fixed to the real live bucket list, and R2 env-var reads consolidated onto one shared map

**What changed.** Three related fixes to the R2/Vercel OpenTofu scaffold —
written a fortnight earlier with no live API access to check it against —
triggered by moving `preview.spiralclass.com` off Vercel onto Fly:

1. **`infra/cloudflare-r2/variables.tf`'s `buckets` list was wrong.** It
   assumed three buckets (`teacher-photos`, `student-photos`,
   `class-materials`) uniformly named after
   `apps/web/src/lib/storage/provider.ts`'s `R2_ENV_PREFIX` map. The real
   live production buckets are four: `agendaprofe-class-materials`,
   `agendaprofe-teacher-photos`, `agendaprofe-chat-audio`,
   `agendaprofe-recordings` — the last two aren't in `provider.ts` at
   all (they're read directly by `chat-audio.ts`/`chat-video.ts` and
   `recording.ts`/`lesson-audio-store.ts`, see point 3). `student-photos`
   is dropped entirely: it was speculative scaffolding with no real bucket
   and no configured env var anywhere. Two more real Cloudflare-account
   buckets are deliberately **not** in this list either:
   `agendaprofe-backups` (DB backups — `r2-admin.ts` already fences this
   off by name from the app's own admin surface, on separate credentials,
   not something this app-storage module should touch) and
   `agendaprofe-teacher-videos` (0 objects, zero references anywhere in
   the codebase — same "don't provision a bucket nothing reads" reasoning
   as dropping `student-photos`). The bucket names themselves were also
   corrected live against the real Cloudflare dashboard listing on
   2026-07-12 — the first pass guessed a uniform `-r2` suffix
   (`agendaprofe-teacher-photos-r2` etc.) that only `class-materials`
   actually has; the other three have no such suffix. Each bucket entry
   now carries an explicit `env_prefix` field instead of one derived from the bucket name,
   because the four buckets' env-var families are historically irregular
   (`LIVEKIT_EGRESS_S3_*` doesn't even share the bucket's own name).
2. **Preview gets its own real buckets, not a shared-bucket env-var
   split.** Each of the four buckets gets an `agendaprofe-preview-*` twin
   (`environment = "preview"` in the same `buckets` list) — a separate
   bucket, separate token, separate credentials. `infra/vercel` now filters
   to `environment == "production"` only and drops the `"preview"` Vercel
   target entirely (the Fly cutover already made Vercel's preview build unreachable at
   the friendly domain, so writing preview vars there was dead config).
   Preview credentials instead flow through a new
   `infra/cloudflare-r2/push-fly-secrets.sh`, which reads Tofu's own state
   (`tofu output -json buckets`, filtered to `"preview"`) and pushes them to
   the Fly app via `fly secrets import` (stdin, not argv, so values never
   hit shell history/`ps`). No app code needed to change for this split:
   Fly (preview) and Vercel (production) are separate runtimes reading the
   same env-var _names_ with different values, unlike the old
   single-Vercel-project `target` array.
3. **The three previously-separate R2 env-var readers are now one.**
   `provider.ts`'s `r2BucketConfig()`/`r2ObjectPath()` are now exported and
   reused by `chat-audio.ts`/`chat-video.ts` (previously a hand-rolled,
   duplicated `r2Config()`/`s3Path()` pair) and by
   `recording.ts`/`lesson-audio-store.ts` (previously their own
   `egressConfig()`/`storeConfig()` readers). `R2_ENV_PREFIX` gained two
   entries, `"chat-audio"` → `CHAT_AUDIO_R2` and `"recordings"` →
   `LIVEKIT_EGRESS_S3`. The prefix map's values changed shape too: from a
   bare name with a hardcoded `_R2_` infix to the **full** env-var prefix,
   so `recordings`' `_S3_` naming (historical — named for the LiveKit
   egress feature, not this module) fits the same map without a special
   case. **No env var was renamed** — every existing `*_BUCKET`/`*_ENDPOINT`/
   `*_REGION`/`*_ACCESS_KEY`/`*_SECRET` name a caller reads today is
   unchanged; only where the reading code lives changed.

**Why it likely changed.** The scaffold was written without live
Cloudflare/Vercel API access and reverse-engineered the bucket list from
`provider.ts` alone, missing the two buckets that bypass that module
entirely — a gap only visible once someone who actually knows the live
Cloudflare dashboard's bucket list looked at it. Splitting preview and
production into physically separate buckets (rather than the module's
implicit shared-bucket-different-Vercel-target model) follows directly from
the Fly cutover: once preview is a different host, sharing credentials
between prod and preview stops making sense on security-isolation grounds
alone, and the scaffold never actually built prod/preview separation in the first
place (it applied `target = ["preview","production"]` uniformly). Bundling
the `R2_ENV_PREFIX` consolidation into the same pass — rather than a
separate follow-up — was a judgment call made while fixing the bucket list:
touching every caller's bucket-config code anyway to add `chat-audio`/
`recordings` support made it a small increment to also delete the two
duplicated readers, rather than leaving a fourth (fixed) one alongside two
duplicates.

**What was affected.**

- `infra/cloudflare-r2/{variables,main,outputs}.tf`,
  `terraform.tfvars.example`, `import.sh`, `README.md` — real 4-bucket +
  4-preview-bucket list, `env_prefix` field.
- `infra/cloudflare-r2/push-fly-secrets.sh` — new.
- `infra/vercel/{main}.tf`, `import.sh`, `README.md` — production-only
  target, `env_prefix`-derived keys.
- `apps/web/src/lib/storage/provider.ts` — `r2BucketConfig`/`r2ObjectPath`
  exported, `R2_ENV_PREFIX` gains `chat-audio`/`recordings`, values changed
  from bare-name to full-prefix.
- `apps/web/src/lib/storage/chat-audio.ts`,
  `apps/web/src/lib/storage/chat-video.ts` — local `r2Config`/`s3Path`
  replaced with `provider.ts`'s shared functions.
- `apps/web/src/lib/video/recording.ts` — `egressConfig()`'s R2 portion now
  sourced from `r2BucketConfig("recordings")`; LiveKit-specific fields
  (`url`/`apiKey`/`apiSecret`) stay locally read (not R2 config).
- `apps/web/src/lib/transcription/lesson-audio-store.ts` — local
  `storeConfig()` replaced entirely with `r2BucketConfig("recordings")`.

**Unresolved risks.**

- **Nothing in this change has been applied against the live Cloudflare,
  Vercel, or Fly API** — same constraint as the original scaffold (no network path to
  `api.cloudflare.com`/`api.vercel.com`/`api.fly.io` from this session).
  `push-fly-secrets.sh`'s `fly secrets import` stdin format is
  best-effort from documented `flyctl` usage, not confirmed live.
- **Adopting the 4 real production buckets/tokens/20 Vercel env vars is
  still a separate, human-run step** (`tofu import`, per each module's
  README) — this PR lands the modules updated but still plan/validate-only,
  same sequencing discipline as the original scaffold.
- **The `student-photos` code path is untouched, not removed** —
  `student-photo.ts`/`STUDENT_PHOTO_BUCKET` still exist in app code and
  will keep silently no-op-ing (unconfigured) until someone either wires a
  real bucket or removes the feature outright. Not fixed here — this
  change only stopped the Tofu module from pretending to manage a
  nonexistent bucket.
- **`recording.ts`'s endpoint reconstruction** (`https://${r2.host}`)
  assumes R2 endpoints are always `https`, which is true for every
  Cloudflare R2 S3 endpoint today but is an assumption, not a value read
  verbatim from env — if a future non-R2 S3-compatible backend used a
  different scheme this would need revisiting.
- **The irregular env-var naming itself (`_R2` vs `_S3`, per-feature
  prefixes) is unchanged** — this consolidated _where_ the reading code
  lives, not the underlying env-var names. A follow-up could rename
  `LIVEKIT_EGRESS_S3_*` to something `_R2_`-consistent, but that's a
  deploy-risk env-var rename across three platforms (Vercel prod, Fly
  preview, and whatever's set locally), deliberately out of scope here.
