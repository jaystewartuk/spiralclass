# D-141. The standard breakpoint scale is restored (2026-08-29)

**Status: Active.** Supersedes [D-122](./D-122.md) entirely.

## The decision

`apps/web` returns to Tailwind's default scale — `sm 640`, `md 768`, `lg 1024`,
`xl 1280`, `2xl 1536` — and the desktop layout begins at **1024** rather than 1281. The bespoke `roomy` breakpoint is removed.

## What D-122 got right, and where it put it

D-122's observation was correct: **a tablet is a touch device, and it should not
inherit mouse-sized controls.** Its mistake was answering that with the layout
breakpoints. Width tells you how much room there is. It does not tell you what
is pointing at the screen — `@media (pointer: coarse)` does, and that is where
target sizing belongs.

Holding the touch concern in the breakpoints cost more than it bought:

- **There was no breakpoint at all between 640 and 1281.** Every width in that
  band rendered a phone layout stretched across it. A 900px browser window got
  a single stacked column with the header's desktop navigation above it — which
  the visual baseline photographed at 768.
- **Nothing responded above 1440.** `xl:` appeared twice in the codebase and
  `2xl:` never, so the baseline shows the teacher dashboard using under half the
  width at 1920.
- **`sm` and `md` were the same value**, so two of the five rungs did nothing,
  and a reader had to open a file to learn what `md:` meant.

[D-140](./D-140.md) supplies the mitigation D-122 was reaching for: a 44px
minimum target everywhere, on every layout, as a standing rule rather than a
consequence of which breakpoint fired.

## The pointer, which is what D-122 was actually asking about

Restoring the standard scale on its own would have handed the Fire HD 10 the
desktop layout, because a width cannot tell a 1280px tablet from a 1280px laptop
window. Both of those are real here, and the product was getting them wrong in
opposite directions:

- **The teacher's Amazon Fire HD 10 is 1280px in landscape.** D-122's threshold
  sat one pixel above it on purpose, so she kept the touch layout.
- **A MacBook was getting the touch layout too** — because any browser window
  narrower than 1281px did, which is most windows that are not maximised. The
  1281px threshold was not selecting tablets; it was selecting "not full
  screen".

So the shell layout is gated on **`(min-width: 1024px) and (pointer: fine)`**,
with a second tier at 1280px for inline navigation. Two named screens,
`desktop` and `desktop-wide`, alongside the standard width scale.

The Fire HD 10 keeps the touch layout because it is a touch device, not because
of an arithmetic coincidence about its width. A laptop gets the desktop layout
at any window width over 1024, including the narrow ones it was previously
denied. **Neither outcome is a compromise** — which is the tell that the query
was finally asked in the right terms.

Only the 14 layout-**mode** utilities in the five navigation shells use these
tiers. Spacing and type stay on the plain width scale, where width is the right
question and a mouse is irrelevant.

## The migration

392 breakpoint prefixes across 164 files were remapped in a single pass, so
nothing cascaded through two renames. Intent was preserved rather than the
letter:

| Was      | Old width | Now    | New width |
| -------- | --------- | ------ | --------- |
| `roomy:` | 640       | `sm:`  | 640       |
| `sm:`    | 1281      | `lg:`  | 1024      |
| `md:`    | 1281      | `lg:`  | 1024      |
| `lg:`    | 1440      | `xl:`  | 1280      |
| `xl:`    | 1680      | `2xl:` | 1536      |

`sm:` and `md:` collapsing into one prefix is only safe if no element set the
same property at both — under the old scale `md:` won on equal widths purely
through Tailwind's key order. That was checked before the rename: **zero
elements did**, across every class string in `src`.

`md` (768) is now unused and deliberately so. It is the rung the intermediate
layout will be built on, which is design work rather than a config change, and
does not happen here.

## Verification

The visual baseline exists for exactly this. 1,164 captures were taken before
the change and re-taken after, at six viewports in both themes, and the diff is
the evidence that intent was preserved where it should be and changed only where
this decision says it should.

`src/lib/breakpoints.test.ts` and `tests/config/responsive-breakpoints.test.ts`
were rewritten to assert the new model rather than adjusted to pass: landscape
tablets are now asserted to reach the desktop layout, which is the claim D-122
asserted the opposite of.
