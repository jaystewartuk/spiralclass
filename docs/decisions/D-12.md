# D-12. Classes complete at their end time; "completed" is automatic, "no-show" is the only manual divergence (2026-06-23)

**What changed.** A class now transitions `scheduled → completed` the moment its
`scheduled_end` passes — not 24 hours later, and never via a manual button.
Three things moved together:

- **Auto-complete fires at `scheduled_end`** (was `scheduled_end + 24h`), in both
  the per-booking Inngest sleeper (`auto-complete-booking.ts`) and the hourly
  backup sweep (`auto-complete-sweep.ts`). Because completion now happens when
  the slot elapses, `completed_at ≈ scheduled_end`, so the teacher cash-flow
  "earned vs held" split updates at the class's end with **no change to
  `cashflow.ts`** — it already keys delivered revenue off `completed_at`.
- **The manual "Mark as completed" button was removed** from the teacher
  dashboard (shipped first in PR #245). The `markBookingComplete` server action
  is retained but no longer surfaced, for backward-compat with installed
  clients.
- **`markBookingNoShow` now also accepts an already-`completed` class** (a
  `completed → no_show` relabel), clearing `completed_at`. This is the piece
  that lets auto-complete fire immediately with no grace window: a teacher who
  needs to record a missed class does it anytime, rather than the system holding
  the class open for 24h so they _could_ mark a no-show before it froze.

**Why it changed.** Under Model B (D-09 lineage) a class is committed against
the package **at booking**, so `completed` and `no_show` are economically
identical — both count as delivered, neither touches `classes_used`. The manual
"complete" button therefore changed no counts and only duplicated work the
system already did automatically; its copy ("deducted from the package") was a
stale holdover from the pre-Model-B world and actively misleading. The 24h
auto-complete delay existed solely to give the teacher a window to mark a
no-show _before_ the class auto-completed. Once a `completed` class can be
relabeled to `no_show` at any time, that window has no remaining job — so
completing at `scheduled_end` is both simpler and better: the teacher sees the
class as done and the cash-flow figure move the moment the lesson ends.

**What was affected.**

- `lib/inngest/functions/auto-complete-booking.ts` — `fireAt = scheduledEnd`
  (was `+ 24h`); step renamed `wait-scheduled-end`.
- `lib/inngest/functions/auto-complete-sweep.ts` — stale-cutoff is now `now`
  (was `now − 24h`); still hourly, still idempotent via `maybeCompleteBooking`.
- `lib/cancellation/auto-complete.ts` — `maybeCompleteBooking` unchanged
  (still `scheduled → completed`, idempotent); only the doc comment updated.
- `app/actions/overrides.ts` — `mark_no_show` accepts `scheduled | completed`, records the real prior status
  in the override `before` JSON, and sets `completed_at = null`.
- `app/(app)/dashboard/clases/[bookingId]/page.tsx` — the no-show action (and
  the "past classes complete automatically" note) now render for `completed`
  classes as well as past-started `scheduled` ones (`canRecordNoShow`).
- `markBookingComplete` retained but unsurfaced.

**Why cash flow didn't need touching.** Completing at `scheduled_end` makes
`completed_at` the delivery time within Inngest jitter (the hourly sweep is only
a backup), so the existing `completed_at`-keyed window in `computeTeacherCashFlow`
now reflects delivery-at-class-end for free. A no-show still counts as delivered
(forfeited time the teacher earned) via the `status IN (completed, no_show)`
group-by, unchanged.

**Unresolved risks.**

- `completed` remains a _materialized_ status (written by the cron), not a
  derived one. We kept it materialized on purpose — every read site that filters
  `status = 'completed'` keeps working unchanged — but it means a class sits as
  `scheduled` for up to an hour if both the per-booking sleeper and the next
  sweep are delayed (Inngest outage). Collapsing `completed` into a derived
  "past, non-canceled, non-no_show" state (and deleting the sleeper + sweep) is a
  larger, separate follow-up.
- The `completed → no_show` relabel fires the `no_show_student` notification
  whenever it runs, so a very late relabel sends a late "you missed your class"
  message. Acceptable in practice (relabels happen within a day or two); a
  staleness guard on that notification is a possible later refinement.
- `markBookingComplete` is now a dead UI path kept only for back-compat; it can
  be removed once no shipped client calls it.
