# D-187. Production video moves to a free Compute Engine box, and recording and transcription go off because it cannot carry them

**Status.** Active · reverses [D-182](./D-182.md) (production on LiveKit
Cloud) and [D-131](./D-131.md) (recording and transcription on). D-131's
_reasoning_ is not reversed — see "Why".

**What changed.** `LIVEKIT_URL` in `config/env/production.runtime.env` moves
from the LiveKit Cloud project back to `wss://livekit.spiralclass.com`, which
now points at an **Always Free `e2-micro`** on Compute Engine in `us-east1`,
running `livekit-server` and Caddy and nothing else
([`infra/gcp-livekit/`](../../infra/gcp-livekit/README.md)). Because that
machine has no room for egress, `CLASS_RECORDING_ENABLED` and
`LESSON_INSIGHTS_TRANSCRIPTION_ENABLED` are commented out in both runtime env
files, and the privacy policy says, in the three places D-131 corrected, that
recording and transcription are switched off in production today. Live
captions are untouched: they run in the browsers ([D-185](./D-185.md)) and need
no server capacity.

**Why.** Two constraints, and they are independent.

1. **Where the video server runs.** Oracle has still not given the box back.
   The Pay As You Go upgrade [D-183](./D-183.md) requested on 2026-09-20 was
   still "in progress" four days later, with the plan still Free Tier, and a
   Free Tier tenancy cannot open a support request to chase it. Forum threads
   report the same upgrade stuck for weeks. LiveKit Cloud works, but its
   free plan covers 5,000 participant-minutes a month (about 41 two-person
   class-hours), and recording is billed per minute on top. The `e2-micro` is
   inside Google's Always Free allowance, so the only charge is its static
   IPv4 address: $0.005 an hour, about $3.65 a month.
2. **What that machine can carry.** Measured on 2026-09-24 against a
   throwaway box built from the same boot script and the same image digests,
   with `lk load-test` run from outside Google and the box's own `mpstat` and
   `docker stats` read off its serial console once a minute:
   - **A class, no recording:** two publishers (720p simulcast video plus
     audio) and one subscriber for ten minutes. **0 packet loss**, 2.2 Mbps
     delivered, `livekit-server` at 10–12% of one core, the whole VM at about
     0.12 core, which is under the quarter-core an `e2-micro` sustains without
     burst credits. About 375 MB of the 953 MB of RAM in use.
   - **A class with the app's three recordings:** the audio-only room
     composite ([D-135](./D-135.md)) plus one track egress per speaker, with
     egress's CPU costs lowered so it would accept all three. **Within a minute
     egress killed the composite and one track with `CPU exhausted`**;
     `livekit-server` and egress were each near a full core, iowait reached 44%
     as the VM swapped, the simulated participants reconnected three minutes in,
     and video afterwards ran at its lowest simulcast layers. (That run fed each
     subscriber twice a real class's traffic, so it was harsher than a class.
     The recording failure came first either way.)

So the machine can host the call but not the capture. The switch is turned off
because the capacity is not there. D-131 turned it on for a business reason,
and that reason has not changed. What changed is that the hardware to act on it
is gone.

**What was considered and rejected.**

- **Stay on LiveKit Cloud.** It works and needs nothing built. It is
  rejected as the _resting_ state because of the cost profile, not as a
  fallback: it remains the rollback, one config line away.
- **A paid `e2-medium` with egress (~$30 a month).** That is the size the
  measurements support for calls plus recording. The operator chose the free
  box, with recording off, over paying for recording while Oracle might still
  come back.
- **Egress on a separate machine started only around booked classes.** It
  would keep recording at little cost, but it needs egress to reach the call
  server's Redis across a private network and an Inngest-driven start-up
  schedule. It's real work, for a feature one teacher uses, and it isn't
  needed to get calls off the metered plan.
- **Wait for Oracle.** No stated date, and no way to ask.

**What it constrains.**

- **Do not add egress to this box.** The numbers above are why. Turning
  recording back on means a bigger machine first, then the flags, then the
  privacy policy, all in one change. `ai-marketing-claims.test.ts` fails if
  the flags and the policy's "switched off" sentences disagree in either
  direction.
- **D-182's three conditions held before this line moved, and they are the bar
  for any future move:** the box serves LiveKit through its own certificate,
  a real class has been joined on it, and the pair in production Infisical is
  the box's own. The first and third are operator steps listed in the change
  that carries this record. The second is met only partly before the deploy:
  a two-device call through LiveKit Meet proves the media path, but a class
  _booked and joined through the app_ can only happen once the app points at
  the box. So the first booked class after the deploy is the check, and the
  Cloud line is the rollback if it fails.
- **Two overlapping classes is the graduation trigger.** At about 0.12 core
  per class, a second concurrent class reaches the `e2-micro`'s sustained
  ceiling. A second teacher with overlapping hours means `e2-medium`.
- **Keep the hostname proxied** ([D-134](./D-134.md)). Its certificate then
  depends on the http-01 challenge reaching the box on port 80.
- **No OpenTofu for this box until one has been applied**
  ([D-150](./D-150.md)). The boot script is the box's configuration, and the
  README is the build record.

**What was affected.** `config/env/production.runtime.env` and
`config/env/preview.runtime.env`; `packages/shared/src/legal/privacy-policy.ts`
(three statements and the date); `apps/web/tests/config/ai-marketing-claims.test.ts`
(the flags asserted off, the insights claims back in `GATED_OFF_CLAIMS`, and the
policy tripwire now checked in both directions); `infra/gcp-livekit/`;
`docs/features/live-calls-video.md` and `docs/features/lesson-insights-reports.md`;
a forward pointer on D-182 and D-131.

**Trade-offs accepted, and unresolved risks.**

- **Recording and lesson insights are dark.** Recordings and retained audio
  already in R2 are untouched and still play, and [D-136](./D-136.md) still
  deletes them when an account closes. Nothing new is captured.
- **One free VM is a single point of failure with no SLA.** It is the same
  risk [D-94](./D-94.md) accepted for the Oracle box. If it fails, the
  fallback is the LiveKit Cloud line kept as a comment in the runtime env file,
  plus the Cloud project's pair in Infisical and a redeploy.
- **A reboot drops a class in progress**, and changing the box means a
  reboot. Change it outside lesson hours.
- **The load was simulated.** It came from one laptop, with TURN on but
  unexercised, so a student on a network that blocks UDP has only the TCP
  7881 fallback and TURN's UDP 3478 to rely on. That path is untested.
- **The Standard-tier outbound allowance** (200 GiB a month free) was taken
  from a third-party pricing summary, not Google's own page. At about 1 GB per
  class-hour it only matters above roughly 200 class-hours a month.
- **Nothing alerts on the box.** The liveness monitor watches the app, not
  `livekit.spiralclass.com`.
