# D-25. Staff access is the strictest bar on the platform: mandatory TOTP with a per-session step-up, an append-only audit log, and narrow capabilities beside the rank ladder

Every `/admin` page and every admin server action calls `requireAdmin()`
([`lib/admin.ts`](../../apps/web/src/lib/admin.ts)). It authorizes on
`meetsRole(actor, minRole) || hasCapability(actor, capability)`. It then
requires two things: TOTP enrolled (`user.twoFactorEnabled`), and a fresh,
session-bound step-up proof
([`lib/auth/admin-stepup.ts`](../../apps/web/src/lib/auth/admin-stepup.ts), an
HMAC-signed cookie valid for 12 hours). No tier is exempt. The `overrides` audit
table refuses `UPDATE` and `DELETE` at the database.

## Why

The superadmin can read every tenant and act on any account. Sign-in for
everyone is a passwordless email code, so an admin's inbox is effectively that
admin's credential. Without a second factor, the all-access account had the same
strength as a brand-new student's. Enrolment on its own did not fix that.
better-auth's two-factor plugin never challenges the email-code rail, so a check
that only asked "is 2FA enabled?" still let anyone who could read an admin's
inbox reach full privilege. That gap was found in a security audit (H-1) after
the auth cutover ([D-40](./D-40.md)), and the step-up proof closes it.

Capabilities exist because the next staff were not engineers. A tester who has
to run the UAT runbook, or an accountant, should see their own slice and nothing
else. They should not get a rung on a ladder whose rungs are money-adjacent.

## Options considered

- **The same bar as any user.** Rejected, for the inbox reason above.
- **Optional MFA for lower tiers.** Rejected. Every tier can act on real
  accounts.
- **Enrolment as proof of a second factor.** It was shipped this way, then
  replaced by the session-bound step-up (see How we got here).
- **Gate MFA in the admin layout.** Rejected. The step-up page renders inside
  that layout, so the gate would redirect to itself. The layout is a shell
  (`resolveAdminActor()`, no MFA), and each page and action is the boundary.
- **An environment switch that disables MFA for recovery.** Rejected, because
  it would just be the new backdoor.
- **New narrow roles as rungs on the rank ladder.** Rejected. `tester` and
  `engineer` rank 0, below `support`, and reach a tool only through an explicit
  capability in
  [`lib/admin-capabilities.ts`](../../apps/web/src/lib/admin-capabilities.ts)
  (`uat:run`, `schema:view`). `superadmin` holds every capability without a
  hand-kept list.
- **Hardware keys / WebAuthn.** They were supported under the old auth vendor
  and dropped with it ([D-40](./D-40.md)). TOTP is the only factor.

## What it cost

- An admin who loses the authenticator is locked out of `/admin`, and the only
  route back is an operator resetting the factor in the database. The original
  plan called for a documented break-glass reset. No runbook for it exists in
  this repository.
- A step-up lasts 12 hours, so a dangerous action does not get its own fresh
  challenge.
- Append-only holds at the database only. A holder of the database credential
  can drop the trigger. The mitigation is an out-of-band copy:
  `writeOverride()` also logs every audit row
  ([`lib/audit.ts`](../../apps/web/src/lib/audit.ts)). An external
  write-once-read-many sink was never built.

## What it constrains

- **Every admin page and every `admin-*` action calls `requireAdmin(`.**
  `apps/web/tests/admin/gate-coverage.test.ts` fails the build otherwise. Its
  `MFA_EXEMPT` set (the step-up page, its enrolment actions and the layout
  shell) is the complete list of surfaces that may skip MFA. Do not grow it to
  unblock a page. Tests: `apps/web/tests/admin/admin-mfa-gate.test.ts`,
  `apps/web/tests/auth/admin-stepup.test.ts`.
- **The env-allowlist bootstrap is transient.** `SUPERUSER_EMAILS` produces an
  unattributed synthetic superadmin only while `admin_users` is empty, and it
  logs a warning and sets a Sentry tag when it does. Seed a real row from
  `/admin/staff`, then blank the variable in production. Test:
  `apps/web/tests/admin/bootstrap.test.ts`.
- **The last active superadmin cannot be demoted or disabled**
  ([`actions/admin-staff.ts`](../../apps/web/src/app/actions/admin-staff.ts)).
- **The audit trail is never rewritten.** `overrides_append_only()` lives in the
  hand-written invariants migration, and the drift check cannot see a missing
  trigger. A platform-scoped action with no single target is recorded with
  `targetType: system` and a null `teacher_id`. It is never skipped.
- **A capability never satisfies a rank floor, and a rank never needs a
  capability entry.** Add a new narrow tool as a capability, not a rank. Tests:
  `apps/web/tests/lib/admin-capabilities.test.ts`,
  `apps/web/tests/lib/admin-nav-visibility.test.ts`,
  `apps/web/tests/actions/admin-uat-action.test.ts`.
- **A destructive UAT control is refused in production three times over**:
  `assertReseedAllowed()` before the event is sent, `isProductionDeployment()`
  in the Inngest function, and `assertNotProductionTarget()` in
  `apps/web/scripts/seed.ts`, which checks the connection it actually has. The
  page does not render the reseed form in production at all. The Stripe check
  refuses when its label does not match the deployment it runs in
  (`apps/web/tests/uat/stripe-check.test.ts`).
- Any future way for staff to read voice-derived content must be built as a
  deliberate, audited capability ([D-22](./D-22.md)).

Behaviour, role floors and the UAT flow:
[admin portal](../features/admin-portal.md).

## How we got here

- **June 2026.** The admin tier was hardened under the old auth vendor:
  mandatory AAL2 on every admin page and action, TOTP or a hardware key, and
  the layout turned into a shell. The `overrides` triggers were added, and
  `overrides.teacher_id` became nullable. "Sign in as" started to require a
  typed reason, refused to target another active admin, and always wrote an
  audit row. The last superadmin became irremovable. Recovery was the vendor's
  dashboard.
- **2026-07-04.** In the auth cutover ([D-40](./D-40.md)) the mandate stood.
  WebAuthn went, AAL2 became an app-enforced `twoFactorEnabled` check, and
  recovery became a database reset.
- **2026-07-09.** The capability layer and `/admin/uat` shipped together. The
  UAT runbook moved from a markdown document into
  [`lib/uat/runbook-steps.ts`](../../apps/web/src/lib/uat/runbook-steps.ts),
  because a non-technical tester could not run CLI steps or read dashboards
  unaided. On the same day, review closed two gaps: the reseed form was still
  rendered in production (merely disabled), and the Stripe check's environment
  label was a passthrough that could call preview data "production".
- **After the cutover.** Audit finding H-1 showed that enrolment alone was a
  single factor, and the session-bound step-up was added.
- **Since then.** The impersonation feature has been removed from the code, so
  its reason-and-attribution rules have nothing left to govern. better-auth's
  `admin` plugin is still mounted, for `revokeUserSessions`.
