# D-40. Replace Supabase Auth (GoTrue) with better-auth — email-OTP only, on the existing Supabase Postgres

**Status: Shipped.** better-auth is live (`better-auth` in
`apps/web/package.json`, `lib/auth.ts`/`middleware.ts` on better-auth sessions,
backfill migration `20260704010000_backfill_better_auth_users` applied) — this
is current policy. Historical phased plan (execution detail may have drifted;
the code is the source of truth):
`better-auth migration plan`.

**What changes.** SpiralClass's authentication becomes **better-auth** — a
portable library whose `user`/`session`/`account`/`verification` tables live in
**our own** Postgres (behind the existing `lib/auth` seam), replacing Supabase
Auth (GoTrue) entirely. The database _host_ stays Supabase for now; only the
auth _provider_ changes. The target surface, decided:

- **Passwordless email OTP only.** Magic-link _delivery_ is dropped (today one
  OTP is emailed as both a clickable link and an inline typed code — we keep the
  code, drop the link).
- **6-digit throttled OTP** — attempt cap (`allowedAttempts`) + a short-window
  request rate-limit on send. Throttling, not length, is the security lever.
- **Sessions:** HTTP-only cookie, plus a bearer token for non-browser callers
  (better-auth `bearer` plugin) — one `session` table, so a single
  `revokeUserSessions(userId)` kills every session together.
- **Owned `user` table keyed by the existing user UUIDs.** better-auth mints the
  code; we deliver it via the existing Resend rail.
- **Second factor: admin-only TOTP + recovery codes** — nothing else. better-auth
  exposes no per-session "2FA-verified" flag, so the gate is app-enforced
  (`role === 'admin' && user.twoFactorEnabled`), `trustDevice` off for admins,
  `allowPasswordless: true`, plus a **DB break-glass reset** so a sole
  passwordless admin can't be locked out.
- **Notification auto-login (`/r/*`) → narrow signed capability tokens** (reusing
  the existing `SESSION_SECRET` HMAC pattern) that authorize the one intended
  action instead of minting a full session.
- **Pin ≥ 1.6.22** (GHSA-qq9h-g4jm-xgf3, CVSS 8.3 account-takeover on
  magic-link/email-OTP, fixed 1.6.22; latest 1.6.23). Our no-password config is
  not exposed to that vector by construction, but we pin anyway and track
  advisories (upstream supports latest-only).

**North star:** when done, the auth layer must read as if the app were **built
from scratch on better-auth only** — no `@supabase/ssr` session clients, no
`supabase.auth.*`, no `auth.users` FK, no AAL2, no magic-link machinery, no
permanent adapters, **no feature flag** — a flagless clean hard-cut, feasible
because only one user logs in on the live site (so the identity migration is
coordinated and trivial). Any transitional code is deleted in the final
decommission phase. The DB host and Supabase Realtime are deliberately _out of scope_ (a
separate later initiative); the sole surviving Supabase-shaped credential is a
short-lived data-plane token minted for the Realtime socket so its `auth.uid()`
RLS keeps working — not an auth provider, and it goes when Realtime does.

**Why it likely changed.** Owning the identity tables makes auth **portable** —
it travels with our Postgres to the later self-hosted DB move instead of being
locked to a Supabase-managed service — and lets us **delete a large accreted
surface** (magic-link link+code duality, passkeys, phone/SMS OTP, teacher payout
step-up, `TrustedDevice`, GoTrue AAL2 plumbing) down to one email-code rail plus
admin TOTP. Decoupling the auth rewrite (now, on stable infra) from the infra
move (later) keeps each independently reversible. This is also the **first**
decision to state the auth provider explicitly — Supabase Auth was inherited
baseline, never a recorded decision, so nothing is being reversed _there_.

**What it reverses / narrows** (read each before it's changed, per this log's
policy):

- **Reverses the phone-OTP rail** — phone-number OTP login (student-facing, behind
  `FLAG_PHONE_LOGIN`) is removed; email is the sole rail (SMS re-addable later).
- **Reverses the teacher device-trust decision** — the teacher 2FA "remember this device"
  (`TrustedDevice`) is removed, along with the teacher payout step-up it served
  (SECURITY_PLAN §11.2, not itself a D-NN).
- **Narrows [D-25](./D-25.md)** — mandatory admin MFA stays, but drops the
  WebAuthn/passkey addendum (TOTP-only) and replaces the Supabase-AAL2 mechanism
  with an app-enforced `twoFactorEnabled` gate + DB break-glass recovery (D-25's
  recovery was "Supabase dashboard only", which disappears with GoTrue).
- **Narrows the consolidated sign-in rail** — the one passwordless rail becomes
  email-OTP-only (drops the magic-link delivery half).
- **Preserves [D-38](./D-38.md)** — Teacher/Student mutual exclusivity per auth
  identity is re-implemented on the new sign-in linking path unchanged.
- **Does not contradict [D-18](./D-18.md)** (migrations still run in the build) or
  [D-26](./D-26.md) (staging stays a separate Supabase project; validated
  staging-first, cut over at promote — no flag).
- **Scoped exception to expand/contract** — the auth cutover is a deliberate
  **hard-cut** (delete-not-translate the old auth routes); a
  minimum-supported-version force-update gate replaces the adoption window.
  Chosen 2026-07-03 to reach the from-scratch end state without a permanent
  compat shim.

**What was affected.** The identity migration re-points two FKs
(`teachers.id`, `students.auth_user_id`) off `auth.users` onto the new `user`
table while preserving UUIDs; `lib/auth.ts` becomes the better-auth instance with
`lib/session.ts` holding the rebuilt `getAuthUser`/`requireTeacher`/`requireStudent`;
`/api/auth/[...all]` replaces `/api/auth/callback`; `lib/admin.ts` gates on TOTP;
`middleware.ts` and the `/r/*` routes are rebuilt; and the dropped features
delete
`lib/auth/{magic-link,webauthn-*,payout-mfa,trusted-device,phone-link}.ts`, the
`TrustedDevice` model, and the phone-OTP routes. A new `lib/realtime-token.ts`
(+ `SUPABASE_JWT_SECRET`) keeps the two `postgres_changes` subscriptions authed.

**Unresolved risks.**

- **UUID-preserving backfill** is the make-or-break and rests on an _inferred_
  (not documented) better-auth import pattern — must be proven on staging in a
  throwaway prototype before any prod migration.
- **Realtime** breaks silently if the bridge token is wrong; needs an explicit
  staging check.
- **The installed client base is force-updated** — a minimum-version gate
  blocks older generations until they update, and everyone re-authenticates
  once at cutover. The gate must be live before cutover or stale clients fail
  opaquely.
- **Admin lockout** — no AAL2 safety net post-cutover; the DB break-glass reset
  is mandatory before enforcing the TOTP gate.
- **Latest-only upstream support** makes better-auth minor upgrades potential
  security work, not optional.

**Update (2026-07-13).** The `lib/realtime-token.ts` bridge (+
`SUPABASE_JWT_SECRET`) described above is retired. Both `postgres_changes`
subscriptions it authed (student live-notes, call instructions overlay) were
converted to portable HTTP polling — the same D-44 treatment chat already got,
finishing that line rather than reversing this one — as a prerequisite for
moving the preview database off Supabase to Neon (see
`infra/database/neon/README.md`). The "Realtime breaks silently if the bridge
token is wrong" risk above no longer applies; there is no bridge token.
