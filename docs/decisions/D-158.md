# D-158. The repository is public, so it publishes the shape and the engineering, never an account or the operator's exposure, and security work is gated in the open

Four rules follow from that, and this record contains no identifier values.

- No identifier naming an account, tenant, project or machine this project owns
  is committed, and the account-identifier gate in
  [`scripts/check-leaks.mjs`](../../scripts/check-leaks.mjs) fails if one comes
  back.
- No document carries what the operator personally owes, to whom, or under
  which regime.
- A security fix lands as an ordinary public pull request with a neutral title,
  pushed only when it can ship ([SECURITY.md](../../SECURITY.md#how-a-security-fix-lands)).
- `main` refuses a merge that introduces a CodeQL alert.

## Why

The repository went public on 2026-09-09, and one person carries everything in
it personally.

An identifier is not a credential. An OCID, a Stripe account id or a cloud
project number grants nothing on its own. That is exactly why each one got
committed without anyone flinching, and why a credential scan correctly ignores
them. In public they aggregate into reconnaissance: which provider holds what,
which box answers where, which accounts belong to one person. A reader loses
nothing when they go. A configuration file, runbook or record is worth its keys,
structure and reasoning, and no value carries any of those.

The legal line has the same shape. Candour about engineering mistakes costs a
hostile reader nothing to use and gives a technical reader real signal. The
operator's tax and regulatory position gives the technical reader nothing and
hands the hostile one a specific, dated, personal exposure.

Security fixes had two rules in conflict. SECURITY.md says never describe an
unfixed flaw in a pull request, and CLAUDE.md says every change lands through
one. The window that matters is the time between a fix becoming readable and
production carrying it.

The gate had a credential scan, a dependency audit and a tenancy parser, and no
data-flow analysis. The first CodeQL scan of `main` found 11 open alerts: 10
high and 1 medium.

## Options considered

- **Keep identifiers, since each is harmless.** Rejected because they
  aggregate.
- **Keep every record unedited, compliance passages included.** This was the
  pre-publication plan. It was right about engineering candour and wrong about
  the operator's exposure, so it was reversed for that material only.
- **Fix in a security advisory's temporary private fork.** Rejected. GitHub
  documents that status checks do not run there, and that a merge from one
  bypasses branch protection. On the auth and payment paths, that skips the
  heavy suites exactly where a broken fix costs most.
- **A normal-titled public PR** narrates the flaw from the first push. **A
  private mirror** doubles the rules, secrets and runners that must stay
  identical. Both rejected.
- **CodeQL as a step in `scripts/ci/steps.mjs`.** Rejected. It needs GitHub's
  alert baseline to tell new findings from old ones, and it takes minutes,
  which would undo the fast tier.
- **An advanced-setup `codeql.yml` workflow.** Rejected, because a workflow
  that performs a check is forbidden. Default setup is a repository setting,
  with no file in the tree.
- **Require the `Analyze (…)` contexts.** Rejected: GitHub renames them, and a
  required context that never posts strands every PR. **Alerts with no merge
  protection** was declined: on a solo repository nobody reads an alert that
  does not block.

## What it cost

- The identifier sweep took an afternoon. It touched 20 files and changed the
  meaning of none of them.
- A fresh clone needs its gitignored links restored by hand: the
  `config/env/*.local.env` overlays and the Infisical project link.
- A neutral title hides nothing from someone who reads the diff. "The same
  sitting" still spans the PR's heavy run, the merged commit's runs and the
  deploy, and a Tier 2 change waits outside lesson hours. The window is
  shortened, not closed, and an unpushed fix exists on one machine until it
  ships.
- Every PR, including a docs-only one, waits for CodeQL. The first full scan of
  `main` took 4½ minutes, measured from the run's timestamps. Validity checks
  and non-provider secret patterns stay off, because on this account they are
  a paid product.
- Nothing checks that a title is neutral, that a branch was held back, or that
  a sentence describes the operator. Those are rules a reader applies.

## What it constrains

- **Publish the shape, never the account.** Real values live in Infisical, in
  gitignored overlays, or in Tofu state. Where an identifier is needed, use in
  this order:
  1. a `config/env/*.runtime.env` key set to `__LOCAL__`;
  2. an environment variable with no default (`"${ID:?where to get it}"`);
  3. a gitignored file with a committed `.example`.
- **Never a fallback default.** `"${ID:-<real value>}"` is a committed value
  that reads as configurable. It put an identifier in two deploy scripts and
  passed review. `infra/oracle-box/variables.tf` takes `compartment_id` with
  no default on purpose.
- **A placeholder comes from a reserved range:** the documentation address
  blocks, or `example-`-prefixed strings. It is never a plausible invented
  value, because the next reader will try it.
- **Another person's account ids appear nowhere.** A teacher's real Stripe ids,
  used as a worked example, became fixtures, and the example reads identically.
- **`IDENTIFIER_ALLOWLIST` needs a reason the string is not an account.**
  Adding one to silence a red run is the failure this gate exists to prevent.
  The address pattern is scoped to `infra/`, `config/`, `scripts/`, `.github/`,
  `docs/deployment/` and `docs/decisions/`, because in `apps/` a routable
  address is a fixture. Test: `apps/web/tests/config/check-leaks.test.ts`.
  Detail: [security posture](../security.md).
- **An optional server key costs nothing when absent.** `POSTHOG_PROJECT_ID` is
  read through `serverEnv()` and is deliberately not in `config/env/`, because
  only an admin check reads it. When it is absent, that check reports
  "unconfigured".
- **Published:** a decision, its constraint and its cost; a mistake and its
  fix; the privacy layer and the lawful bases the product states
  ([D-22](./D-22.md)); that the entity is UK-established, where that explains a
  country gate, GBP billing or the governing law. **Not published:** what the
  operator owes or is liable for, the regulatory classification of a replaced
  architecture, a quotable admission that a live document was legally wrong,
  and the entity's legal form. Ask of anything new: does this tell someone how
  the platform was built, or something about its operator they could use?
- **Never merge from a temporary private fork, and never push a security fix
  early** to get a runner's answer. Run `pnpm gate --allow-dirty`, and run
  `pnpm gate:heavy` locally if needed. The neutral title applies to security
  fixes only.
- **Code scanning is a ruleset, not a status.** `local-gate` stays the only
  required context ([D-157](./D-157.md)). Never add a `codeql.yml` (tune
  `query_suite` in
  [`scripts/setup-branch-protection.sh`](../../scripts/setup-branch-protection.sh)),
  and never add a bypass actor. Dismiss a false positive on the Security tab
  with a reason, which leaves a record. Guarded in
  `apps/web/tests/config/local-gate.test.ts` ("code scanning gates on new
  alerts, not on a check").

## How we got here

- **Early September 2026, before publication.** Identifiers were swept out and
  the account-identifier gate was added. Two deploy scripts carried the
  Infisical project id behind a `:-` default. The link file was gitignored and
  the scripts were made to fail with a setup message. Later the link moved to
  `$HOME`, which removed the guarantee that it pointed at this project. A
  committed hash, `infra/infisical/project.sha256`, checked by
  `infra/infisical/project-id.sh`, now refuses a different project. The code
  wins over the original record here. The PostHog project id went too: the rule
  is not judged one value at a time.
- **2026-09-04 to 09-06.** Compliance passages and two whole records (the
  privacy-controller framing and the platform's regulatory position) were
  removed. Each was left as a tombstone saying what it had covered, so the log
  did not quietly shrink. The one engineering finding was kept: under direct
  charges, Strong Customer Authentication follows the connected account's
  country ([payments](../features/payments.md)).
- **2026-09-13.** CodeQL default setup and private vulnerability reporting were
  switched on by hand. Until then, SECURITY.md had pointed reporters at a
  private route that was off. That day, live protection on `main` had drifted
  from the script: it required the workflow job names, linear history was off,
  and an extra approval ruleset had an admin bypass. Running the script reverts
  those settings, which is a separate decision. The 11 open alerts were left
  for triage.
- **Undated, after publication.** The security-fix rule was written into
  SECURITY.md and CLAUDE.md's title convention.
- **This consolidation ([D-202](./D-202.md))** retired the tombstones. Their
  numbers are listed in the index with what they covered.
