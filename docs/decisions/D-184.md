# D-184. Production runs on one Cloud Run service in `us-east4`, beside a managed Neon database in `aws-us-east-1`

Production's web app is the Cloud Run service `web` in `us-east4`, scaled to
zero, deployed by `scripts/cloudrun-deploy.sh` with the shape in
[`config/cloudrun/production.env`](../../config/cloudrun/production.env). It is
the only production target. Its database is a managed Neon project in
`aws-us-east-1`, never a self-run box. A separate `database` job checkpoints
and migrates first, and it is the only job holding a database credential.

## Why

The reason is cost. The platform earns nothing, and Fly cost $5.70–7.23 a
month, so the whole prize was $70–85 a year. It was worth taking only because
the move was cheap: the image, the entrypoint and `config/env/` were already
host-neutral ([D-70](./D-70.md)). The constraint is latency to the database,
which is paid once per SQL statement.

## Options considered

- **Fly `ord`, always on.** It was 12 ms from Neon, and it cost money for no
  revenue. Fly at `min_machines_running = 0` cost about 30 cents a month but
  gave an 8–10 s cold start on nearly every visit.
- **Oracle Always Free in Querétaro, beside LiveKit.** It was 58 ms from Neon
  in Ohio. It would have shared two OCPUs with live video, let one outage stop
  everything, and left production's secrets as files on a box Oracle may
  reclaim.
- **Postgres colocated on the free box.** It was the fastest option, and free.
  It lost on recovery: backups would depend on a person. Production once went
  eleven days with no backup when backups were not a managed service's job.
  Moving back off the box would also become a data migration.
- **Cloud Run `us-east5` (Ohio).** It measured no faster than `us-east4`, and
  `us-east4` offers custom domain mapping.
- **A global load balancer instead of domain mapping.** It costs about $18 a
  month, more than Fly. Cloudflare's free proxy cannot front a `run.app` URL,
  because the Host header arrives unrewritten.
- **Moving the app nearer the teachers instead.** Neon has no Mexico region.
  Cloud SQL and AlloyDB have no free tier. A self-run `e2-micro` would give up
  the PITR and branching that [D-178](./D-178.md)'s checkpoint relies on.
- **`MIN_INSTANCES=2` against a wedged instance.** It is outside the free
  grant, and the wedged instance would still take half the requests.

## What it cost

- **There is no hard spending cap.** A spike bills rather than throttles. The
  bounds are `MAX_INSTANCES=4` and a budget alert. A cap that stops the service
  would trade a bill for an outage.
- **Cold starts.** A visitor on a cold instance waits a median of 2.0 s, at
  most 3.7 s. Only one thing keeps an instance warm: the external HetrixTools
  monitor that checks `spiralclass.com/api/health/live` about once a minute.
  That monitor is also the largest use of the free grant: 43,200 checks a
  month × ~0.2 s × 2 vCPU ≈ 17,000 vCPU-s, under 10% of the 180,000 vCPU-s
  grant.
- **CPU is throttled between requests,** so `after()` work can stall. Both
  call sites are best-effort analytics.
- **There is no warm standby.** Rolling back a release is a traffic shift to an
  earlier revision. A regional outage needs "If the domain ever moves again" in
  [`RELEASE_AND_STAGING.md`](../deployment/RELEASE_AND_STAGING.md).
- **Custom domain mapping is a Preview feature** with no SLA.

## What it constrains

- **One URL is registered with Inngest: `https://spiralclass.com/api/inngest`.**
  Inngest registers an app per URL, so a second URL fires every cron twice,
  including the ones that bill. The deploy syncs the domain after
  `gcloud run deploy`, never the `run.app` URL, and CI never maps a domain.
  [`cloudrun-deploy.test.ts`](../../apps/web/tests/config/cloudrun-deploy.test.ts)
  enforces this.
- **The `database` job stays separate from the Cloud Run job.** It was split
  out so two targets could deploy independently. It stays because it is a
  credential boundary: the job that builds the image runs the most third-party
  code and never holds `DATABASE_URL`. Do not fold it back.
  [`production-targets.test.ts`](../../apps/web/tests/config/production-targets.test.ts)
  enforces this.
- **The service shape is passed on every deploy,** so a console edit does not
  outlive the next release. Memory stays at least 1Gi, because 512 MB wedged
  production on 2026-08-26.
- **`/api/health/live` stays cheap and never queries the database.** It is
  both the monitor's warm-keeping target and the liveness probe (`LIVENESS_PROBE`:
  every 15 s, 5 s timeout, restart after four failures). A probe on
  `/api/health` would restart every instance during a Neon outage. A check
  against it more often than every five minutes would keep Neon awake and use
  up the free 100 CU-hours around day 17.
- **Production's database stays managed.**
- **No OpenTofu module for a self-hosted box is committed before it has been
  applied and a state file exists** ([D-164](./D-164.md)). `infra/oracle-box/`
  is the one waived exception, behind a banner that comes off with its first
  apply.
- **The Oracle tenancy is Pay As You Go.** `ocpus`, `memory_in_gbs` and
  `boot_volume_gb` in `infra/oracle-box/variables.tf` sit at the Always Free
  ceilings, and raising one now bills instead of failing. A reserved IPv4 that
  is not attached is also billed. Nothing in the tree can read the account
  tier.
- **Re-derive latency from
  [`round-trips.integration.test.ts`](../../apps/web/tests/db/round-trips.integration.test.ts);
  never re-quote it.**

## How we got here

- **Before September 2026.** Fly sat in `ord`, not `dfw`, because Sentry
  measured `BEGIN` from `dfw` at 27.5 ms average. That was about 800 ms of a
  1.7 s response.
- **2026-09-02.** A Fly invoice of about $10 started a measurement from the
  running machines. Fly `ord` was 12 ms to `aws-us-east-2`. Oracle Querétaro
  was 58 ms to `us-east-2`, 55 ms to `us-east-1` and 78 ms to `us-west-2`. ICMP
  was used from Oracle and a TCP connect from Fly, to an S3 host standing in for
  Neon. The decision was to move the app to Oracle and keep Neon, on an assumed
  4 round trips per query × 7 queries per page, or about 1.3 s.
- **2026-09-04.** This was reversed. The app stayed on Fly, and Oracle took
  LiveKit, preview and preview's Postgres. On 2026-09-05 the Oracle module
  merged unapplied, behind its banner, before the repository went public.
- **2026-09-19 and 2026-09-20.** The box was destroyed for a rebuild, and
  Oracle then refused 56 A1 launches with `Out of host capacity` between 13:38
  and 22:14. The tenancy went Pay As You Go for capacity priority, which is
  Oracle's claim, not a measurement. `oci limits resource-availability get`
  showed 200 GB of storage, 2 cores and 12 GB of memory available, 0 used. A 1
  USD budget, `always-free-tripwire`, alerts at 1%. Hetzner ARM, at €10.49 a
  month, is sold only in Germany and Finland, about 160–190 ms from callers.
  The x86 options, at €19.49 and about $24, would bring back the amd64
  cross-build.
- **2026-09-21.** Cloud Run jobs made 25 TCP connects to the Neon proxy from
  inside each region. `us-east4` took 21.1 ms, `us-east5` 21.0 ms and
  `us-east1` 31.6 ms. Recording what Prisma 7 hands `pg` showed **one
  statement per read**, including `include`, not four. A 7-query page therefore
  pays about 7 round trips, so +9 ms costs it about 60 ms, and the earlier
  1.3 s was about 4× too large. Container start was p50 0.90 s, max 1.63 s
  (n=12). A warm request took 0.16–0.20 s. 1 vCPU booted no slower than 2. The
  image is 118 MB.
- **2026-09-23, the cutover.** The apex DNS records had to be DNS-only before
  Google would issue the certificate. HTTPS was down from about 16:05 to 16:21
  UTC, so the step belongs outside lesson hours. `fly scale count 0` destroys
  machines, while `fly machine stop` only stops them. Fly was destroyed that
  afternoon, giving up the week-long rollback. Preview was left with no host.
  Cloud Run had been stamping the short SHA as the deployment id, and now
  stamps the full one.
- **2026-09-24, the database followed the app.** From `us-east4`, production
  in `aws-us-east-2` measured 19.5–20.1 ms. Neon's `aws-us-east-1` proxies
  measured 3.9–4.5 ms, and the new project 4.4–4.7 ms. `/api/health`'s
  `latencyMs` went from about 22 ms to 7–9 ms warm, about 100 ms a page. The
  new project, `spiralclass-use1`, was filled with `db-clone-to-region.sh`
  during about an hour behind `MAINTENANCE_MODE`. The rehearsal found three
  bugs:
  - empty arrays under macOS bash 3.2, now caught by
    [`shell-empty-arrays.test.ts`](../../apps/web/tests/config/shell-empty-arrays.test.ts)
  - `btree_gist` missing, because `pg_dump -n public` carries no extensions
  - a verify that compared rows only, now held by
    [`db-clone.integration.test.ts`](../../apps/web/tests/db/db-clone.integration.test.ts)

  The old project was kept as the rollback.

- **2026-09-29.** Production had wedged twice, on 2026-08-26 and 2026-09-21,
  each time alive and not answering. The second wedge answered one check in
  15 s and then nothing. The live service had only a TCP startup probe, which a
  wedged process passes, so the liveness probe was added. It has not yet been
  seen restarting an instance, and the probable cause, a saturated Prisma pool,
  is unfixed.
- **2026-10-14.** Preview is to return as a second Cloud Run service
  ([D-199](./D-199.md)).

**Still open:** whether the deploy's `NEON_API_KEY` reaches the new project (if
not, the checkpoint fails closed), LiveKit reachability from `us-east4`, and
load. Every number here was taken at n≤25.
