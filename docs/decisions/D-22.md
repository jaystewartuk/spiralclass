# D-22. A student's voice is kept only on a recorded per-student consent, and the privacy promises are code the tests hold

Nothing derived from a student's voice is captured or kept unless that
(teacher, student) pair has a recorded consent. For a minor that has to be the
guardian's. The check is `lessonInsightsConsentOk()` in
[`lib/lesson-notes/consent.ts`](../../apps/web/src/lib/lesson-notes/consent.ts),
and every capture point calls it. The published privacy policy and supplier
register are structured data in
[`packages/shared/src/legal/`](../../packages/shared/src/legal/privacy-policy.ts),
and a test holds them against the code. What the policy promises about voice
data (derive, then discard; status but never content for staff; deleted when the
account closes) is enforced where the data is touched.

## Why

The lesson-insights pipeline was the first part of the product to store a
record derived from a student's voice, sometimes a minor's, and to send that
voice to an outside processor. The visible recording indicator tells both people
that a capture is happening. It does not show that anyone agreed to it. Students
come from many countries and some are minors. The safe floor is a capture that
cannot run without a deliberate, per-student, minor-aware consent, enforced at
the point of capture and not at the UI.

The second half has a precedent. The landing page once advertised a feature
whose flag was off everywhere, because the copy and the flag lived in different
files and no test joined them. A supplier list rots in the same way: a vendor
arrives in a pull request, and nobody re-opens the privacy page. So the list is
code, and a test does the joining.

## Options considered

- **Treat the recording indicator as consent.** It was rejected as the only
  safeguard. It is necessary but not sufficient, because it records nothing and
  says nothing about a minor.
- **Let the student's own consent count for a minor.** Rejected. A minor's own
  timestamp never stands in for a guardian's.
- **Gate the A/V recording itself on this consent.** Rejected. The teacher's
  recording is gated separately (Pro, `CLASS_RECORDING_ENABLED`). This consent
  gates only the capture for analysis.
- **Keep the raw per-speaker audio by default.** Rejected. The learning value is
  in the derivatives, so the default is derive-then-discard. A teacher can opt
  in to keeping the audio (`Teacher.lessonAudioRetentionOptIn`, read in
  [`lib/transcription/pipeline.ts`](../../apps/web/src/lib/transcription/pipeline.ts)).
- **A generic admin grid that browses every table.** Rejected for the insights
  tables. Staff get pipeline status only.
- **A hand-written, per-locale privacy notice.** Replaced. See How we got here.
- **A retry queue for a partly failed recording purge.** Rejected as machinery
  nobody would watch. The failure is logged at error level instead.

## What it cost

- Consent is **teacher-attested**. The platform stores a timestamp, not a
  signed artefact. The minor flag is also teacher-set. If it is set wrong, the
  default (`isMinor` false, capture still gated on the adult timestamp) fails
  towards "no capture", not towards "capture without the guardian".
- The policy is in English only. Legal text is never machine-translated
  ([D-72](./D-72.md)), and that costs a reader who does not read English.
- Retention periods other than the 90-day notification window
  (`INBOX_RETENTION_DAYS`) are policy choices made outside this repository. A
  recording on an open account is kept for as long as the account is open.
- Supplier locations cannot be tested. Those the repository pins cite the file
  they come from. The rest cite the vendor, and the page shows
  `SUBPROCESSORS_REVIEWED` so a reader can see how old the list is.

## What it constrains

- **Every capture path calls `lessonInsightsConsentOk()`.** Today these are
  `startBookingRecording` and `maybeStartLessonAudioCapture` in
  [`lib/video/call-recording.ts`](../../apps/web/src/lib/video/call-recording.ts),
  and the browser transcript writer in
  [`lib/transcription/browser-transcript.ts`](../../apps/web/src/lib/transcription/browser-transcript.ts).
  A new path that keeps voice or its text must call it too. A class for two
  also needs the buyer's confirmation for the second person,
  `Package.partnerConsentAt` ([D-149](./D-149.md)). Tests:
  `apps/web/tests/lesson-notes/consent.test.ts`,
  `apps/web/tests/video/call-recording.test.ts`.
- **All consent columns default off.** Do not backfill them, and do not default
  a new pairing to on. Live captions have their own self-service consent
  ([`lib/captions/consent.ts`](../../apps/web/src/lib/captions/consent.ts)),
  which shares the same `isMinor` flag. Do not merge the two consents.
- **Nothing is captured that nobody can see.** Both participants see an
  indicator whenever lines are being kept.
- **`/admin/lesson-insights` shows statuses, counts and timestamps only.** It
  shows no transcript, score, insight, profile text or audio link
  ([`page.tsx`](../../apps/web/src/app/admin/lesson-insights/page.tsx)). If
  staff ever need to read real content, that has to be a deliberate, audited
  capability ([D-25](./D-25.md)), not a column added to this view. No test
  guards this yet. The comment in the file is the guard.
- **Closing a teacher's account destroys her recordings**:
  `purgeTeacherRecordings`
  ([`purge-recordings.ts`](../../apps/web/src/lib/account-deletion/purge-recordings.ts))
  removes `CallRecording`, `LessonAudio`, `LessonTranscript` and
  `LessonSummary`. Storage is deleted first and the row second, one object at a
  time, and a row whose object survived is left in place. The purge runs
  outside the deletion transaction and can never block a deletion. Test:
  `apps/web/tests/account-deletion/purge-recordings.test.ts`.
- **The register stays code.**
  [`subprocessors.test.ts`](../../apps/web/tests/config/subprocessors.test.ts)
  fails when a vendor credential in `src/lib/env.ts` is neither mapped to a
  supplier nor listed as not-a-processor with a reason, when a supplier cites a
  gate that no longer exists, or when the policy loses an Article 13 section or
  picks up another regime's vocabulary. Do not answer a red run by adding a
  "not a processor" entry without a true reason.
- **Do not restate what the code cannot confirm.** At-rest encryption is claimed
  because `FIELD_ENCRYPTION_REQUIRED` makes the key a boot requirement in
  `assertProductionCredentials`. It is a deployment secret, so no file here
  shows it set. The commented-out example in `config/env/preview.runtime.env`
  has misled two sessions into thinking it was unset.
- What is still open: student deletion purges nothing, so a student's voice
  stays in a former teacher's recordings. Nobody has decided whether that is
  right.

## How we got here

- **June 2026.** The pipeline policy (now part of [D-185](./D-185.md)) left
  retention and consent open. They were settled as derive-then-discard with a
  teacher opt-in to keep audio, and transcription stayed behind a flag and a
  vendor key. The consent surface was meant to be the Record action and its
  indicator. Within days that was judged too thin, and a migration (since squashed into
  the baseline) added `is_minor`,
  `insights_consent_at` and `guardian_consent_at` to `teacher_students`, all
  defaulting off. The status-only admin view followed.
- **August 2026.** The privacy page was a bilingual notice hand-written per
  locale. The two variants sat inside a per-locale catalog, so the French
  catalog had machine-translated both, and a French reader saw a link labelled
  "Español" that rendered in French. 54 `web.legal.*` keys came out of all three
  catalogs. The page became one UK GDPR policy, because the operating entity is
  UK-established and the Terms are governed by English law. At the same time,
  the supplier list moved into code. It had 16 entries at first publication.
  The draft's at-rest encryption claim was cut because nothing in the
  repository proved it. It was restored on 2026-08-25, when the operator
  confirmed both encryption variables had always been set in production.
- **After recording went live (from 2026-08-26).** The retention table promised
  deletion on closure, but `anonymizeTeacher` touched only the teacher row,
  device tokens and notifications. The purge closed that gap. It was a
  promise-keeping change and set no new retention period.
- **Later.** Transcripts moved into the participants' browsers
  ([D-185](./D-185.md)), and the same gate went there: a class's caption lines
  are kept while the teacher has captions on. The legacy audio capture now
  starts on `participant_joined` when transcription and recording are both
  enabled, not on the Record tap. Both changes reverse the June "rides the
  Record action" framing. The visible indicator stays.
