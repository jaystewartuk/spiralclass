# D-22. Lesson-insights capture is gated on an explicit per-student (minor-aware) consent

**Status: Active.** Adds a code-level consent gate to the lesson-insights
pipeline ([D-19](./D-19.md)).

**What changed.**

1. **Capture is gated on an explicit per-student consent.** D-21 §2 leaned on the
   visible recording indicator as the consent surface. That indicator is necessary
   but, as a durable safety floor, it is **not sufficient on its own**. Voice capture for the insights pipeline now
   requires an explicit, recorded consent for the specific `(teacher, student)`
   pair, enforced **at the point of capture**:

   - Three additive columns on `teacher_students`: `is_minor` (bool, default
     false), `insights_consent_at`, `guardian_consent_at` (both nullable
     timestamps). All default OFF, so every existing and new pairing starts with
     capture disabled.
   - A pure predicate `lessonInsightsConsentOk()` (`lib/lesson-notes/consent.ts`):
     a **minor** is gated on the **guardian** timestamp; an adult on the student's
     own. A minor's own consent never stands in for a guardian's.
   - `startCallRecording` (`app/actions/call-recording.ts`) loads the pairing's
     consent and **skips `startLessonAudioCaptures` when it isn't satisfied**. The
     A/V recording the teacher asked for is **never** gated on this — only the
     insights capture is.
   - A teacher-facing control on the student page records/revokes consent and flags
     a minor (`setInsightsConsent`).

**Why.** Storing a derived record of a student's voice — possibly a minor's —
and shipping it cross-border to external vendors is the processing D-19 §6
deliberately gated. The safe posture is: keep the pipeline dormant in production
**and** make capture structurally impossible without a deliberate, per-student,
minor-aware consent, so the indicator is never the only thing standing between a
student and an external voice processor. The gate
is cheap, defends-in-depth, and is the right floor regardless.

**What was affected.**

- Schema: `teacher_students` gains `is_minor` / `insights_consent_at` /
  `guardian_consent_at` (migration `20260625500000_lesson_insights_consent`,
  additive). No backfill — capture defaults off everywhere.
- `lib/lesson-notes/consent.ts` (new pure helper), `app/actions/call-recording.ts`
  (gate), `app/actions/insights-consent.ts` (new action), the student learning
  profile card + a new consent control.
- No teacher→student payment, booking, or subscription logic is touched.

**Unresolved risks.**

- **Consent capture is teacher-attested.** The teacher records that consent was
  obtained; the platform stores the timestamp, not the underlying signed artifact.
  Storing the artifact itself would be a later addition on top of these columns.
- **Minor flag is teacher-set.** A mis-set `is_minor` is possible; the
  conservative default (false, with capture still gated on the adult timestamp)
  means the failure mode is "no capture", not "capture without guardian consent".
