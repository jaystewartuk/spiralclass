# D-69. `ClassContent`/`ClassMaterial` merge into `LibraryMaterial`; AI compose gains a template field on both outputs

**What changed.** Three tables collapse into one. `ClassContent` (one
Markdown body per booking, always visible) and `ClassMaterial` (a per-class
file/link pushed on a `send_timing` schedule) are gone; both are now ordinary
rows in the pre-existing `LibraryMaterial` table (the reusable level-gated
library the level-materials and taxonomy work already built), discriminated by
two new nullable columns:

- `booking_id` — `NULL` = a reusable library item (unchanged behavior); set
  = private to that one class (`Booking.materials`).
- `send_timing` — `NULL` = always visible, no push (the old `ClassContent`
  behavior); set = pushed on that schedule (the old `ClassMaterial`
  behavior).

`level_id` becomes nullable (a booking-scoped row has no level).
`ClassContentRevision` is replaced by a generalized `MaterialRevision`, keyed
by `material_id` instead of `booking_id` — version history is now a property
any material with a body _could_ have, though only the booking-scoped
"content" material exercises it today. The app layer still enforces "at most
one body-bearing, never-scheduled material per booking" (mirroring the old
`ClassContent` UNIQUE constraint) via find-then-upsert rather than a DB
constraint, since the merged table has no reason to forbid a booking from
holding several body-bearing materials in the future.

The two AI compose paths (a single class's content vs. a standalone library
material) now share one prompt builder (`lib/materials/prompt.ts`,
`buildMaterialPrompt`) and one Anthropic call (`generateMaterial`, replacing
`generateClassContent`/`generateLibraryMaterial`) — "one AI plumbing, two
outputs" was already true for the Pro gate and monthly cap; it's now true for
the prompt code too. Both outputs gained a lesson-template picker
(`templateId`) — previously only class-content generation could follow a
saved template structure (D-46); the standalone library generate form
(`dashboard/materials/generate-form.tsx`) had no template field at all, which
was the concrete gap that triggered this pass.

**Why it likely changed.** A teacher-facing complaint that "material" and
"generated content" felt like two different things that should be one, with
duplicated fields (title, level, visibility, tags) and an inconsistent
capability split (the class page could author content but the library page
couldn't generate it with AI; the library page could hold a file but a class
couldn't attach one without a separate flow). The taxonomy work
already treated a library item as the general "material" concept; keeping
`ClassContent`/`ClassMaterial` as separate entities meant every future
materials feature (tagging, AI, templates) had to be built twice.

**What was affected.** `apps/web/prisma/schema.prisma` + migration
`20260712020000_merge_class_content_and_materials`; `lib/materials/*`
(replaces `lib/class-content/*` and `lib/library-materials/*` — `config.ts`,
`handlers.ts`, `revisions.ts`, `prompt.ts`, `tags.ts`, `templates.ts` all live
here now); `lib/ai/anthropic.ts`; `lib/notifications/materials.ts`;
`lib/materials/timing.ts` (`materialSendTimeElapsed` now accepts a null
timing, treated as always-visible); `lib/storage/materials-purge.ts`;
`app/actions/{library,class-content}.ts` (`materials.ts` retired — its
upload/delete flow is now `uploadBookingMaterialAction`/
`deleteLibraryMaterialAction` on `library.ts`); the class detail page's
materials panels; the standalone library page's generate form; the student
booking detail + print pages; the teacher student-detail cross-booking
materials rollup; the API routes that read the old models; and tests across all
of the above.

**Unresolved risks.** The UI still shows the booking-scoped "content" editor
and the "scheduled materials" list as two separate cards on the class page —
same visual split as before, just both backed by the merged table now — not
the fully unified "one form, any material" editor floated during design.
`send_timing: NULL` (i.e. "attach a file/link but don't push it, just show
it on the class page") is schema-supported but not yet exposed in either
UI's timing picker, which still requires one of the four scheduled values for
a file/link attachment; only the content material actually uses the null
state today.
