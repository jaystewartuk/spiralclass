# D-182. Production video returns to LiveKit Cloud while Oracle has no capacity for the box

**Status.** Reversed by [D-187](./D-187.md) (2026-09-24): production video
moves to a free Compute Engine box at `livekit.spiralclass.com`, under this
record's three conditions. Previously Active · reverses
[D-94](./D-94.md)'s first half (production's move onto the self-hosted box).
D-94's second half — the four gated video flags — is untouched.

**What changed.** `config/env/production.runtime.env`'s `LIVEKIT_URL` points at
`wss://spiralclass-qzx0z7t7.livekit.cloud`, a LiveKit Cloud project named
`SpiralClass` (`p_g4h3ujut5sd`, US region), instead of
`wss://livekit.spiralclass.com`. Production's `LIVEKIT_API_KEY` and
`LIVEKIT_API_SECRET` in Infisical are that project's new pair. No app code
changed, exactly as when D-94 moved the other way: `LiveKitProvider` talks to
any LiveKit-API-compatible server, and `RTC_PROVIDER` stays `livekit`.

**Why.** The box D-94 moved production onto no longer exists. `CUTOVER.md`
step 3 terminated it at 13:30 on 2026-09-19, deliberately and with its boot
volume, to free the tenancy's whole 200 GB for the rebuilt box. Every launch
since has been refused: 56 attempts between 13:38 and 22:14, each one
`Error: 500-InternalError, Out of host capacity.`, in a region
(`mx-queretaro-1`) with one availability domain to ask. The tenancy's limits
are clear — 2 cores, 12 GB and 200 GB all available — so nothing here is
fixable by waiting for a quota.

That made the cutover's own accepted risk real: "If capacity is unavailable
after step 3, LiveKit is down until Oracle has hardware. Accepted on the basis
that no classes are booked until Monday morning." Monday morning is the
deadline, and a booked class with no video is the outcome this avoids.

**What was considered and rejected.**

- **Keep retrying and do nothing else.** The retry loop does keep running, but
  it is a lottery with no stated odds, and losing it means discovering on
  Monday morning that a class cannot start.
- **Rebuild in another Oracle region.** A new VCN, a new reserved address and
  new DNS, decided at night, for the same free-tier capacity lottery and worse
  latency to the users.
- **Pay As You Go on Oracle.** Plausible — paid tenancies get capacity priority
  — but it needs a card, it is the operator's decision, and it does not restore
  video tonight.
- **Point production at preview's stack.** There is no preview stack: it lived
  on the same box.

**What it constrains.** `LIVEKIT_URL` does not move back to
`livekit.spiralclass.com` on the grounds that a box exists again. Before it
moves, all three must hold: the box serves LiveKit through its own certificate
(`CUTOVER.md` step 7), a real class has been booked and joined on it, and the
pair in Infisical is the box's, not this project's. D-94's capacity ceiling
(~15-20 concurrent 2-participant rooms) and its graduation trigger stand
unchanged for that day.

**What was affected.** `config/env/production.runtime.env` (one value, plus the
comment block above it). Nothing else: `apps/web/tests/lib/csp.test.ts` already
allows `https://*.livekit.cloud` and `wss://*.livekit.cloud`, so the browser
reaches the Cloud socket with no header change.

**Trade-offs accepted, and unresolved risks.**

- **Self-hosting's reason for being is paused, not abandoned.** D-94 moved
  production onto the box to own the media path; this hands it back to a vendor
  with its own quota and pricing.
- **The captions agent and the recording egress ran on the box and now run
  nowhere.** Live captions and class recording are unproven on Cloud in this
  deployment and nothing here checks them. A class itself — two participants in
  a room — does not depend on either.
- **Preview has no video at all**, and `preview.spiralclass.com` is down
  entirely until a box exists. `CUTOVER.md` step 6 already prefers that to
  running a production build there.
- **`livekit.spiralclass.com` still resolves to an address with nothing behind
  it**, and `scripts/local/synthetic.sh`'s certificate probe for that host will
  fail until the box returns or the probe is re-pointed. Left as is
  deliberately: a failing probe for a host that is genuinely gone is honest.
- **This record was written during the outage it describes.** The measured
  numbers in it are the attempt counts and the error string, both from the
  retry loop's log; nothing else here was measured.
