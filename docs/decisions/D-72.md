# D-72. The platform is language-first: `teachers.discipline` becomes `teachers.target_language`, non-language subjects are removed, and the two language lists collapse into one registry (2026-07-15)

**Status: Active as architecture; the language-first _positioning_ below is
superseded by [D-173](./D-173.md).** Everything this record built still stands
and is what the code does: one registry, `teachers.target_language` as a BCP-47
code, `asr` a capability flag on it. What no longer holds is the sentence under
it — that SpiralClass is a tool for **language teachers**. The audience is
independent teachers of **any subject**, anywhere in the world, which is what
`CLAUDE.md`'s opening says and what every public marketing surface sells;
D-173 records that widening and what it cost, and
`packages/shared/src/i18n/i18n.test.ts` fails the build on copy that scopes the
audience back to language teaching. **The schema is still narrower than the
copy** and both halves are true at once: a teacher's subject remains a code
from the 174-language registry, and widening that column is its own change,
not something the copy already did. Reverses D-20's "the platform stays
subject-agnostic" stance (that decision's other three calls — no platform
curriculum, teacher-owned tags/levels as data, packs seeded additively — all
stand). Builds on [D-17](./D-17.md) (in-house AI compose), [D-20](./D-20.md),
and [D-27](./D-27.md) (live captions). Product detail:
`../../product/CLASS_CONTENT_INPUTS.md`.

**What was decided.** SpiralClass is a tool for **language teachers**, and the
code now says so. Three calls:

1. **Language-first positioning, subject-agnostic architecture.** The product,
   its features, and its data model commit to language teaching. What stays
   generic is the cheap part D-20 already got right: levels and focus tags are
   teacher-owned rows, not enums, so nothing here needs a migration to widen
   again. What goes is the _hedging_ — the music/math/generic seed packs, the
   six-code subject picker, and the prompt's "this might not be a language
   lesson" branches.

2. **`teachers.discipline` → `teachers.target_language`.** The old column did
   three jobs at once: name the subject, select the focus-tag seed pack, and
   flag whether the subject was a language. On a language-first platform those
   collapse into one BCP-47 code: the pack derives from it
   (`src/lib/focus-packs.ts`), the subject name is `languageName(code)`, and
   "is it a language" is no longer a question. `subject_label`,
   `DisciplineDef.placeholder`, `subjectIsLanguage`, and a `namesSameLanguage`
   string heuristic all died with it. Migration
   `20260715000000_language_first_target_language` maps `spanish→es`,
   `english→en`, everything else `→ NULL` (the teacher re-picks).

3. **One language registry.** `caption-languages.ts` (12 ASR-gated codes) and
   `material-languages.ts` (20 English _names_) were the same concept in two
   representations with two ranges, and had already drifted: a teacher could
   generate Thai materials the captions picker had never heard of, and `zh` was
   labelled "Mandarin Chinese" when ISO says `zh` is Chinese-the-macrolanguage.
   They become `packages/shared/src/languages.ts` — one list of
   `{ code, label, asr }`, where `asr` is a **capability flag, not a second
   list**. Caption surfaces filter `asr: true`; "what do you teach" offers
   everything. Codes are stored; labels and prompt names are derived.

**Why.** The prompt bug that started this made the hedge visible: the material
generator had **no subject input at all**, so the only concrete noun it saw was
the output language and it inferred a language lesson for everyone. It was
correct for the only live teacher purely by accident. The deeper cause was that
the product was already language-shaped where it mattered — live captions with
ASR + translation, CEFR levels seeded for every teacher, a
`grammar/vocabulary/skill` tag taxonomy, the student-UI-in-English asymmetry —
while the schema and copy pretended otherwise. The music and math packs were
10-12 tags jammed into "theme"/"activity" because the taxonomy never fit them.
We were paying the full cost of subject-agnosticism and getting the ergonomics
of a Spanish-only tool.

Nothing about "globally popular" required the hedge: independent language
teachers are a global, tool-poor market, and it is the vertical where the AI
features (captions, translation, level-pitched generation) actually
differentiate. They are worth nothing to a guitar teacher.

**Language coverage.** 174 ISO 639-1 codes **generated from CLDR**
(`packages/shared/scripts/generate-languages.mjs`, bilingual, ~15KB).
Generation, not hand-maintenance, because CLDR already has correct bilingual
names — and it caught the `zh` bug on its own. Build-time, not runtime
`Intl.DisplayNames`, because Hermes ships a weaker ICU than Node.

Deliberately **not** all ~7,900 ISO 639-3 codes: ~95% have no Spanish name, the
list is ~240KB, and essentially none are taught. Languages outside 639-1 that
someone does teach get curated in, as data, when a real teacher asks — and
only against a published catalogue, because a wrong code silently mislabels a
teacher's own language, which is worse than an absent one.

**Unresolved risks.**

- **A stored code the registry no longer carries** renders as the raw code
  (`languageLabel` and `languageName` fall back to it), the materials settings
  page treats it as unset, and the picker shows no selection; only a re-save of
  that field is rejected as "Unknown language", so the teacher re-picks. No
  read path throws.
- **Macro variants are empty.** The `macro` and `parent` fields exist so a
  macrolanguage's variants can be added as **data, not a schema change**; no
  generated row uses them today.
- **`teachingLanguage` is still defaulted from the UI locale** in the material
  pickers, not from the teacher's own value. It is the better default (it is
  literally "the language you teach in") and all 12 of its codes now share the
  one registry, so the swap is small — just not done here.
- **Migration not yet run anywhere.** Written and reviewed, not applied; no prod
  DB access this session to confirm no teacher holds a retired code. The `CASE`
  has no `ELSE`, so any unexpected value lands as `NULL` rather than being forced
  to a wrong language. Already-seeded `music:*`/`math:*` focus tags are left
  untouched — teacher-owned rows (D-20).
- **A dangling citation**: nine code sites cite a decision number (streaming
  generation, the old `MATERIAL_LANGUAGES`) that no record on `main` carries —
  the residue of a numbering collision between two in-flight branches.
  Unrelated to this change; worth backfilling.
