# D-157. One registry defines green; the laptop and GitHub's runners both run it, and no workflow restates it

`scripts/ci/steps.mjs` is the only definition of what "green" means and
`scripts/ci/gate.mjs` is the only program that runs it: `.githooks/pre-push`
runs the fast tier on the laptop, `gate.yml` runs the same fast tier on a
runner, and `heavy.yml` runs the heavy tier (mutation, integration, the browser
suites, the image build) on runners for every pull request and every push to
`main`. A workflow calls `gate.mjs` or a deploy script and names no step of its
own. Nothing is scheduled anywhere, and on the laptop one heavy job runs at a
time.

## Why

Every time the checks existed in two places, the copies drifted. The deploy is
the worst case on record: when the production deploy steps were re-typed into a
script in August 2026, the re-typed copy was the one missing the pre-migration
Neon checkpoint, and `promote.mjs` went on reporting a checkpoint it had not
taken. Where the checks run has moved repeatedly; the registry made each move
cheap.

## Options considered

- **Checks defined in workflow YAML** (before August 2026) — a second
  definition of green that the laptop cannot run.
- **Laptop only, no workflows** (August–September 2026) — no fallback when the
  laptop is shut, no status from a cloud session, the heavy suites held the
  machine 20–40 minutes per run, and the amd64 production image was a QEMU
  cross-build on an arm64 Mac.
- **A hand-written job list in `heavy.yml`** — correct the day it is written;
  the first heavy step added later runs on the laptop and in no job, silently.
- **A test container and port per worktree** — fixes the corruption, doubles
  the memory problem on a 16GB machine.
- **Visual baselines for both macOS and Linux**, or a wider
  `maxDiffPixelRatio` — the first doubles regeneration for a set nothing ships
  on; the second makes the guard decorative (two lines of grey text swapping
  places on a 1280×2184 page is about `0.003` and already passes at `0.01`).
- **A `schedule:` trigger for the maintenance jobs** — a cron fails silently,
  which is how the backup gap below happened.

## What it cost

- A workflow is a second runner, so `local-gate` has two producers (the hook via
  `scripts/ci/status.mjs`, and `gate.yml`'s `status` job). They run the same
  registry and can only disagree about timing.
- The status is self-attested: nothing stops one being posted by hand. Its
  value is the mechanical "was this exact commit checked".
- A fork PR gets no `local-gate` status (read-only token, no secrets); the
  maintainer runs the gate against it.
- A runner deploy leaves no entry in the local `.gate/release.json`;
  `git log origin/production` and Cloud Run's revision list are the record.
- The laptop no longer catches a visual regression before a push, and
  `pnpm promote --force-gate` on a Mac skips the visual sweep.
- Nothing probes production between deploys, and nothing makes an off-Neon
  copy on a schedule.

## What it constrains

- **No check in a workflow.** Add it to `steps.mjs`. Guarded by
  [`local-gate.test.ts`](../../apps/web/tests/config/local-gate.test.ts):
  "no workflow runs a check the registry already owns" (the forbidden list is
  derived from `STEPS`), "the gate workflow runs gate.mjs and names a tier",
  "the heavy workflow asks the registry for its matrix", and "no deploy workflow
  reimplements a deploy script". No composite action ("no composite action came
  back").
- **Every suite is a registered step.** A suite no step runs is not run;
  `test-packages` filters by path (`./packages/*`), not by package names.
- **The workflows stay cheap and contained**, each asserted in the same file:
  `runs-on` exactly `ubuntu-latest` (larger runners bill even on a public
  repository), every action pinned to a 40-character SHA with its version in a
  comment, `permissions: contents: read` at the top, no `pull_request_target`,
  no `schedule:`, a concurrency group (`cancel-in-progress: false` on the
  deploy), a `timeout-minutes` on every job, `persist-credentials: false`, and
  no event-derived `${{ }}` inside a `run:` body. When a job genuinely needs an
  arm64 runner, allow it by name; do not widen the check.
- **`local-gate` is the one required status**, posted through the REST API so it
  binds one SHA. The `gate.yml` job context is not required (the laptop posts in
  about 90 seconds, the runner in about ten minutes), and Heavy is not required
  (about 17 minutes); promote is what refuses an uncertified commit
  ([D-199](./D-199.md)).
- **`heavy.yml` also runs on `push: main`**, because a `pull_request` run tests
  the merge with base as of that moment. Its `complete` job, named **Heavy
  tier**, is the stable name promote reads and cannot pass while a leg failed.
- **The pre-push hook always runs the fast tier.** `GATE_TIER=full` opts in.
  `SKIP_GATE=1` and `--no-verify` are forbidden (CLAUDE.md).
- **One heavy job at a time on the laptop.** The gate, `integration.sh`,
  `e2e.sh` and `image-build.sh` take the machine lock
  ([`scripts/ci/lock.mjs`](../../scripts/ci/lock.mjs)); runners pass
  `--no-lock`. Behaviourally tested by
  [`machine-lock.test.ts`](../../apps/web/tests/config/machine-lock.test.ts).
  Every checkout shares one turbo cache through
  [`scripts/turbo.mjs`](../../scripts/turbo.mjs).
- **One visual baseline set, `-linux.png`, written only by `heavy.yml`'s
  dispatch.** `regression.spec.ts` skips off Linux, `scripts/ci/e2e.sh` refuses
  to regenerate off Linux, and
  [`manifest.test.ts`](../../apps/web/tests/visual/manifest.test.ts) stays in the
  fast tier: it is the only thing that notices a capture with no committed
  image, which Playwright would otherwise write on the runner and pass.
- **Nothing is scheduled.** `synthetic` and `sweep` are commands in
  [`scripts/local/jobs.mjs`](../../scripts/local/jobs.mjs), each with a 7-day
  staleness budget that `pnpm gate` reports as a warning, never a failure. There
  is no backup job: Neon's point-in-time restore and the pre-migration
  checkpoints are production's backup ([D-178](./D-178.md));
  `scripts/local/backup-prod-db.sh` stays unregistered, for an off-Neon copy by
  hand. A registered job nobody runs trains the operator to skim the banner.
- **If the repository ever goes private**, minutes are metered again and nothing
  warns. Reverse in this order: delete `.github/workflows/`; re-invert the guard
  block in `local-gate.test.ts`; deploy from the laptop with
  `scripts/database-deploy.sh` then `scripts/cloudrun-deploy.sh`; accept the
  QEMU build. No workflow may become the only way to deploy or the only
  definition of a check.

## How we got here

- **2026-07-06 → 2026-08-10.** Local test runs were banned because the suites
  ran an 8GB laptop out of memory; the ban was retired when a 16GB M4 replaced it.
- **2026-08-12.** The test tiers moved from runners onto the laptop, behind the
  pre-push hook, with `steps.mjs` as the registry and `local-gate` as a commit
  status. The failure mode the hook targets was confirmed 2026-07-20: an edit
  made after a green run, pushed unchecked.
- **2026-08-17.** Actions use measured at ~1,500–1,700 billable minutes a month
  against a 2,000-minute allowance: the deploy ~744 (30 runs, 2026-08-08..16,
  7.4 min average), the nightly sweep ~600–750, the backup ~120, synthetic ~60.
  Moving the deploy out brought it to roughly 780. Fly's Depot builder had been
  tried first: a fixed ~4GB against Turbopack's ~3.45GB peak, a coin flip that
  turned `main` red on 2026-07-15.
- **2026-08-25.** The allowance emptied anyway and production's database went
  **eleven days without a backup** while nothing said so. All fourteen workflows
  and four composite actions were deleted; the crons became hand-run commands
  with a staleness nag. The same day the backup job was dropped: Neon backs
  production up. That gave up an off-provider copy and the R2 dump's 14-day
  reach; checkpoints reach back five deploys.
- **2026-08-31.** Seven concurrent sessions ran seven gates on one laptop (10
  cores, 16GB, 8.1GB of 9.2GB swap in use; seven worktrees held 18GB against
  22GB free). Two shared resources corrupt rather than queue: the one test
  Postgres on port 5433, and port 3000, where a stray `next start` once caused
  eleven spec failures. The machine lock (one-hour timeout) and the shared turbo
  cache followed (a monorepo `typecheck` from 16.5s to 88ms in another
  worktree). The Tier 2 escalation left the hook; the heavy suites ran once per
  batch of merges.
- **2026-09-04.** The repository was public, so the minutes were free, and
  `ubuntu-latest` builds the amd64 image natively instead of a 20–30+ minute
  QEMU cross-build. The workflows came back on the condition above, and the
  "no workflows" guards were inverted, not deleted.
- **Early September 2026.** `packages/shared` (1,196 tests in 71 files) and the
  captions agent (69 in 9) had been run by no step. Registering them found three
  red assertions, one a timezone defect only a non-UTC machine could see.
- **2026-09-05.** A Linux baseline set (120 images) let the heavy tier move to
  runners. `test-web` measured 9m53s on a runner against 64.7s on the laptop, so
  a `heavy` tier was split out of `full`.
- **Between 2026-09-05 and 2026-09-09.** `pnpm ship-pr` was deleted; batching
  had only been arithmetic against one laptop. Its careful merge wrapper went
  with it; it existed because on 2026-08-30 `gh` reported failure after both
  PRs had merged.
- **2026-09-09.** Stale Linux images (`features-390-*`) turned Heavy red; the
  macOS set, read by no release, was deleted rather than regenerated.
