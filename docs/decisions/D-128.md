# D-128. The privacy layer becomes UK GDPR, and the supplier list becomes code

**What changed.** `/privacy-notice` was a bilingual _Aviso de privacidad_ written
under Mexico's LFPDPPP. It is now a single **UK GDPR / Data Protection Act 2018
privacy policy**. Four things moved together.

- **One document, in `@spiralclass/shared`.** `legal/privacy-policy.ts` holds
  the policy as structured data — sections, a lawful-basis table, a retention
  table — and `legal/subprocessors.ts` holds the supplier register.
  `apps/web/src/app/privacy-notice/page.tsx` is a renderer with no copy of its
  own.
- **The Mexican-law framing is gone.** No LFPDPPP, no ARCO rights, no `aviso`,
  no INAI. In their place: the controller named and located, an Article 6
  lawful basis per purpose, the identified interest wherever the basis is
  legitimate interests, international-transfer wording, retention periods, the
  full UK data-subject rights list, and the right to complain to the ICO.
- **A sub-processor register, in code.** Sixteen suppliers with what each is
  for, what each can see, where each processes, and — for the three that are
  feature-gated — which gate. The page renders gated suppliers under a heading
  that says they receive nothing while the gate is off.
- **A guard test that joins the two things nothing joined.**
  `apps/web/tests/config/subprocessors.test.ts` holds the register against the
  vendor credentials `src/lib/env.ts` declares, in both directions: a new
  vendor env var must be either mapped to a supplier or listed as
  not-a-processor _with a reason_, and a supplier may not cite a gate that no
  longer exists. It also asserts the policy keeps the sections UK GDPR
  Article 13 requires, and that the Mexican-law vocabulary does not come back.

**Why it likely changed.** The Terms have been governed by the laws of England
and Wales throughout, and the privacy page was the last surface still written
to a different regime — the last piece of the pre-[D-58](./D-58.md) entity that
had not moved. Bringing it into line is what this decision does; the assessment
of what the earlier document did or did not satisfy is not published here (see
[D-159](./D-159.md)).

The register-as-code half is a second, separate lesson applied. This repository
has already had one failure of exactly this shape: the landing page advertised
pronunciation scoring whose flag was off in every environment, because the copy
lived in the i18n catalog, the flag lived in a config file, and no test joined
them ([D-114](./D-114.md), and `ai-marketing-claims.test.ts` is the join). A
supplier list is the part of a privacy policy that rots the same way — a vendor
is added in a pull request, the page is one nobody re-opens. So the list is
code and the test is the join.

**What was affected.**

- **The `?lang=` variant pattern is gone from this page.** Legal copy is
  authored in English and never machine-translated — the standing rule from
  [D-81](./D-81.md) — and the old shape actively broke it: the two variants
  were keyed `web.legal.privacy.es.*` / `…en.*` _inside a per-locale catalog_,
  so `catalog.fr.ts` had machine-translated both, and a French reader was shown
  a link labelled "Español" that rendered in French. 54 `web.legal.*` keys were
  removed from all three catalogs. `/terms` is untouched and keeps its own
  `?lang=` pattern.
- **Metadata still follows the viewer's locale.** The browser tab and the
  search snippet are chrome, not legal text, so `web.privacyNotice.meta.*` stays
  translated in all three locales — retitled from _Aviso de privacidad_ to
  _Política de privacidad_ and its equivalents.
- **`tests/seo/page-metadata.test.ts`** now asserts one document with a bare
  canonical instead of the two-variant pattern.

**Unresolved risks.**

- **Retention periods are policy choices, not facts read off the code.** The
  90-day notification window is real (`INBOX_RETENTION_DAYS`); the rest are set
  outside this repository (see [D-159](./D-159.md)).
- **Supplier locations cannot be verified by a test.** Four are pinned by this
  repository and cited inline (`fly.production.toml`,
  `infra/database/neon/README.md`, and two lines of
  `config/env/production.runtime.env`); the rest are the vendor's own published
  region, read on `SUBPROCESSORS_REVIEWED`, which the page renders so a reader
  can see how fresh the list is rather than trusting an undated table.
- **RESOLVED 2026-08-25, and the page was corrected.** The draft claimed that
  sensitive stored values are encrypted at rest; it was cut before publishing
  because the repository could not confirm it. the operator confirmed that **both**
  `FIELD_ENCRYPTION_KEY` and `FIELD_ENCRYPTION_REQUIRED` are and have always
  been set on the Fly production app, so the claim was true all along and the
  policy now makes it — covering the Wise API token and RSA signing key
  (`lib/wise/credentials.ts`) and the Google Calendar refresh token
  (`lib/calendar/google/connection.ts`), all AES-256-GCM under HKDF-derived
  per-column subkeys.
  **The two residues this entry first recorded are both closed by that second
  fact, and the reasoning is worth keeping.** `FIELD_ENCRYPTION_REQUIRED` makes
  the key a hard boot requirement (`assertProductionCredentials`), so
  production cannot start without a valid one — the silent fallback to
  plaintext is unreachable there, and because the flag has always been set, no
  production row was ever written in the pre-rollout plaintext state. The
  absent backfill is therefore moot rather than outstanding.
  ⚠️ **Why the repository said otherwise, which is the transferable part.**
  `FIELD_ENCRYPTION_REQUIRED` is a Fly **secret**, not runtime config, so it
  appears in no file here — while `config/env/preview.runtime.env` carries it
  as a commented-out example, which reads as "this is a runtime-config var and
  it is unset everywhere." Two sessions in a row drew the wrong conclusion from
  that. The fix is a comment where the misleading example is, not a code
  change, and it is not in this PR.
- **The document is English-only.** That follows D-81 and it has a real cost
  for a reader who does not read English. A professionally translated version —
  not a machine-translated one — would close it.
