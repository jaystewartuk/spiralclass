# D-66. Infisical (cloud free tier) replaces plaintext `.env.fly.local` as the Fly deploy secrets source

**What changed.** The Fly app's (`agendaprofe`, currently serving preview)
runtime secrets move from a plaintext `.env.fly.local` file, pasted by
hand into `fly secrets set`, to Infisical Cloud's free tier: one project
(**SpiralClass**), two environments (`preview` now, `production` created but
left empty until the Fly production promotion actually happens). `infra/infisical/push-fly-secrets.sh` reads a
given environment via the Infisical CLI (`infisical export --format=dotenv`)
and pipes it straight to `fly secrets import` — same stdin-only, no-argv
house style as `infra/cloudflare-r2/push-fly-secrets.sh`. R2 credentials
stay excluded and Tofu-owned (D-65); Infisical owns everything else
`apps/web/src/lib/env.ts`'s `serverSchema` reads that isn't R2 — see
`infra/infisical/README.md` for the full var list. Shared-across-environment
secrets (Resend, Sentry, Inngest, Google OAuth client, etc.) use Infisical's
cross-environment secret references (`${preview.KEY}`) from `production`
instead of duplicating values, so a rotation in one place propagates instead
of silently drifting.

**Why it likely changed.** `.env.fly.local` was a manual, un-versioned,
un-audited file — no record of who has a copy, no rotation trail, and
every Fly deploy required re-pasting values by hand. It was also a growing
list (Stripe, Supabase, Inngest, Sentry, Resend, Google OAuth, LiveKit,
Upstash, Wise) with real overlap between what preview needs today and what
production will need once it migrates to Fly — a plaintext file has no way
to express "same value, different environment" without literally
duplicating the file. Infisical's environment model (plus secret references
for the shared subset) fits that shape directly. Cloud free tier over
self-hosted: this is a solo-dev project at a scale where self-hosting
Infisical (a new stateful Postgres+Redis service, patch/backup/upgrade
burden) would add more operational risk than the plaintext file it's meant
to replace — self-hosting only pays off with compliance requirements or a
multi-team setup, neither of which applies here. `infra-postgres` (the
Hetzner scaffold) stays config-only, unrelated to this.

**What was affected.**

- `infra/infisical/push-fly-secrets.sh` — new script, mirrors
  `infra/cloudflare-r2/push-fly-secrets.sh`'s stdin-piping pattern.
- `infra/infisical/README.md` — new: account/project/environment setup,
  the shared-secret-reference pattern, the full var list (cross-referenced
  against `env.ts`), and the `NEXT_PUBLIC_*`/build-arg gap this change
  deliberately does not touch.
- `.env.fly.local` — retired once Infisical actually holds every value (see
  README's "Retiring" section); never committed to git, so no history to
  scrub.
- Root `Dockerfile` — gained a third `NEXT_PUBLIC_*` build-arg
  (`NEXT_PUBLIC_TEACHER_PHOTOS_R2_PUBLIC_URL`), surfaced while auditing
  which vars Infisical should/shouldn't own.
- `infra/cloudflare-r2/README.md` — new note documenting that the
  `teacher-photos` public URL is manual, not a Tofu output, and why it's
  excluded from both Infisical and `push-fly-secrets.sh`.
- No application code changed — this is a secrets-delivery mechanism, not a
  runtime behavior change. `apps/web/src/lib/env.ts` continues to read the
  same env var names it always did; Infisical/Fly are just what populates
  them now instead of a hand-pasted file.

**Unresolved risks.**

- **Nothing here has been run against the live Infisical or Fly APIs** — no
  network path to `app.infisical.com` or `api.fly.io` from this session.
  `infisical export --format=dotenv`'s exact output shape and the
  cross-environment secret-reference syntax are documented-but-unverified;
  confirm both live before treating this script as routine. See the
  `UNVERIFIED IN THIS SESSION` comments in both new files.
- **`NEXT_PUBLIC_*` build-time vars are mostly untouched by this change** —
  they're baked into the Docker image via `--build-arg` at `fly deploy`
  time, not read from `fly secrets`/Infisical at runtime. Three are wired
  that way (manually, per the root `Dockerfile`'s comment):
  `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_ANON_KEY`, plus
  `NEXT_PUBLIC_TEACHER_PHOTOS_R2_PUBLIC_URL` (added alongside this change,
  once review surfaced it — the R2 `teacher-photos` public bucket URL,
  non-secret, sourced manually from the Cloudflare dashboard since
  `infra/cloudflare-r2` deliberately doesn't provision/output the public
  domain, see that module's README). Sentry/PostHog `NEXT_PUBLIC_*` vars
  still aren't wired into the Fly build at all. A real gap, but pre-existing
  and out of scope here — not something this
  secrets-manager swap was meant to fix.
- **Actually entering the real secret values into Infisical is a separate,
  human-run step** (same adoption discipline as [D-65](./D-65.md)'s Tofu imports) —
  this decision and its scripts are plumbing, not a claim that the values
  have already been migrated off `.env.fly.local`.
- **Production environment is a placeholder** — created in Infisical now so
  the shared/override structure exists ahead of need, but has no secrets
  and no wiring into any script/CI. Do not push to it until the actual Fly
  production promotion happens; pushing now would
  be pushing preview-shaped values at a Fly app that doesn't exist yet.
