# D-164. Nothing in the tree describes what does not exist or lists what is not done: dead things are deleted, and work owed is an issue

A runbook, infrastructure module, development path or document that describes
something which does not exist, or was never applied, is deleted. It is not
banner-ed, archived or kept "for history"; git history is the archive. Work not
yet done lives in this repository's GitHub Issues
(<https://github.com/jaystewartuk/spiralclass/issues>). It never lives in a
file: no `TODO.md`, no `BACKLOG.md`, no `plans/` directory, and no dated audit
whose last section is a findings list.

## Why

A description of nothing reads as authoritative and is wrong. Twice it nearly
caused damage:

- `ORACLE_RUNNER.md` had four stacked "superseded" banners above a
  **`Status: LIVE`** line that was false for seven weeks. A reader who trusted
  the heading got the wrong answer. A reader who trusted the banners read 36k to
  learn none of it applied.
- `infra/oracle-runner/`'s README said "a `tofu apply`/rebuild today reproduces
  the box as-is". It had never been applied. On 2026-08-29 a session read that,
  and twice proposed applying it to fix a missing TLS certificate. That would
  have changed a template while production stayed broken. The real fix was a
  hand edit over SSH and `caddy reload`. `infra/cloudflare/` was worse: its
  first `apply` would have created a **second** Access application on the docs
  hostname rather than adopting the hand-made one.

A queue in a file rots because nothing closes a bullet. An issue's state
changes when a pull request or a person closes it, and the list is correct
afterwards either way.

## Options considered

- **A "superseded" or "unsupported" banner** — a reader has to find the banner
  before the content misleads them, and `ORACLE_RUNNER.md` shows they don't.
- **An archive directory** — `docs/archive/` was 72 files its own README had to
  warn readers not to treat as policy.
- **Repair the dead thing** — the work plus a standing duty to keep green a
  path nobody walks. Chosen against for Codespaces: one session used it, and
  its Node 22 image could not run `pnpm install` against `engines.node >=24.15.0`.
- **Migrate the backlog items onto a board** — about 40 deferred items would
  have drowned a board meant for deciding what a fortnight contains.
- **A private planning board** — this was the home until publication. It then
  left the one category a sceptical reader most wants to see, what is known to
  be wrong, behind a login. Mirroring public items into Issues would mean two
  homes for one commitment.

## What it cost

- Operational knowledge went with some runbooks: Play Store publishing, Google
  sign-in setup and SES provisioning. Recover them from git history when
  needed; do not restore the files.
- An Oracle rebuild became a hand operation with no machine-checkable
  definition, and the docs Access gate exists only in the Cloudflare dashboard.
- The zero-install Codespaces path is gone. Evaluating the repo needs Node,
  pnpm and Docker locally.
- The queue is public, including what is broken and unfixed. Something
  irresponsible to publish goes to [SECURITY.md](../../SECURITY.md)'s private
  channel, not an issue.

## What it constrains

- **Delete, don't banner.** When a thing is retired, retire its runbook and its
  guard in the same change. A guard that outlives its premise makes dead code
  look load-bearing: an `/api/mobile` tree lived a month past its client that
  way.
- **No infrastructure module is committed before it has been applied and has a
  state file.** The one waiver, `infra/oracle-box/`, is recorded in
  [D-184](./D-184.md) and carries a banner that comes off on its first apply.
- **A development path comes back working or not at all.** It must be verified
  against the Node major in the `Dockerfile` and named in
  `docs/development/setup.md`. There is deliberately no guard that
  `.devcontainer/` stays gone. Recreating it is allowed; leaving one dormant is
  not.
- **An issue is a closable statement of work.** Its title is a sentence naming
  the problem from the user's side. It has a **Done when** line and a
  `p1`/`p2`/`p3` label set at the weekly triage. An undated idea is an issue;
  something settled is a decision record, not an issue.
  `pnpm issue:check` ([`scripts/issue-check.mjs`](../../scripts/issue-check.mjs),
  [`issue-check.test.ts`](../../apps/web/tests/config/issue-check.test.ts))
  checks a draft, and the `/issue` skill runs it before every filing. An issue
  filed in the browser is checked by nothing. That is deliberate: a bot would
  wrongly flag every outside bug report.
- **Nothing enforces "no queue file".** The rule is here and in `CLAUDE.md`. A
  guard on `TODO.md` would catch only that spelling.
- Decision records are the exception: they are rewritten in place as current
  policy ([D-202](./D-202.md)), not deleted when a part is reversed.

## How we got here

- **2026-08-08.** 100 queue-shaped documents were deleted: 6 root files, 11
  plans, 5 audits, the 72-file `docs/archive/` and 6 deployment docs. Open
  issues were closed, and the single home became the maintainer's private
  board. `POST_LAUNCH_BACKLOG.md`, last refreshed 2026-06-07, by then cited 11
  documentation paths deleted in the 2026-07-24 reorg. The board's own drift
  check counted `- [ ]` checkboxes, so it missed both large backlogs, which
  used plain bullets. 96 dangling references across 85 files were repaired, and
  `mkdocs.yml` lost 28 of its 30 redirects. About 440 references to
  pre-reorg paths were left in code comments.
- **2026-08-29.** `infra/oracle-runner/` and `infra/cloudflare/` were deleted,
  and `ORACLE_BOX_REBUILD.md` was transcribed from the running box. On
  2026-09-03 the Oracle box was given a module again, on condition it was
  applied first ([D-184](./D-184.md)).
- **Early September 2026 (undated).** `HETZNER_PLATFORM.md` (65k, never
  applied), `SELF_HOSTED_RUNNER.md` (never built), `ORACLE_RUNNER.md` and a
  root `vercel.json` were deleted. The same sweep found 13 `just` recipes
  calling things that did not exist, Supabase credentials still set as `ENV` in
  the `Dockerfile`, and release runbooks saying "there is no Actions escape
  hatch" after CI had moved to runners ([D-157](./D-157.md)). The
  `.devcontainer/` path, `pnpm dev:cloud` and the `allowedOrigins` branch it
  needed were deleted rather than repaired. `.nvmrc` moved from 24 to 26 in the
  same change.
- **2026-09-09.** On publication, the board moved into this repository's
  Issues. The no-file rule was unchanged.
