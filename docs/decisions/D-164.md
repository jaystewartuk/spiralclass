# D-164. The runbooks for infrastructure that was reversed are deleted, not banner-ed

**What changed.** Three deployment runbooks are deleted outright, along with the
last Vercel config file and every live reference that pointed at them:

| Deleted                                 | What it described                                              | Why it is not a description of anything                       |
| --------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------- |
| `docs/deployment/HETZNER_PLATFORM.md`   | 65k: audit + deploy-ready Tofu for a paid Hetzner platform box | Never applied. No Hetzner resource ever existed               |
| `docs/deployment/SELF_HOSTED_RUNNER.md` | A physical mini-PC runner                                      | Never built; ruled "off the table permanently" a month before |
| `docs/deployment/ORACLE_RUNNER.md`      | 36k: the Oracle A1 box as a GitHub Actions runner              | Deregistered twice; the box is LiveKit-only                   |
| `vercel.json`                           | Which branches Vercel auto-deploys                             | Vercel was torn down in [D-89](./D-89.md) Phase 5             |

**Why now.** The decision that put every workflow back on GitHub-hosted runners
already recorded the problem and did not fix it — its own closing list says
these files "still describe a runner role as live". A superseded banner was the
compromise, and `ORACLE_RUNNER.md` is the proof it does not work: it carried
four stacked banners above a **`Status: LIVE`** line that was false for seven
weeks. A reader
who trusts the heading before the banners gets the wrong answer, and a reader
who trusts the banners has read 36k to learn that none of it applies.

## The rule

> **A runbook for infrastructure that does not exist is deleted, not banner-ed.**
> The decision records are where a reversal lives; that is what they are for and
> they are append-only. A runbook is a description of how to operate something,
> so a runbook for nothing is not history — it is a wrong answer with a
> disclaimer on top.

The history is intact and is not being re-litigated:
[D-119](./D-119.md) → [D-129](./D-129.md) → [D-157](./D-157.md) →
[D-161](./D-161.md) → [D-162](./D-162.md), and before those, four moves between
GitHub-hosted runners, a free Oracle ARM box and a paid Hetzner pool whose
records were not published. The answer that survived all of it
is one line: **CI runs on `ubuntu-latest`, and nothing else.**

## What else was carrying a dead claim

The sweep that found those three found that the drift was not confined to docs.

**Broken commands the catalog still advertised.** `just --list` is described in
`CLAUDE.md` as the human-facing catalog of this repo's commands, and thirteen of
its recipes could not run. They invoked a deleted workspace, a build script, a
helper and six `pnpm` aliases — **none of which exists**. `mprocs.yaml`
likewise still opened a pane for it, so `just dev` started a failing process on
every launch.

**Dead credentials still in the image.** The `Dockerfile` set `SUPABASE_URL`,
`SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` as build-time `ENV` to
satisfy a Zod schema that dropped all three when D-89 decommissioned Supabase.
Its header also claimed the image was "not used by Vercel", counted eight
`NEXT_PUBLIC_*` build args where there are nine, and pointed at
`.github/workflows/../actions/fly-build-deploy` and `docs/ops/FLY_SPIKE.md` —
**two paths that no longer exist**.

**Two release runbooks describing the previous arrangement.**
`LOCAL_AUTOMATION.md` and `RELEASE_AND_STAGING.md` still said a promote runs the
full gate and deploys from the laptop under QEMU, and — the line that matters
most — that **"nothing can post that status"**
without a laptop and that **"there is no Actions escape hatch"**. D-157 and
D-161 falsified both: `gate.yml` posts `local-gate` on every PR, `heavy.yml`
runs the heavy tier on runners, and both deploys run on runners.
`RELEASE_AND_STAGING.md` also told the operator to unset a maintenance flag on
`-a spiralclass-preview`, **an app that does not exist** — the preview app is
`agendaprofe-preview`.

## What was deliberately NOT done

- **`docs/decisions/**` is untouched.** Every D-record keeps saying what it said,
  including the ones that decided things later reversed. `CLAUDE.md` leans on
  that history explicitly ("so the runner question isn't re-litigated").
- **`docs/deployment/oracle-runner-cloud-init.sh` is kept**, with its dangling
  reference repaired. [D-139](./D-139.md) decided to keep it deliberately, and
  reversing an explicit decision is not a sweep's call. It carries its own "do
  NOT run this" banner and `ORACLE_BOX_REBUILD.md` cites it as the thing not to
  use.
- **The dead notification transport is untouched.** Removing it is a functional
  change to the dispatcher, not documentation cleanup, and its credential stays
  declared for the same reason. **This is the largest known piece of dead code
  in the tree and it is still there.**
