# D-20. Class-content inputs are teacher-configured structured data seeded per discipline, not a platform curriculum library (2026-06-24)

**Status: Active, with one call reversed by [D-72](./D-72.md).** All four layers
shipped together. **D-72 narrowed the platform to language teaching**: the
"stays subject-agnostic" framing below no longer holds, `teachers.discipline` is
gone (replaced by `teachers.target_language`), and the music/math/generic seed
packs are removed. D-20's other calls all stand — no platform curriculum,
teacher-owned tags/levels as data rather than enums, additive pack seeding —
and they are what made the D-72 narrowing cheap. The full framing, the
"library per subject" trap this rejects, and the layer-by-layer design live in
`../../product/CLASS_CONTENT_INPUTS.md`.
Builds directly on [D-17](./D-17.md) (in-house AI class-content compose) and
follows the level model from
`../../product/LEVEL_MATERIALS_PLAN.md`.

**What was decided.** How a teacher configures _what a class should be about_ —
the thing she would otherwise type into a separate ChatGPT tab ("A2 student,
practice the past tense, she likes cooking, do a role-play"). Four calls:

1. **No platform-owned per-subject curriculum library.** We explicitly do **not**
   build and maintain a Spanish course, a music syllabus, a math curriculum,
   etc. That is a content-publishing business, it re-introduces the
   language-school lock-in the level table was designed to avoid, and the moat
   isn't canned content — it's the student context the platform already holds.

2. **Inputs are a teacher-owned, seedable structured layer (the level pattern,
   reused).** The pedagogical inputs become teacher-scoped rows seeded from a
   pack chosen by the teacher's discipline — exactly how `Level` auto-seeds
   CEFR. Language-flavored defaults are DATA (seed rows), not schema, so the
   platform stays subject-agnostic. **Spanish is the first pack**; English,
   another-language, music, math and a generic fallback ship alongside it.

3. **Four additive layers, no breaking changes.**
   - **L1 — student profile.** `teacher_students.interests` / `.goals`: the
     durable "who", set once, fed into every generation. Teacher-private (like
     `custom_price_note` / student notes): never in the student export.
   - **L2 — focus tags.** A teacher-scoped `focus_tags` taxonomy (grammar,
     vocabulary, skills, activities, themes), seeded per discipline. The teacher
     picks tags when generating; the labels seed the prompt.
   - **L3 — discipline.** A soft `teachers.discipline` code that _selects the
     seed pack_. A label, **not** an enum that gates logic.
   - **L4 — reusable native content.** `library_materials.body` lets a lesson
     (typed or AI-drafted) be saved once at a level and assigned to many
     students through the existing notebook — distribution, not a new system.

4. **Authoring gated Pro; viewing free; topic now optional.** The focus-tag
   picker and save-to-library run through the same `gateProFeature("class_content")`
   path as D-17. Students view native content free. Free-text topic is optional
   once a focus tag carries the intent (the action requires at least one).

**Why.** The free-text topic alone threw away context an external chatbot can't
keep (level, goals, interests, what's covered) and made the teacher re-type the
same setup every class. Structuring those inputs is the differentiator D-17
identified, made real. The seed-pack approach delivers the "start with Spanish"
benefit the question asked for **without** committing the platform to authoring
and maintaining curricula per subject — the language defaults are a few rows of
data, and a music or math teacher reuses the same tables with a different pack.

**What was affected.** Additive migration `20260624120000_class_content_inputs`
(`teachers.discipline`; `teacher_students.interests/goals`; `focus_tags` table +
RLS; `library_materials.body/content_source`). New libs `src/lib/disciplines.ts`
and `src/lib/focus-tags.ts`. Extended `lib/class-content/prompt.ts`, the compose
action, the class-content panel, the student-detail + account-settings pages,
the library action + surfaces, the `@spiralclass/shared` `LibraryEntry`
contract, and the student data export. Not a Tier-2 path itself (no payment /
auth / booking-state logic) — but it touches `prisma/**`, so it shipped
`pnpm verify:local` + `git push --no-verify` per the Tier-2 rule for schema changes.

**Follow-up shipped 2026-07-03: teacher-editable focus tags.** No schema
change — `FocusTag.position`/`.archived` already existed for this. Added
`saveFocusTagsForTeacher()` in `src/lib/focus-tags.ts` (Pro-gated like every
other authoring mutation here); web action `app/actions/focus-tags.ts` +
`/settings/focus-tags`. `category` is editable free text too, so a teacher isn't
capped at the seed pack's five groupings.

**Unresolved risks.**

- **Discipline change is additive only.** Switching discipline seeds the new
  pack but never removes the old one's tags (they can be archived). Acceptable
  for v1 — a teacher can now archive stale-pack tags herself via the
  teacher-editable focus-tag screen (shipped 2026-07-03, see below); levels
  are still seed-only.
- **Focus-tag labels aren't translated** (like `Level.label`) — they're written
  in the pack's natural metalanguage.
