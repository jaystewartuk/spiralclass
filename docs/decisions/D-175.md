# D-175. Tenant isolation is checked by the application twice — a source parser at the gate and a Prisma extension at runtime — not by Postgres row-level security

`apps/web/scripts/tenancy-guard.mjs` parses every Prisma call in `apps/web/src/`
and reports each query against a model carrying `teacherId` that does not
constrain itself to one tenant; `apps/web/tests/authz/tenancy-guard.test.ts`
runs it in the fast tier as a ratchet against
`apps/web/scripts/tenancy-guard.baseline.json` (a file's count may shrink, never
grow, and a file with no entry must stay clean). At runtime a query-only Prisma
client extension (`apps/web/src/lib/tenancy/`) compares each query's arguments
with the tenant the auth gate recorded for the request, and reports or throws
when a query names a different one.

## Why

There is no row-level security: it left with Supabase ([D-70](./D-70.md)), and
the `where teacherId = ?` on every query is the only tenant isolation
([data-model.md](../architecture/data-model.md)). Until this record, the thing
enforcing that was people reading diffs. The scanner's first run found **264
unscoped queries in 112 files**, out of 922 queries against the 58 models that
carry `teacherId`. Once the repository was public, an unscoped query became
findable by anyone with a browser.

The two halves answer different questions. The parser proves a query **names**
a tenant, over the whole tree, including code no test runs. It cannot prove the
tenant is the **right** one: an id from a URL, a form field or a webhook can
reach a flawless `where` and return another teacher's rows (an IDOR). The
tenant a request is entitled to is known once, at the auth gate, so the runtime
half carries it from there — `attachActorToObservability` in
[`lib/auth.ts`](../../apps/web/src/lib/auth.ts) calls `enterTeacherScope` and
the value rides an `AsyncLocalStorage` context — to the one place that sees
every query.

## Options considered

- **Postgres row-level security.** Still the strongest answer. For one process
  and one connection pool, an incomplete policy set is the same bug as a
  missing `where` and is invisible from the application code. It needs a role
  split, `FORCE ROW LEVEL SECURITY` and per-transaction `SET LOCAL` through a
  transaction-mode pooler. That work is filed as
  [#58](https://github.com/jaystewartuk/spiralclass/issues/58) (role split),
  [#59](https://github.com/jaystewartuk/spiralclass/issues/59) (`SET LOCAL`),
  [#60](https://github.com/jaystewartuk/spiralclass/issues/60) (the
  cross-tenant inventory, which should come first in substance) and
  [#61](https://github.com/jaystewartuk/spiralclass/issues/61) (policies). The
  runtime context is where a `SET LOCAL` value would come from, which is why
  the tenant is a context and not a parameter.
- **A `grep` for `teacherId`.** Five shapes contain the string and do not
  constrain the query: `teacherId: undefined` (no filter), `teacherId: null`,
  `teacherId: t ?? undefined`, an `OR` with another branch, and
  `{ not: t }`. The scanner reports them as `vacuous` or `negated`, and the
  guard test asserts all five.
- **Scoping all 264 in one change.** A big-bang edit of a live tree is a worse
  change than the problem; the ratchet stops new ones without waiting for a
  cleanup.
- **An ESLint rule beside the ratchet.** Deferred: a second implementation of
  the same judgement drifts. Worth adding once the baseline is small.
- **Enforcing at runtime in production from day one.** Rejected. The extension
  sits in front of every query on live payment rails, a false positive is a
  teacher who cannot take a booking, and `TeacherShareGroup` lets a
  teacher-scoped request legitimately touch another tenant's material.
  Production reports to Sentry; `TENANCY_GUARD=enforce` is a decision to take
  on the reports.
- **Re-deriving "names a tenant at all" at runtime too.** A restatement of the
  parser; the shared vocabulary is asserted equal in
  [`tests/tenancy/guard.test.ts`](../../apps/web/tests/tenancy/guard.test.ts)
  instead.

## What it cost

- The baseline is a list of known leaks-in-waiting, not an audit. 61 of the
  first 264 were `opaque` (a `where` passed as a variable, spread or return
  value), which the parser counts as violations rather than guessing. 43 were
  the admin console, which reads across tenants by design
  ([D-25](./D-25.md)); 37 in `app/actions/`, 25 in `lib/notifications/`, 10 in
  `lib/payments/`. Working it down is
  [#62](https://github.com/jaystewartuk/spiralclass/issues/62).
- `derived` scope (`where: { bookingId }` on a child of `Booking`) is accepted
  on trust: the parser cannot follow the id to a tenant check. Treating it as a
  violation would have roughly tripled the baseline.
- Raw SQL (`$queryRaw`) is invisible to both halves.
- At runtime only the teacher gate is wired. The student portal, admin console,
  webhooks, Inngest jobs and the seed run with no scope, and the guard is inert
  for them; the student axis is
  [#63](https://github.com/jaystewartuk/spiralclass/issues/63). In production
  it reports and prevents nothing.
- An extension in front of every query reopened one settled question: the
  public demo was made a rendered fixture partly because there was "no Prisma
  client extension, so there is no chokepoint" ([D-125](./D-125.md)). That
  blocker went away with this extension;
  [#64](https://github.com/jaystewartuk/spiralclass/issues/64) reopened the
  question, and on 2026-10-14 the fixture decision was kept on its other
  ground — a demo account would still need a sign-in that proves no identity.
  The extension refuses no writes, and making it do so would need a decision of
  its own.

## What it constrains

- **Never regenerate the baseline to turn a red check green.** Regenerate after
  scoping a surface, never instead of scoping one — the rule
  `scripts/check-leaks.baseline.json` carries for the same reason.
- **The tenant-model list is derived from `schema.prisma`.** A new model with a
  `teacherId` column is covered with no edit; do not replace the derivation
  with a hand-written list.
- **A cross-tenant query says why.** `// tenancy-exempt: <reason>` at the call
  site, and the guard test fails a reason under four words. At runtime the twin
  is `runCrossTenant("<reason>", …)` in `lib/tenancy/context.ts`.
- **The extension inspects arguments and never rewrites them.** It calls
  `query(args)` with what it was given, so a bug can change what is logged, or
  in `enforce` whether a call happens, never what the database is asked.
  `lib/prisma.ts` casts the extended client back to `PrismaClient`; that is
  sound only while the extension has no `result`, `model` or `client`
  component, and
  [`tests/tenancy/client-surface.test.ts`](../../apps/web/tests/tenancy/client-surface.test.ts)
  notices if one appears.
- **Scope helpers await inside the scope.** A `PrismaPromise` does nothing
  until awaited, so `storage.run(scope, fn)` returning an unawaited query exits
  the scope first and the query runs unscoped — a silent hole that looks clean.
  [`tests/tenancy/interception.test.ts`](../../apps/web/tests/tenancy/interception.test.ts)
  fails if the helpers are simplified back.
- Neither half proves the **right** tenant is named by an unscoped code path no
  request exercises. Authorization stays the auth gates' job
  (`requireOnboardedTeacher`, `requireApiOnboardedTeacher`).
- Reversing this means arguing that review alone is enough on a repository
  anyone can read, or landing RLS through the issues above.

## How we got here

- **Until July 2026:** Supabase RLS policies existed beside application
  scoping. The move off Supabase removed them ([D-70](./D-70.md)), and
  `data-model.md` wrote the consequence down as the largest security assumption
  in the system.
- **For publication (the record gives no date):** the parser and ratchet
  landed. First run:
  264 unscoped queries in 112 files, 922 queries against 58 tenant models. The
  pre-existing check, `tests/authz/teacher-data-isolation.integration.test.ts`,
  seeds two tenants for four hand-picked accessors; it stays, and says nothing
  about a fifth.
- **Shortly after:** the runtime extension. Its first test, written to prove
  interception happens, failed against a real database connection error and
  exposed the unawaited-promise hole above before it shipped.
- **2026-10-16:** the baseline holds 260 queries in 108 files (summed from
  `tenancy-guard.baseline.json`), and four call sites in `apps/web/src` carry a
  `// tenancy-exempt:` reason. `runCrossTenant` and `runInTeacherScope` have no
  caller outside `lib/tenancy/` and its tests.
