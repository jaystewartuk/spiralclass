# D-139. Delete the two OpenTofu modules that were never applied

> [!IMPORTANT]
> **The accepted cost below was reversed on 2026-09-03 by
> [D-150](./D-150.md), for `infra/oracle-runner` only.** The Oracle box gets an
> OpenTofu definition again — but under a condition that is this decision's own
> reasoning restated rather than dropped: **nothing is committed until it has
> been applied and a state file exists.** The reasoning here is untouched and
> still binds; what changes is that the module stops being a claim and starts
> being applied, which was never true of the one deleted here.
>
> **`infra/cloudflare`'s deletion is NOT reversed** and stands on the separate,
> stronger ground given below — a first apply would have created a second
> Access application on the same hostname rather than adopting the existing
> one.

**What changed.** `infra/oracle-runner/` and `infra/cloudflare/` are deleted.
Neither was ever applied, neither had a state file, and both described
infrastructure that in reality was built and is maintained by hand.
`infra/oracle-runner/` is replaced by
[`docs/deployment/ORACLE_BOX_REBUILD.md`](../deployment/ORACLE_BOX_REBUILD.md),
transcribed from the running box on 2026-08-29 rather than from the module's
own templates. `infra/cloudflare/`'s knowledge — the Access application that
gates `docs.spiralclass.com` and `docs.agendaprofe.com` — stays in
[`DOCS_SITE.md`](../deployment/DOCS_SITE.md), where it was already recorded.

**Why it likely changed.** _This one is not reverse-engineered: it is a
deliberate reversal by judgement, and no new evidence prompted it._ Nothing
about either module stopped working, because neither ever worked — that is the
point. A module that has never been applied does not describe infrastructure,
it asserts a state nobody has reconciled, and the assertion is confidently
wrong in a file that reads as authoritative.

The cost stopped being hypothetical on 2026-08-29. `infra/oracle-runner/`'s
README claimed that "a `tofu apply`/rebuild today reproduces the box as-is". A
session read that sentence and twice proposed applying the module to fix a
missing TLS certificate. Applying it would have edited a template that changes
nothing while production stayed broken; the real fix was a hand edit of
`/home/ubuntu/oracle-livekit-production/Caddyfile` over Tailscale SSH followed
by `docker exec livekit-caddy caddy reload`. A claim that misled a reader who
had just read the whole repository will mislead a human at 2am with the box
down.

`infra/cloudflare/` carried a sharper version of the same fault. Its Access
application was created by hand in the dashboard, so a first `apply` would not
have adopted the existing application — it would have created a **second** one
on the same hostname. Its `variables.tf` has a single `domain` and cannot
express the `self_hosted_domains` list that actually protects both hostnames,
so the module could not have produced the live configuration even in
principle.

This follows [D-129](./D-129.md), which deleted `binding.mjs`, `drift.mjs`,
two of that repository's own check scripts for not doing what they claimed, and kept
`status.mjs` on the distinction that it _generates_ rather than _asserts_.
Both modules here fall on the wrong side of that same line. Keeping them also
contradicts what that separate tool exists to do, which is fail CI when a
context-file claim goes false.

**What was affected.** `infra/oracle-runner/` (`main.tf`, `variables.tf`,
`outputs.tf`, `cloud-init.yaml.tftpl`, `terraform.tfvars.example`,
`.terraform.lock.hcl`, `services/`) and `infra/cloudflare/` (`main.tf`,
`variables.tf`, `outputs.tf`, `terraform.tfvars.example`,
`.terraform.lock.hcl`) are gone, along with their READMEs.
[`infra/README.md`](../../infra/README.md)'s module table and its shared-backend
prose shrink accordingly — both modules used the shared `backend.hcl`, so the
list of modules sharing that backend changes.

The hand scripts that are genuinely used are **kept**:
`oracle-livekit-cloud-init.sh`, `oracle-cloudshell-provision.sh`,
`oracle-livekit-only-cleanup.sh` and `oracle-launch.sh`.
`oracle-runner-cloud-init.sh` is also kept — it is explicitly marked
historical and instructs the reader not to run it, so it makes no false claim
about current state.

Live references that told a reader to run something now deleted have been
repointed at the runbook — most importantly
[`ORACLE_LIVEKIT_PRODUCTION.md`](../deployment/ORACLE_LIVEKIT_PRODUCTION.md),
whose "Deploying" and "Disaster recovery" sections both carried a
`cd infra/oracle-runner && tofu apply` that would have been followed by
someone with a box down.

Twelve decisions mention the module. Because this log is current policy rather
than history, none of their reasoning is rewritten. **[D-134](./D-134.md)
carries a dated pointer to this decision**, because its
`cloudflare_dns_record.livekit` no longer exists; the module's own design record
carried one too, and was not published. Every other mention is incidental and is
left exactly as it is, as deliberate historical record.

**Unresolved risks.** **A rebuild of the Oracle box is now a hand operation
with no machine-checkable definition.** That is the real cost being accepted,
and it is accepted knowingly: the definition that existed was not checkable
either, since nothing ever ran it, and it was wrong in ways nobody could see.
What is genuinely lost is the _possibility_ of making it true later by
importing existing infrastructure into state — that path is now a rewrite
rather than an import.

`ORACLE_BOX_REBUILD.md` is prose, so nothing fails when the box drifts away
from it. It is dated and says what was observed and when, but it will rot
unless it is edited in the same session as any change to the box.

**The shape of the box now lives in one place and it is not version
controlled.** The `.bak` files in `/home/ubuntu/oracle-livekit-production/`
are the closest thing to a change history the machine has.

Deleting `infra/cloudflare/` leaves the Access application defined only in the
Cloudflare dashboard. Nothing in this repository will notice if the gate on
`docs.spiralclass.com` is removed by hand.
