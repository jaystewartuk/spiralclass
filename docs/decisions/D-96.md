# D-96. Entitlements audit: keep code-defined plans + the single shared resolver, close enforcement/UX gaps rather than rearchitect (2026-07-20)

**Status: Active.**

**What changed.** A full-codebase audit of subscription/entitlement handling
(front end, backend, admin), requested to find inconsistent enforcement, UI
that silently fails, and to decide the right long-term architecture. The full
audit report, feature inventory, edge-case review, and rationale live in
`docs/engineering/ENTITLEMENTS_AUDIT.md` — this
entry is the short decision-log pointer.

**The decision: no architecture change.** The existing model — one pure,
clock-aware resolver (`entitlementsFor()` in
`packages/shared/src/subscriptions-entitlements.ts`) returning a capability
object, imported identically by web SSR, the API responses, and every
backend gate — was already correct and had **zero duplicated or drifted
reimplementations** anywhere in the codebase. No database-editable entitlement
matrix was added; plans/caps/capabilities stay code-defined constants, gated
behind the same PR/CI process as any other change. See the audit doc §2 for
the full "why not a matrix" reasoning.

**What was actually wrong** was gaps in _applying_ the architecture, not the
architecture itself:

1. `gateAddStudent` (`apps/web/src/lib/subscriptions/enforce.ts:33-47`) — the
   Free plan's 3-active-student cap gate — was fully implemented and
   unit-tested but **never called** from either create-student path (web
   `createStudentAction` and its API sibling). The cap was unenforced
   everywhere. Now wired into both.
2. A `saveCustomPrice()` caller had no `catch` — a Free teacher hitting the
   server's 402 saw the spinner just stop with no explanation. Fixed to toast
   the real error, matching the file's existing `saveContact()` pattern.
3. Two routes returned an internal reason code as the user-facing
   `message` (`errorResponse(402, "plan-limit", "custom_price")` →
   literally showed **"templates:1"** for the template-cap case). Both now
   return `upgradeNudge(...)`, the same localized message the server action
   already used.
4. **No screen anywhere proactively gated a Pro-only control** — every gate
   was reactive (submit, then fail). This is why "Generate Class Materials
   with AI" was visible and clickable for Free teachers: the control's only
   gate was `hasAnthropicCreds()` (are AI creds configured at all), never the
   teacher's own plan. The _backend_ gate (`gateProFeature(…,
"class_content")`) was already correct — a Free teacher got a real 403, not
   a crash or a leak — but only after clicking, with no upfront lock/badge/
   upgrade prompt. Fixed by threading a new `isPro` field (computed
   server-side via `entitlementsFor()`) into the class-content/library API
   responses and through to `MaterialForm` on both platforms, which now
   disable Generate/Edit-with-AI and show an explanation + upgrade CTA before
   the teacher can even attempt the action. The server gate remains
   authoritative; this is UX only.

**What was affected.** `apps/web/src/app/actions/teacher-students.ts`,
`apps/web/src/components/materials/material-form.tsx` (+ its three
callers: `add-material-sheet.tsx`, `content-edit-form.tsx`,
`dashboard/materials/page.tsx`, `classes/[bookingId]/content/edit/page.tsx`),
a new `apps/web/src/components/subscriptions/pro-lock-note.tsx`,
`packages/shared/src/api.ts` (new `isPro` field on `TeacherClassContent` /
`TeacherLibrary`), `packages/shared/src/i18n/catalog.ts` (new copy, all three
locales), `apps/web/src/app/admin/teachers/[id]/page.tsx` (read-only resolved-
entitlements debugging view — no new write path), and
`docs/product/SUBSCRIPTIONS.md` (corrected a stale `canUseWhatsApp` field
reference and the `gateAddStudent` wiring claim). Tests added in both
`apps/web/tests/` — see the audit doc §9.

**Unresolved risks / deliberately out of scope this pass** — see the audit
doc §10: podcast generation still has the old reactive-only pattern (same
fix shape, not applied yet); no full interaction test exists for
`MaterialForm`'s new disabled state beyond SSR string checks; a full
screen-by-screen proactive-gating pass (custom price, templates) was not done
— only the named AI-authoring surface was; a future school/enterprise plan
would need a seat-based concept this model doesn't have yet.
