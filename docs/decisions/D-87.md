# D-87. Customer-facing Anthropic defaults split by call shape — four short surfaces to Haiku 4.5 (5× cheaper), class-content compose to Sonnet 5 (~40% cheaper), because `effort` 400s on Haiku (2026-07-19)

**Status: Active.** Supersedes **the model choice, and nothing else**, in three
earlier decisions that each named `claude-opus-4-8`:

- **[D-17](./D-17.md)** — "AI compose = the platform `@anthropic-ai/sdk`,
  `claude-opus-4-8`". Native structured content over PDFs, in-house authoring,
  the Pro gate, `hasAnthropicCreds()` degradation, and
  Markdown-with-`rehype-raw`-off are untouched and still current policy.
- **[D-19](./D-19.md)** — categorisation "from Claude (`claude-opus-4-8`)".
  The buy-vs-build split, teacher-in-the-loop validation, and
  derive-then-discard audio are unchanged.
- **[D-73](./D-73.md)** — the intro-coach call's model. Everything else about
  Layers 1–3 stands.

Each of those three carries a superseded-in-part pointer back here.

**What changed.** All five customer-facing Anthropic model defaults were
`claude-opus-4-8`. They now split **by call shape**, not uniformly:

| Constant                    | File                               | Surface                                         | New default           |
| --------------------------- | ---------------------------------- | ----------------------------------------------- | --------------------- |
| `anthropicModel()` fallback | `src/lib/env.ts`                   | Class-content / library AI compose (D-17, D-69) | **`claude-sonnet-5`** |
| `SUMMARY_MODEL`             | `src/lib/lesson-notes/summary.ts`  | Post-class lesson summary (D-15)                | `claude-haiku-4-5`    |
| `INSIGHTS_MODEL`            | `src/lib/lesson-notes/insights.ts` | Structured lesson insights (D-19)               | `claude-haiku-4-5`    |
| `BRIEF_MODEL`               | `src/lib/lesson-notes/brief.ts`    | AI pre-class brief (D-19, Phase F)              | `claude-haiku-4-5`    |
| `INTRO_COACH_MODEL`         | `src/lib/intro-video/coach.ts`     | Intro-video coaching feedback (D-73, Layer 3)   | `claude-haiku-4-5`    |

`captionTranslationModel()` is **not** part of this change — live-caption
translation was already `claude-haiku-4-5` on its own hot-path reasoning (D-27),
and keeps its separate `CAPTION_TRANSLATION_MODEL` override.

**Why the split.** This decision was first written and committed as a _blanket_
move of all five to `claude-haiku-4-5`, on cost alone. That version was wrong
and was revised before it reached production. Two reasons, in order of
severity:

1. **It would have 400'd every material generation** — the hard blocker; see
   the named finding below.
2. Class-content compose is not the same shape of call as the other four. It is
   long-form, customer-visible pedagogical content on a paid Pro feature; it is
   the **only** one of the five that streams, the **only** one at `max_tokens:
4096` (the others are 1024–2048), and the **only** one passing
   `output_config.effort`. The other four are short, structured calls — two of
   them forced-tool-call shaped — where Haiku is both safe and appropriate.

### Named finding: `effort` is not supported on Haiku 4.5 — a blanket switch would have 400'd every material generation

Every call site in `apps/web/src/lib/ai/anthropic.ts` — `generateMaterial`,
`refineMaterial`, `generatePodcastScript`, `generateMaterialStream` — passes
`output_config: { effort: "medium" }`, and every one of them resolves its model
through `anthropicModel()`. The Anthropic API **rejects `effort` with a 400 on
pre-4.6 models**, including `claude-haiku-4-5` (it is supported on Opus 4.5 at
low/medium/high, and on 4.6+ models generally). Pointing `anthropicModel()` at
Haiku therefore breaks material generation outright — not a quality regression,
a hard failure on every call.

**This exact failure already happened once, on another surface.**
`apps/web/src/lib/captions/translate.ts` carries a standing comment explaining
why its own call must _not_ set `output_config.effort`: the caption model is
Haiku 4.5, the rejected request threw for **every** utterance, the route
returned 502, and no caption line was ever published — the teacher's Subtitles
toggle silently showed nothing. So the constraint was already known and
documented in this repo, on a Haiku call that had `effort` removed. D-87's
blanket version would have reintroduced the identical bug from the opposite
direction: instead of adding `effort` to a Haiku call, moving an
`effort`-passing call to Haiku. Treat that comment and this finding as one rule:
**`effort` and Haiku never coexist.**

**Why it wasn't caught.** Preview still runs the pre-D-87 backend, so on-device
testing exercised the old model and the change looked clean. No test covered
the model↔parameter compatibility relationship, and nothing in the type system
expresses it: `model` is a plain `string` and `output_config` is validated by
the API, not the SDK. The four constants that _are_ safe on Haiku are safe
precisely because they pass no `effort` — an invariant that lived nowhere but
in the call sites themselves.

**It is now test-guarded.** `tests/lib/env.test.ts` asserts `anthropicModel()`'s
default is a member of an explicit effort-capable model set, with a comment
naming the constraint and stating what to do if `effort` is ever removed from
the call sites. Each of the four Haiku constants carries a comment explaining
why Haiku is fine _there_ and what to change if `effort` is ever added.

**Corrected cost math.** Published Anthropic pricing:

| Model                                       | Input / 1M                                        | Output / 1M               |
| ------------------------------------------- | ------------------------------------------------- | ------------------------- |
| `claude-opus-4-8` (prior default, all five) | $5.00                                             | $25.00                    |
| `claude-sonnet-5` (compose)                 | $3.00 — **$2.00 introductory through 2026-08-31** | $15.00 — **$10.00 intro** |
| `claude-haiku-4-5` (the other four)         | $1.00                                             | $5.00                     |

- **Class-content compose: Opus 4.8 → Sonnet 5 is ~40% cheaper** on both axes at
  standard rates, **~60% cheaper** at introductory pricing. Against the
  worst-case envelope `docs/deployment/COST_PLAYBOOK.md` models, per-generation worst
  case falls from ≈$0.15 to ≈$0.07 (≈$0.045 intro), and a single Pro teacher at
  the full `CLASS_CONTENT_AI_MONTHLY_CAP` of 100 generations falls from
  ≈$15/month to ≈$7/month (≈$4.50 intro), scaling linearly per Pro teacher.
- **The other four: Opus 4.8 → Haiku 4.5 is a flat 5× cut** on both axes. None
  of them is capped the way class content is (see risks), so this is where the
  uncapped exposure shrank most.

Sonnet 5 is the right landing spot for compose rather than a token compromise:
it is the best speed/intelligence combination in its tier at near-Opus quality,
and it supports the full `low`→`max` effort range, so the existing
`effort: "medium"` keeps working unchanged with no call-site edit.

**The accepted trade-off.** Still real, but smaller and better targeted than the
blanket version claimed. The four short surfaces move to a materially weaker
model: expect flatter lesson summaries, less well-evidenced insight
categorisation, thinner pre-class briefs, and less specific intro-video
feedback. All four are Pro-gated — teachers pay 199 MXN/month (or the
Founding/annual equivalent) for the tier that unlocks them — so the regression
lands on paying customers, not a free tier. Nothing breaks; the output gets
weaker. The long-form surface where a quality drop would be most visible —
class-content compose, where the teacher reads and edits a full draft — is the
one that stayed a tier up, which is the substance of the revision.

**What was affected.** `apps/web/src/lib/env.ts` (the `anthropicModel()`
fallback, the `ANTHROPIC_MODEL` schema comment, and the
`captionTranslationModel()` comment), `apps/web/src/lib/lesson-notes/{summary,
insights,brief}.ts`, `apps/web/src/lib/intro-video/coach.ts` (each with a
why-Haiku-is-safe-here comment naming the `effort` constraint). Tests:
`tests/lesson-notes/summary.test.ts` (the `SUMMARY_MODEL` assertion, retargeted
to Haiku rather than weakened), an `anthropicModel` block in
`tests/lib/env.test.ts` — the fallback previously had **no** default coverage at
all — now covering the Sonnet 5 default plus the effort-capability invariant,
and the model-provenance fixtures in
`tests/lesson-notes/{brief-service,notes.integration}.test.ts` +
`tests/actions/lesson-notes-action.test.ts`. Docs: `docs/deployment/COST_PLAYBOOK.md`,
`docs/engineering/lesson-insights.md`, `docs/engineering/live-notes-panel.md`,
`config/env/preview.runtime.env`, `apps/web/prisma/schema.prisma`'s
example-value comment, and superseded-in-part pointers on D-17/D-19/D-73.

**No production change until redeploy, and no env change is required.** These
are code-level defaults; preview picks them up on the next `main` deploy, and
production on the next promote.

**Unresolved risks.**

- **The escape hatch is asymmetric — call this out loudly.** `ANTHROPIC_MODEL`
  still overrides `anthropicModel()`, so class-content/library compose can be
  put back on Opus with an env change and no deploy. The **other four constants
  are hardcoded and ignore `ANTHROPIC_MODEL` entirely** — reverting lesson
  summaries, insights, briefs, or intro-video coaching needs a code change and a
  full promote. That asymmetry is pre-existing (D-15/D-19/D-73 each hardcoded
  their own constant), but D-87 is the first decision where it actually costs
  something, because it's now the difference between a one-line rollback and a
  release. It also now has a second edge: **an `ANTHROPIC_MODEL` override is
  itself constrained** — setting it to a pre-4.6 model 400s every compose call,
  and env values are not covered by the guard test (which pins the _default_
  only). **Follow-up:** route all five through one resolver that also validates
  effort-capability, so a single env var can move the whole platform's model
  tier without re-opening this trap.
- **Quality regression is unmeasured.** There is no eval set, golden-output
  corpus, or A/B for any of these five surfaces, so "materially weaker" is a
  reasoned expectation, not a measured delta — a regression will surface as
  teacher complaints rather than a dashboard. The per-surface split _is_ the
  mitigation that the blanket version would have needed; if it still bites, the
  next step is moving one of the four short surfaces back up rather than
  reverting wholesale.
- **Only class content is capped.** `CLASS_CONTENT_AI_MONTHLY_CAP` bounds
  per-teacher spend for compose only; lesson summaries, insights, briefs, and
  intro-video coaching have no equivalent monthly ceiling. The 5× cut on those
  four lowers the blast radius of that gap but does not close it.
- **Sonnet 5's introductory pricing expires 2026-08-31.** Compose cost rises
  ~50% ($2/$10 → $3/$15 per 1M) on that date with no code change and no
  deploy — a silent cost step. Revisit the COST_PLAYBOOK envelope then, and
  re-evaluate whether compose still warrants the Sonnet tier at standard rates.
- **Haiku 4.5's context window is 200K, not 1M.** Opus 4.8 carried a 1M-token
  window; Sonnet 5 also carries 1M, so compose is unaffected. For the four
  Haiku surfaces the headroom is now 5× smaller. None of those prompts comes
  close today (the largest is a lesson transcript plus live notes), but a future
  change that feeds a long transcript into one of them could hit a ceiling that
  did not previously exist.
- **Prompts were tuned against Opus and were not re-tuned.** Anthropic's own
  migration guidance is that prompts carried across model tiers often want
  re-tuning; nothing here was re-worked, so some of the expected quality drop on
  the four Haiku surfaces may be recoverable with prompt work rather than by
  paying for a bigger model.
