# D-81. French as a third UI language, on a registry-driven, add-a-language-in-two-steps i18n architecture

**What changed.** French (`fr`) is now a fully supported UI language alongside
`es-MX` and `en`, and the localization system was reshaped so future languages
are additive rather than a cross-cutting edit.

- **One registry, `packages/shared/src/i18n/locales.ts`.** `LOCALES` is the
  single source of truth (`tag`, `languageCode`, `label` endonym, `englishName`,
  Accept-Language `match`). `AppLocale`, `LanguageCode`, the Accept-Language
  matcher, the outbound-copy bridge, and the SEO `inLanguage` list all derive
  from it. Adding a language is **two steps**: append a row here, add its catalog
  block. The catalog's compile-time completeness guard then names every key the
  new locale is missing — a half-translated locale can't build.
- **Complete French catalog.** All 3,589 keys in the shared string catalog
  (`packages/shared/src/i18n/catalog.ts`) are translated. `nav.ts` (primary
  navigation labels/descriptions) and the shorter exhaustive dictionaries
  (`OG_LOCALE`, the student web nav, the two web error screens) are translated
  too, so the day-to-day UI is fully French.
- **"System Default" preference + manual override.** A new
  `LocalePreference = "system" | AppLocale` models the choice. On first launch
  the app follows the device/browser language (unchanged auto-detection, now
  registry-driven for all three locales); the user can override to a specific
  language or back to _System Default_, which keeps tracking the device live.
  `resolveLocale(preference, detected)` collapses the two into the locale to
  render. The preference is stored in the `locale` cookie (the `"system"`
  sentinel falls through to Accept-Language).
- **Generic language picker, generated from the registry.** The old ES/EN pill
  toggle in Settings is replaced by a `LanguageSelect` rendering
  _System Default · English · Español ·
  Français_ straight from `localeOptions()`. It never hardcodes a language;
  registering a locale adds its row automatically. Switching updates the UI live
  (React state / server-action revalidate) with no app restart. The compact
  `LocaleToggle` pill switcher stays on public surfaces (auth/help/legal), now
  writing the same preference.

**Why it likely changed.** The product was bilingual with the two-locale pair
threaded through many call sites; adding a language needed a scalable spine and
a real third language to prove it. French was the target, and "follow the
device unless the user says otherwise" is the expected behaviour the old
toggle-only model didn't express.

**What was affected.** Shared: `locales.ts` (registry + preference helpers +
`localeOptions`), `catalog.ts` (fr block, `settings.language.system`, removed
the unused `common.locale.*` keys). Web: `lib/i18n.ts`
(`getLocalePreference`), `actions/locale.ts` (accepts `"system"`, mirrors the
_resolved_ locale to the DB row), new `LanguagePicker`/`LanguageSelect`
replacing the footer/nav toggle. Tests updated across all three to loop over the
registry instead of a hardcoded pair, plus new preference/picker coverage.

**Unresolved risks.**

- **English fallback for long-form + legal copy.** Help docs (`content/*.ts`)
  are translated, but the Terms/Privacy legal pages and the outbound
  email/push templates deliberately fall back to English for `fr`
  (legal text shouldn't be machine-translated; email copy is authored es/en
  only). French users see English there until those are separately translated —
  acceptable per "fall back to English when a translation is missing," but worth
  revisiting before marketing French heavily.
- **`nav.ts` and a few small dictionaries stay exhaustive** (`Record<AppLocale,
string>`), so a future language must fill them in — the compiler flags exactly
  where, but it's not zero-effort like the catalog. If the language count grows,
  migrating nav labels into the catalog would make it truly two-step everywhere.
- **Booking/payment status endonyms** got a light-touch French pass; a native
  reviewer should sanity-check gender agreement (e.g. "Programmé(e)") before a
  French launch.
