# D-189. The lesson transcript is the caption text the browsers already recognise, kept with consent; no audio is captured for it

**Status.** Active · partly reverses [D-187](./D-187.md) (transcription goes
back on; recording stays off) · amends [D-185](./D-185.md) (caption lines are
no longer always ephemeral) · changes the capture half of
[D-19](./D-19.md)'s "derive-then-discard" (there is nothing to discard).
D-187's reasoning about the box is not reversed: it still cannot carry egress,
and this is how insights run without any.

**What changed.** `LESSON_INSIGHTS_TRANSCRIPTION_ENABLED` is on again in both
runtime env files, and what it now enables is a transcript written by the
participants' browsers. While the teacher has live captions on, the browser
that recognised a finished utterance (its own speaker's, the other person's
from the call audio, or the Deepgram stream for a phone — the D-185
assignment, unchanged) also POSTs the source text to
`/api/captions/transcript`. The server re-checks the caption access and that
the class's session says `transcriptCapture` — the flag, and the pairing's
recorded insights consent ([D-22](./D-22.md)), the guardian's for a minor and
the buyer's confirmation for a class for two ([D-188](./D-188.md)) — then
appends the line to the booking's `LessonTranscript` in one atomic
`INSERT … ON CONFLICT` statement, provider `browser-live`. When the LiveKit
`room_finished` webhook arrives, or failing that when an Inngest job wakes
after the scheduled end plus a grace period, the row is rebased to a 0-based
timeline, marked `browser`, and `lesson.transcript.ready` fires. Phase C
(insights), the profile, the brief and the vocabulary queue run exactly as
before, from the same row and the same shape. Both participants see a
"Transcript kept for learning insights" pill while it happens.

The egress capture behind the same flag (`maybeStartLessonAudioCapture`) now
additionally requires `CLASS_RECORDING_ENABLED`, which is off, so the flag
coming on starts no egress on a box that has none. Its retirement, with the
`LessonAudio` model, is a separate change.

**Why.** Lesson insights had been dark since 2026-09-24 because the whole
pipeline began with a LiveKit egress per speaker, and the free `e2-micro`
production video runs on cannot carry one (D-187, measured). Every way of
bringing egress back costs money: an `e2-medium` is about $30 a month; LiveKit
Cloud's Build plan covers less than one class's egress and its Ship plan is
$50 a month; recording each participant's audio in the browser and uploading
it (issue #116) still pays Deepgram batch transcription for every class,
about $0.43 per 50-minute class at $0.0043 a minute. The operator's brief was
zero or as near as possible.

Meanwhile the transcript already existed. D-185 put a recogniser on both
speakers in every captioned class, and its output is a speaker-labelled,
time-ordered stream of finished lines in the source language — everything
Phase C reads (`speaker`, `text`, `startMs`) — thrown away by design because
captions were only ever captions. Keeping the text costs nothing when a
desktop Chrome is in the call, which PostHog's `call_connected` events for the
30 days to 2026-09-28 say is most classes:

| Class shape (by booking)                        | Bookings | Who recognises                           | Marginal cost            |
| ----------------------------------------------- | -------- | ---------------------------------------- | ------------------------ |
| Student on Mac or Windows Chrome                | ~19 / 28 | the student's desktop Chrome, both ways  | $0                       |
| Teacher on tablet or iPhone, student on a phone | ~7 / 28  | Deepgram streaming, already for captions | $0.48–0.77, already paid |

Deepgram Nova-3 streaming was $0.0048 a minute on promotion on 2026-09-23 and
the account holds about $192 of free credit with no card on file, so the
phone-to-phone case costs nothing until that runs out, and then only what
captions already cost.

**What was considered and rejected.**

- **Browser audio capture to R2, then Deepgram batch (#116).** Keeps the
  audio pipeline and pronunciation scoring, and still needs the unmeasured
  Android and iOS `MediaRecorder` behaviour, segment uploads, clock
  alignment and a migration for N rows per speaker. Costs $0.43 a class for
  ever. Rejected as the resting state; it remains the path if pronunciation
  scoring is ever wanted, since that needs audio.
- **A bigger box or a paid LiveKit plan.** $30–50 a month for a feature one
  teacher uses. Rejected by D-187 and not reopened.
- **Egress on a separate machine around booked classes.** Rejected in D-187
  as real work for the same feature; nothing changed.
- **A second recogniser for insights, independent of the captions toggle.**
  Would run recognition (and Deepgram minutes) silently, with no indicator
  the participants understand. Rejected: D-21 wants the capture visible, and
  the teacher already has one switch. This is what "v1 rides on captions"
  means, and revisiting it is a new record.
- **Storing timings from the recogniser.** It has none. The line's
  duration is estimated on the client as the gap since that speaker's previous
  line, capped at a minute, and the end is stamped at receipt by the server.
  Phase C orders and quotes; it never needed word timings.

**What it constrains.**

- **Consent is decided on the server, per class, for both speakers.**
  `lessonTranscriptCaptureOk` is the one place; the route refuses a line the
  session does not cover, whatever the client says. Do not add a client-side
  path that keeps a line the session did not authorise, and do not keep a
  teacher-only transcript for a pairing without consent.
- **Text only, never audio.** The privacy policy now says no audio is
  recorded or stored for insights. A change that captures audio for this
  pipeline reopens the policy, the supplier register, and this record.
- **`browser-live` is a state, not a vendor name.** The provider column
  carries the row's lifecycle for this path; finalising flips it under a
  guard, and the append's `WHERE` drops a line for a row that is no longer
  live. A second completion path must go through `finalizeBrowserTranscript`,
  not write the row directly.
- **The indicator stays.** `transcriptKept` renders to both participants
  while lines are being kept. Removing it reopens D-21.
- **The egress path stays dormant.** `maybeStartLessonAudioCapture` requires
  recording to be enabled. Do not loosen that to "make insights work"; they
  work without it.
- **`ai-marketing-claims.test.ts` pins both flags against the policy prose in
  both directions**: recording off and "class recording is switched off";
  transcription on and "kept as a written transcript". Flip either without
  the other and the gate fails.

**Trade-offs accepted, and unresolved risks.**

- **Insights only run for a captioned class.** A teacher who never turns
  captions on gets no transcript. That is the trade for one visible switch.
- **Transcript quality is the recogniser's, and unmeasured on learner
  speech.** Both the browser's service and Deepgram tend to tidy grammar,
  which is what the grammar category hunts for. The teacher-confirm loop
  bounds the damage (an unconfirmed finding never enters the profile); the
  first real class's findings should be read before the feature is trusted.
- **Pronunciation scoring stays dark.** It needs audio and Azure, and was
  never on. `LESSON_INSIGHTS_PRONUNCIATION_ENABLED` stays in
  `GATED_OFF_CLAIMS`.
- **Speaker attribution is the recognising browser's claim**, at the same
  trust level as a caption line. A participant could post lines labelled as
  the other speaker; the rate limits bound volume, not honesty.
- **Timings are estimates.** A held-back final or a long silence gives a line
  a shorter duration than it had; a split utterance shares one estimate by
  length.
- **A class with a break long enough for the room to close is finalised at
  the break.** Lines after it are dropped and Phase C has already run for
  the first half. Nothing tracks how often that happens.
- **A lost POST is a lost line.** The client does not retry; the route
  cannot deduplicate. Acceptable for a transcript read for patterns.
- **The egress capture code, `LessonAudio` and the admin pipeline-health
  counts for it are now dead in production** and await their own change, with
  #116 closed by this record and #117 narrowed to auto-record.
- **The marketing pages do not advertise insights again yet.** The cards D-187
  removed were not restored here; restoring one means listing it in
  `CLAIM_GATES`.
