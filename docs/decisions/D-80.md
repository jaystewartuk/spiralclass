# D-80. Vocabulary difficulty separated from CEFR language level

**What changed.** AI-generated material now treats **vocabulary difficulty** as
its own axis, independent of the CEFR **language level**. The level controls
grammar complexity, sentence structures, discourse, and abstractness of ideas;
vocabulary difficulty controls word frequency, idioms, uncommon synonyms, and
technical/literary terms. Before, the one prompt line told the model to _"pitch
the difficulty and vocabulary"_ to the level — so selecting a high level (e.g.
Spanish C1) pulled in rare words the teacher sometimes didn't recognize. Now a
C1 lesson can be written with Basic (familiar) vocabulary: complex grammar and
ideas expressed with common words.

Four levels (`MATERIAL_VOCABULARIES` in `@spiralclass/shared`):

- **basic** — most common words only; avoid uncommon synonyms/idioms; best for
  teaching new grammar and concepts.
- **everyday** — normal conversational vocabulary (the effective default).
- **advanced** — higher-level vocabulary and more complex expressions.
- **native** — rare words, idioms, literary/academic/regional expressions.

Two configuration levels, teacher-default with a per-class override:

- **Teacher default** — `teachers.material_vocabulary` (nullable), configured on
  the _AI material style_ settings screen alongside the D-78 controls.
- **Class override** — `bookings.vocabulary_override` (nullable), set from the
  class-content compose surface; it beats the teacher default for that
  one class and is _the_ control used during generation. Persisted when the
  teacher generates, so the compose picker doubles as the class setting.

`resolveVocabulary(classOverride, teacherDefault)` applies the precedence
(class → teacher → global default `everyday`). The signature leaves room for a
future `studentOverride` ahead of the class one — **no student-level setting is
modeled yet** (deliberately deferred).

The **"Allow uncommon words"** framing from the brief maps onto this: off =
basic/everyday (common words), on = advanced/native.

**Why it likely changed.** Teachers reported that high-level generated material
contained words even they didn't understand — the level was doing double duty as
a vocabulary dial. CEFR levels describe _communicative ability_, not lexical
rarity, so a high level should raise grammar/discourse complexity while leaving
word choice a separate, deliberately-chosen knob. Defaulting to accessible
vocabulary (`everyday`) means CEFR level never silently raises rarity.

**What was affected.**

- **Prompt builder** (`apps/web/src/lib/materials/prompt.ts`): the level line
  now scopes the CEFR level to grammar/structure/concepts and explicitly
  disclaims vocabulary; a new `vocabularyDirective()` (always emitted — the
  default is accessible vocabulary, not "no directive") owns word choice. Added
  to both `buildMaterialPrompt` and `buildMaterialRefinePrompt`, so **every**
  generation path inherits it: lesson/class content, library material, streamed
  generation, and Edit-with-AI refine (the app has no separate "AI tutor" — all
  flows funnel through these).
- **The one funnel** (`lib/materials/handlers.ts`): `resolveSubject` reads the
  teacher default; `generateClassContentForBooking` resolves
  `classOverride ?? teacherDefault ?? everyday`, persists the class override
  when the caller supplies one, and passes the resolved value in. Library /
  streamed / refine inherit the teacher default via the same spread — no
  call-site change (same pattern D-78 established).
- **Shared** (`packages/shared`): `MATERIAL_VOCABULARIES`, `MaterialVocabulary`,
  `DEFAULT_MATERIAL_VOCABULARY`, `resolveVocabulary()`; `vocabulary` added to
  `materialStyleSchema`, `MaterialStyleSettings`, and `TeacherClassContent`
  (`vocabularyOverride` + `vocabularyDefault`); i18n copy.
- **Prisma**: `20260720000000_add_vocabulary_difficulty` — nullable
  `teachers.material_vocabulary` + `bookings.vocabulary_override` (additive; no
  backfill — existing teachers and classes inherit the default).
- **Routes**: material-style PUT writes the teacher default; class-content GET
  exposes override + default; the generate route accepts `vocabulary` and
  persists/applies it.
- **UI**: a _Vocabulary difficulty_ chip group on the
  material-style settings screen (teacher default) and in the class-content
  compose panel (class override), each carrying the copy "Language level and
  vocabulary difficulty are separate. Students can learn advanced grammar and
  concepts using familiar vocabulary."

**Scope + compatibility.** Because the material-style action lists its columns
explicitly, it never writes `material_vocabulary`, so a save elsewhere can't
wipe a value set here. All columns nullable → existing classes/teachers automatically get the default
behavior; existing stored content is untouched.

**Unresolved risks.** The prompt effect is only observable by generating a
material and reading it — the unit tests assert the directive is present and
that the level line no longer dictates vocabulary, not that the _model_ actually
uses commoner words (same limitation D-78 noted). The default was changed for
_all_ teachers (unset now injects an `everyday` directive rather than the old
level-couples-vocabulary behavior) — this is the intended product fix, but it is
a behavior change for existing generations, not a byte-identical no-op. No
student-level personalization yet; the resolver is shaped to add it later
without touching callers.
