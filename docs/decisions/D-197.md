# D-197. A price is written in its reader's number format, and the currency it is charged in is always named (2026-10-04)

**Status.** Decided, not built. Gates the `formatterFor` change in #178 step A6.

**What changed.** `formatterFor` in `packages/shared/src/money.ts` takes the
reader's locale, from the registry's `intl` field, instead of a hard-coded
`en-US`. Separators, digit grouping and the symbol's position follow the
reader.

Four things do not change:

- **The currency.** It is the stored currency of the price. A reader's locale
  never converts, swaps or rounds an amount.
- **The code suffix.** `narrowSymbol` plus the appended ISO code, so a price
  always names its currency exactly once.
- **The amount.** Minor units, and the currency-aware exponent.
- **The cache.** Formatters are cached by locale and currency together.

Which locale is "the reader's" follows the surface:

- **The booking funnel:** `booking_page_locale`.
- **Email and push:** the recipient's locale.
- **The app:** the signed-in person's language.

**Why.** Measured with Node 24's ICU, using `money.ts`'s own rule
(`narrowSymbol`, code appended if absent):

| Price        | Today, every reader | `es` (`es-419`) | `en`            | `fr`             |
| ------------ | ------------------- | --------------- | --------------- | ---------------- |
| 1,500 MXN    | `$1,500.00 MXN`     | `$1,500.00 MXN` | `$1,500.00 MXN` | `1 500,00 $ MXN` |
| 25,000 CLP   | `$25,000 CLP`       | `$25,000 CLP`   | `$25,000 CLP`   | `25 000 $ CLP`   |
| 1,500 JPY    | `¥1,500 JPY`        | `¥1,500 JPY`    | `¥1,500 JPY`    | `1 500 ¥ JPY`    |
| 1,234.50 EUR | `€1,234.50 EUR`     | `€1,234.50 EUR` | `€1,234.50 EUR` | `1 234,50 € EUR` |

Spanish and English readers see exactly what they see today, byte for byte.
Only French changes. For a French reader today's output is not just foreign,
it is wrong: in French the comma is the decimal separator, so `$25,000 CLP`
reads as twenty-five pesos, and `¥1,500 JPY` as one and a half yen. That
misreading is what reaches German (`25.000`) and Brazilian (`25.000`) readers
too once #76 adds them.

[D-99](./D-99.md) settled that the platform presents one currency per price
and lets the card issuer convert. Formatting is a different question. It
changes how a number is written, never which currency it is in or how much,
so D-99 stands.

**What was considered and rejected.**

- **Keep `en-US` for everyone.** It is what misreads a 0-decimal currency in
  every language that groups with a dot or a space.
- **Format in the currency's home locale (MXN as `es-MX`, EUR as `de`).** It
  is consistent per currency, but a French reader would see a German
  `1.234,50 €`. The reader's conventions are the ones that read correctly.
- **Drop the code suffix where the symbol is unambiguous to the reader.**
  `$` alone is a dozen currencies. The suffix is what tells a teacher's MXN
  price apart from the funnel's USD hint (D-144), and it is cheap.

**What it constrains.**

- A formatted price is display only. Never parse one back into an amount: a
  field that shows `1 500,00` must hold its value as minor units, not as the
  rendered string. Inputs keep their own parsing.
- Never use the reader's locale to choose or convert a currency (D-99, D-64).
  The currency is the price's own.
- The code appears exactly once, whatever the locale. The existing check
  against "KWD 150.000 KWD" stays.
- Tests compare against `Intl`'s output with its real space characters.
  French groups with a narrow no-break space (U+202F), not a plain space.

**What was affected.** Nothing yet. Step A6 changes `formatterFor` and
`formatMinorUnits` to take a locale, threads one through every caller, and
adds tests: a 0-decimal currency for a French reader, Spanish and English
unchanged, and the code appearing once.

**Trade-offs accepted, and unresolved risks.**

- **The frozen mobile app keeps `en-US`.** It is still installed on real
  phones, and `formatterFor`'s fallback for old ICU stays.
- **A teacher and her buyer can read the same price written two ways.** A
  French teacher with an English funnel sees `1 500,00 $ MXN` in her app,
  while her buyers see `$1,500.00 MXN`. Same amount, same currency, each in
  its reader's script. Accepted.
- **Engines can differ.** ICU versions occasionally change a locale's spacing
  or symbol. Snapshotting `Intl`'s own output, rather than hand-written
  strings, keeps a test honest about that, at the cost of a test that moves
  when Node's ICU does.
