# D-50. Capture billing country + address at checkout now; enable Stripe Tax later behind a flag

**What changed.** Both Stripe checkout rails — the student one-off package
charge (`lib/payments/start-checkout.ts`)
and the teacher subscription charge (`lib/subscriptions/start-billing-checkout.ts`)
— now set `billing_address_collection: "required"` so Stripe's hosted page always
collects a billing address. The collected address is persisted alongside the row
it belongs to: `payments.billing_country` / `payments.billing_address_json` (read
off `customer_details` when `checkout.session.completed` lands) and
`teacher_subscriptions.billing_country` / `billing_address_json` (written back
onto the platform Customer via `customer_update[address]=auto`, then read off the
Customer on subscription activation). Migration
`20260708010000_capture_billing_address_for_tax` is additive + nullable, with a
defense-in-depth alpha-2 CHECK mirroring `teachers_country_iso_format`.

Stripe Tax itself (`automatic_tax[enabled]`) is **not** turned on. It is gated
by a single kill-switch, `stripeTaxEnabled()` (env `STRIPE_TAX_ENABLED`, default
off), threaded into both checkout calls. Flipping it on is the _only_ change
needed to start computing tax — no schema change, no backfill.

**Why it likely changed.** Global-launch item 7. **Enabling tax retroactively is
impossible without the buyer's address**, so the address had to be captured _now_
even though whether to compute tax is deferred. Capturing costs nothing and keeps
the door open. Whether and where to collect is a business decision taken outside
this repository ([D-159](./D-159.md)) — never a code default, which is the whole
reason it sits behind a kill-switch that is off.

**What was affected.** `lib/stripe/client.ts` (both checkout builders gain
`billingAddressCollection` + `automaticTax`), `lib/stripe/tax.ts` (new gate),
`lib/stripe/billing-address.ts` (new address→columns normalizer, shared by both
webhooks), `lib/stripe/types.ts` (address schema + `customer_details` + Customer
`address`), the two webhook handlers, `lib/subscriptions/lifecycle.ts`
(`activateSubscription` persists billing, never nulling a prior capture), env +
Prisma. Capture-only respects "never paywall getting paid" — nothing about the
payout rail changed and no buyer is charged tax.

**Unresolved risks.** (1) `STRIPE_TAX_ENABLED` has prerequisites outside the
codebase that **the flag does not enforce**; it is not safe to flip on the
strength of the code alone. (2) The checkout collects no tax identifier, so any
buyer-side handling that would depend on one is not built. (3) OXXO/SPEI stay
suppressed (card-only), so this only covers card checkouts.
