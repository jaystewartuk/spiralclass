# D-180. The two counts every pull request moves are stated as floors

**Status.** Active.

**What changed.** `scripts/readme-counts.mjs` states the test-file count and
the decision-record count as floors, "more than N", where N is the largest
multiple of a step strictly below the real count. The steps are 100 test files
and 25 decision records. Every other count it holds stays exact. A floor is
still recomputed on every gate run and still rewritten by `--fix`. The checker
also fails on an exact count of a floored claim ("803 test files"), because the
floored pattern cannot see one and it would drift unchecked.

The decision scout's prompt (`.claude/agents/decision-scout.md`) states the
record count too and joins the checked documents. It said 125 against a tree
of 127.

**Why.** Almost every pull request adds a test file. So every open branch
rewrote the same line of `README.md` and `docs/development/testing.md`, and any
two branches open at once conflicted. Measured with `git log -G` over
`README.md` and `docs/` from 2026-09-04 to 2026-09-14: the test-file number
changed in 19 commits and the decision-record number in 8. No other count
changed in more than 3. On 2026-09-14, #118 and #119 were opened together, and
each conflicted on this line as soon as another PR merged.

With a floor, the line changes once per step. Two branches that both cross a
step write the same text, which git merges without a conflict.

**What was considered and rejected.**

- **Deleting the numbers.** This ends the conflicts, but the front door loses
  concrete facts a reader uses to size the project. The rule that a stated
  number is checked was never the problem.
- **`merge=union` in `.gitattributes`.** A union merge keeps both sides, so the
  line would state two numbers.
- **A tolerance band with the number left exact** ("within 5% of the tree").
  `--fix` would have no single right answer, and a number that is allowed to be
  wrong is no longer a claim anything verifies.
- **Floors for every count.** Models, migrations and indexes change a few times
  a month and read better exact. Floor a claim only when its measured churn
  earns it.

**What it constrains.**

- A floored claim must say "more than". The checker rejects the exact form.
- Do not add a floor to a claim without measuring its churn first. Do not raise
  a step to make a gate go green: `--fix` is the answer to drift.
- CLAUDE.md's rule is unchanged: a number in a front-door document is added to
  `scripts/readme-counts.mjs`.

**What was affected.** `scripts/readme-counts.mjs` (now exporting
`expectedFor` and `reconcile`, with `scripts/readme-counts.d.mts`),
`apps/web/tests/config/readme-counts.test.ts`, the count sentences in
`README.md`, `docs/README.md`, `docs/development/testing.md`,
`docs/decisions/READ-THIS-FIRST.md` and `.claude/agents/decision-scout.md`.

**Trade-offs accepted, and unresolved risks.**

- The front door is less precise: "more than 800" can mean 899.
- A conflict can still happen when one branch crosses a step and another branch
  edits nearby prose on the same line. That is now rare instead of routine.
- A branch cut just below a step can pass its own gate and fail on the merge
  tree once main has crossed the step. The fix is the same as before: rebase
  and run `--fix`.
