# D-123. Attach social previews to the share link, and render the text ourselves

> **Two later corrections, both to the AI half.** [D-127](./D-127.md) moved
> image generation onto Vertex AI after the consumer API turned out to gate
> every call on a separate prepay balance. [D-155](./D-155.md) found that the
> reason every generated meme was a shocked face was our own prompt: the
> single hardcoded brief below asked for "an exaggerated, instantly readable
> facial expression", identically, for every teacher on the platform.

**What changed.** A teacher can now give a shared booking link its own
social-preview image — uploaded, or generated by the platform image model — and
that image replaces the built-in Open Graph card for that link only. Three new
pieces:

- **`SocialPreviewImage`** — one stored image asset, and the AI generation
  ledger. `source` is `upload | ai` (with `template | system` reserved), so the
  two rails share one model and nothing downstream branches on provenance.
- **`SocialPreview`** — one placement: "a link shared for THIS group previews
  with THIS image and THIS caption". `shareGroupId = null` is the teacher's
  default, used by untagged shares.
- **`/api/og/social-preview/[id]`** — a Satori route that composes the stored
  background with the caption, the teacher's name and the brand.

Resolution runs off the `utm_content` tag `shareTaggedUrl()` already puts on
every per-group link: the group named by the tag, else the teacher's default,
else nothing. "Else nothing" is what makes this safe — `generateMetadata` then
omits `openGraph.images` entirely, and Next's file-convention
`opengraph-image.tsx` supplies the existing card byte for byte.

Also added: `lib/ai/image-gen.ts` (a vendor-neutral seam shaped exactly like
`lib/ai/tts.ts`) with a Gemini adapter; `GEMINI_IMAGE_API_KEY`,
`GEMINI_IMAGE_MODEL` and the `SOCIAL_PREVIEW_AI_ENABLED` flag; and two analytics
events, `social_preview_generated` and `social_preview_selected`.

**Why it likely changed.** Language teachers get far more engagement from funny,
relatable posts than from ordinary promotional ones, and the teacher driving
this was rationing images against ChatGPT's free tier. The bottleneck was never
raw image volume — it was effort: describing the same context every time, then
pasting the result somewhere it does not actually become the link preview.

Six decisions carry the design, each of which had a plausible alternative:

- **The image belongs to the share LINK, not the booking page.** The same
  booking page is promoted differently in different places — a meme in one
  Facebook group, a clean card in another, a professional one in a bio link.
  Attaching it to the teacher would have made a meme the preview for every
  context she has. Rejected: a new short-link entity per promotion, which
  duplicates `utm_content` tagging that already works, already feeds attribution,
  and costs no redirect hop.
- **AI generates the visual; SpiralClass renders every character of text.** The
  prompt explicitly forbids letters, numbers, signage and watermarks. A
  misspelt Spanish meme posted by a _Spanish teacher_ discredits the exact
  expertise she is advertising, and accented characters are precisely where
  image models fail. Three further wins fall out: a caption edit is free and
  instant, brand text is always correct, and caption A/B testing later costs
  zero generations. This is also what makes the provider a commodity — the axis
  they differ most on is designed out.
- **The background is persisted; the composite is rendered on demand.**
  Regenerating per crawl would be non-deterministic and cost money per Facebook
  scrape, so the asset is stored. The composite is not, because Satori is
  deterministic, free and already in production here — baking it would turn a
  caption edit into a re-upload plus orphan cleanup plus a second cache to
  invalidate. Re-evaluate only if render latency ever threatens a crawler
  timeout.
- **Cache invalidation is the `?v=<updatedAt>` in the card URL.** Facebook and
  WhatsApp cache the first scrape of a URL, so the only reliable way to show a
  changed preview is a URL they have never seen. Keying it on the placement's
  `updatedAt` means a change mints a new URL automatically and no change keeps
  every warm cache.
- **One configuration axis, named `angle`.** Not the purpose-times-style matrix
  the brief floated: for this audience the two are ~95% correlated, so a 24-cell
  matrix mostly offers combinations whose output nobody can predict, while
  multiplying analytics cardinality before there is a single data point. The
  name is `angle` (not `type`, not `style`) precisely so a second dimension is an
  additive column later rather than a rename that orphans every stored row and
  every recorded event. The teacher picks an angle and optionally says what it is
  about in her own words; she never sees a prompt.
- **Free gets 3 a month, Pro 20.** A small monthly allowance on Free, rather
  than the flat Pro gate used for the
  homework and intro-video AI helpers, because this is the feature that turns a
  Free teacher into a paying one — putting it entirely behind the paywall would
  gate acquisition on having already converted. Twenty images is about four or
  five real posts with three or four regenerations each, on the order of a dollar
  a month against a GBP 7.99 subscription. Uploads are never capped.

**What was affected.** Purely additive. Two new tables, one new enum pair, no
existing table or row touched, and the migration is `CREATE`-only.
`generateMetadata` in `b/[slug]/page.tsx` now reads `searchParams` for
`utm_content` and conditionally sets `openGraph.images` / `twitter.images`; the
page was already dynamic, so no staticness was spent. The dashboard share-groups
page gained a preview editor per group plus one for
the default. New assets reuse the existing PUBLIC `teacher-photos` R2 bucket
under `${teacherId}/social/` — no new bucket, no new Terraform, no new env vars
in three environments, matching how testimonial avatars already namespace there.
The AI path is dark until both `GEMINI_IMAGE_API_KEY` and
`SOCIAL_PREVIEW_AI_ENABLED` are set (the D-114 two-condition shape); with the
flag off, upload still works and every existing link is untouched.

Analytics needed almost nothing, because the loop was already closed:
`utm_content` flows through the `ap_src` cookie into
`attributionProperties()` on the server funnel events, so "funny meme leads to N
landings leads to M purchases" is a PostHog breakdown by `utm_content` joined to
the angle configured for that group. Only two events were added, and neither
counts impressions.

**Unresolved risks.**

- **Crawler behaviour is unverified end to end.** Facebook's, WhatsApp's and
  LinkedIn's scrapers cannot be exercised from a test suite or a preview deploy
  behind auth. What is verified locally: the metadata override and its omission
  (`tests/social-preview/og-metadata.test.ts`), the card route's dimensions,
  cache headers, listing gate and degradation
  (`tests/social-preview/card-route.test.ts`), and Next's merge rule itself, read
  from `next/dist/lib/metadata/resolve-metadata.js`. What still needs a human
  with a real link: the Facebook Sharing Debugger, a WhatsApp message to
  oneself, and LinkedIn's Post Inspector.
- **We count landings, not clicks.** Nobody can count clicks on a Facebook post
  without owning the redirect, which was deliberately not built. The funnel
  therefore starts at `booking_page_viewed`, not at the post.
- **WhatsApp's in-chat thumbnail is a near-square centre crop and is
  size-sensitive.** The layout keeps the caption in the centre band and puts the
  brand footer where a crop may take it, but the exact crop is not contractual
  and could change.
- **The default model id (`gemini-3.1-flash-image`) is env-overridable and will
  age.** A model rename is a `GEMINI_IMAGE_MODEL` change, not a deploy — but
  nothing warns when the pinned default stops existing except a `blocked`/`error`
  reason reaching a teacher.
- **Single-default-preview is an application-layer guarantee.** Postgres allows
  many NULLs under a unique index, so the schema cannot bound the
  `shareGroupId = null` row to one. It is upserted inside a transaction and
  resolution is deterministic regardless (newest wins); a partial unique index
  was rejected because it is not expressible in the Prisma schema and would read
  as permanent drift to the migration-drift gate.
- **The teacher's free-text topic reaches a third-party provider.** It is
  control-character-stripped, bounded to 160 characters, embedded inside a prompt
  we wrote, rate-limited per teacher and recorded for audit — but the provider's
  own safety filter is the last line, and a `blocked` result is surfaced to her
  as "try describing it differently" rather than escalated.

**Superseded (billing path only, D-127, 2026-08-24):** `GEMINI_IMAGE_API_KEY`
against the public Generative Language API gated every call on a separate
Prepay balance that a linked Cloud Billing account doesn't satisfy — the
first real generation attempt 429'd. `lib/ai/gemini-image.ts` now calls the
same model through Vertex AI (ordinary postpaid Cloud Billing) instead; see
D-127. Everything above — the prompt design, the six decisions, the
unresolved risks — is unaffected.
