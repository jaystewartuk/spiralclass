# D-171. One visual baseline set, owned by the machine that gates the merge

**Status.** Active. Supersedes the two-set mechanism of
[D-161](./D-161.md) — not its argument, which is why the heavy tier is on
runners at all.

**What changed.** The 120 `-darwin.png` visual baselines are deleted.
`apps/web/tests/visual/regression.spec.ts` skips unless
`process.platform === "linux"`, `scripts/ci/e2e.sh` refuses to regenerate
baselines anywhere but Linux, and `apps/web/tests/visual/manifest.test.ts` stops
comparing two sets and starts asserting that the second one does not grow back.
The committed set is `-linux.png`, produced and asserted on `ubuntu-latest`, and
`gh workflow run heavy.yml -f update_visual_baselines=<route>` is the only way to
move it.

## Why — the second set had already lost its consumer

D-161 committed a macOS set and a Linux set for a reason that was true when it
was written: the laptop ran the heavy suites, so the laptop needed images it
could assert against. It named the cost in its own text, under "The standing
cost, which is a bookkeeping cost":

> Restyle a page, regenerate on the laptop, review the diffs, merge — and the
> runner goes red on exactly the routes just fixed.

That cost bought the laptop's ability to catch a visual regression before a
push, and while `pnpm ship-pr` wrote the receipt `pnpm promote` believed, it also
bought part of the release certification.

[D-162](./D-162.md) removed the second half. `pnpm promote` no longer runs or
reads a local full-tier gate; it asks GitHub whether **Gate** and **Heavy** both
concluded green on the push run for the exact commit being promoted. From that
point nothing that ships has depended on a macOS pixel. What remained was the
bookkeeping, paid on every design change, for a guard whose only remaining job
was to tell the operator something a runner would tell him twenty minutes later
on the same pull request.

The immediate occasion was smaller and is worth recording because it is what the
cost looks like when it lands: `features-390-light` and `features-390-dark` were
stale in the Linux set, so **Heavy was red on `main` from its first push and on
every pull request under it**, publicly, in the Actions tab of a repository that
had just been made public. Fixing that properly meant regenerating on the runner
_and_ on the laptop — two machines, two commands, one of which the runner cannot
run and the other of which holds the machine lock (D-146) for 20-40 minutes to
refresh images no release reads.

## What was considered and rejected

- **Regenerate both sets and carry on.** The honest version of the status quo,
  and what this change nearly was. Rejected because it pays the bookkeeping
  again for a set nothing reads: the darwin images would have been regenerated
  to keep a local run green that certifies no release and blocks no merge.
- **Make the sweep platform-neutral by widening `maxDiffPixelRatio`.** Rejected
  here for exactly the reason D-161 rejected it, quoted rather than re-derived:
  the tolerance already cannot see two lines of grey text swapping places on a
  1280x2184 page, and one wide enough to span two font stacks "would not make
  the guard portable; it would make it decorative". **The threshold is
  unchanged by this record.** A future reader finding a Linux-only sweep should
  not read it as a step toward a looser one.
- **Keep both sets but stop asserting darwin locally.** The worst of both: the
  images stay in the repository, rot silently, and the parity guard that made
  them trustworthy has nothing left to compare.
- **Pin the snapshot suffix to `linux` so a Mac asserts the Linux images.** A
  loud red on every route, on a machine whose font stack was never going to
  match — and one `--update-snapshots` away from writing macOS pixels into the
  set the gate reads. The skip refuses instead of failing, and e2e.sh refuses to
  write at all.

## What it constrains

- **The visual sweep asserts on Linux only.** A change that makes it assert
  elsewhere needs a baseline set produced there, which is the thing this record
  deleted.
- **`scripts/ci/e2e.sh` must keep refusing to regenerate off Linux.** Not a
  convenience check: it is what stops a local run overwriting the only set with
  another machine's rasterisation.
- **`manifest.test.ts` stays in the FAST tier.** Playwright defaults to
  `updateSnapshots: 'missing'`, so a captured route with no committed image gets
  one written on a runner whose disk is thrown away, and the leg reports green.
  That test is the only thing that says a capture is uncovered, and it has to
  fail before the heavy tier starts, not after.
- **The `-linux` suffix is not decoration.** It names the machine whose pixels
  these are. Renaming the set platform-neutral would make a second platform's
  images look like a merge conflict rather than a mistake.

## What was affected

`apps/web/tests/visual/regression.spec.ts-snapshots/*-darwin.png` (120 files,
deleted) · `apps/web/tests/visual/regression.spec.ts` (the skip) ·

## Trade-offs accepted, and unresolved risks

- **The laptop no longer catches a visual regression before a push.** Accepted:
  `heavy.yml` runs the sweep on every pull request and every push to `main`, so
  the regression is caught before a merge rather than before a push. The gap is
  minutes of feedback, not coverage.
- **`pnpm promote --force-gate` now certifies less than it used to on a Mac.**
  It runs `gate.mjs --tier full` locally, and the visual sweep inside that will
  skip. `--force-gate` is the escape hatch for when the runners' verdict cannot
  be read at all, and a reader reaching for it should know it is no longer a
  full-strength substitute for this workflow's green. **Nothing checks this**;
  the skip prints, and that is all.
- **Seeing a design change locally is now a different command.**
  `capture.spec.ts` writes a gallery and asserts nothing, which is the right
  tool and was already there — but it is not the tool anyone had learned to
  reach for, and this record is most of the reason to know it exists.
- **Regenerating a baseline now requires a push and a dispatch.** Slower than a
  local command, and it cannot be done from a branch that has not left the
  laptop. This was already true of the Linux half; it is now true of the only
  half.
- **One set means one machine's opinion of a page.** If `ubuntu-latest`'s font
  stack changes under us, every route moves at once and nothing independent
  disagrees. The failure is loud rather than silent, which is why this is a
  risk rather than an objection.
