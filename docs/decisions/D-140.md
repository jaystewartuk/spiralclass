# D-140. Legibility outranks visual identity, and the layout asks the pointer, not the width, whether it is drawn for a finger

Every typographic and colour value in
[`packages/shared/src/tokens.ts`](../../packages/shared/src/tokens.ts) is set
for a dyslexic reader first. The face is Atkinson Hyperlegible; body text is
17px and nothing is smaller than 15px; there are no italics, no all-caps labels
and no negative letter-spacing; status always has a word as well as a colour;
and body text is held at 12.8:1, short of black on white. Each reader can set
text scale, spacing and a warm tint, and the choice is stored on their account
([`lib/reading.ts`](../../apps/web/src/lib/reading.ts)). The controls are the
first onboarding step and sit on both account pages; there is no persistent
toolbar. Layout breakpoints are
Tailwind's default widths. Whether the app shell draws for a mouse is decided
by `(min-width: 1024px) and (pointer: fine)`, the `desktop` and
`desktop-wide` screens in
[`apps/web/src/lib/breakpoints.ts`](../../apps/web/src/lib/breakpoints.ts).

## Why

Dyslexia does not present one way. Preferred size, spacing and ground vary
enough that any fixed choice is a compromise for most readers, so the defaults
follow the evidence and the reader can change them. Visual noise costs a
struggling reader more than anyone, so about ninety percent of the interface is
neutral, and one saturated hue is kept for the primary action and for a class
happening now.

The teacher the product was built with works from an Amazon Fire HD 10, which
is 1280 CSS px wide in landscape and wants the touch layout. A laptop window
1280px wide wants the desktop layout. No width separates the two; the pointer
does.

## Options considered

- **A dyslexia-branded face (OpenDyslexic, Dyslexie)** — controlled studies
  have repeatedly failed to show a speed or accuracy gain over an ordinary
  well-drawn sans-serif. Atkinson Hyperlegible gives commonly confused letters
  different shapes (`b d p q`, `I l 1`), and that mechanism carries over to
  dyslexia. Spacing has better support in the literature than any font swap.
- **A condensed face (Archivo) to fit French in fixed-width navigation** —
  condensing tightens exactly the spacing that helps. French wraps or gets a
  shorter label instead.
- **Moving every breakpoint above the widest tablet (1281px)** — tried, and
  withdrawn the same month (see below).
- **One fixed reading setting** — any fixed choice is a compromise for most
  readers.

## What it cost

- Less fits on a screen. A 17px floor and open spacing make the calendar, the
  admin tables and the student detail page longer.
- Two weights, so hierarchy comes from size, colour and space.
- A persisted preference on Teacher and Student, mirrored into a cookie so it
  applies on first paint.
- The warmth of the original terracotta identity.
- `md` (768) is unused. The intermediate tablet layout is design work that has
  not been done.

## What it constrains

- **The floors are external constants, and the guards check them as literals.**
  [`d140-rules.test.ts`](../../apps/web/tests/config/d140-rules.test.ts) fails
  on negative tracking, italics, all-caps, an arbitrary size under the floor,
  a deleted type step, and an on-colour dimmed by opacity.
  [`tokens.test.ts`](../../packages/shared/src/tokens.test.ts) checks the
  palette and the dark-surface ordering. A guard that derives its bound from
  the thing it guards proves only that the thing equals itself.
- **Tailwind's stock size keys are redefined onto the floors, not removed.**
  `xs` and `sm` are both 15, `base` is 17 and `lg` is 19
  (`apps/web/tailwind.config.ts`). Tailwind emits nothing for an unknown class,
  so a removed key fails silently.
- **Colour comes from the token layer.** Each value is the smallest OKLCH
  lightness step that clears its ratio against the hardest surface in its own
  theme. [`retired-brand.test.ts`](../../apps/web/tests/config/retired-brand.test.ts)
  fails on the old hexes.
- **Width is for room, the pointer is for input.** Only the layout-mode
  utilities in the navigation shells use `desktop` / `desktop-wide`. Spacing
  and type stay on the width scale. Never add a second scale or an arbitrary
  `min-[…]:` variant; if a surface needs a middle tier, name a screen.
  `theme.screens` replaces Tailwind's scale, so omitting a key deletes its
  utilities at build time.
  [`responsive-breakpoints.test.ts`](../../apps/web/tests/config/responsive-breakpoints.test.ts)
  and [`breakpoints.test.ts`](../../apps/web/src/lib/breakpoints.test.ts)
  enforce both, and pin every Playwright project to a 1440×900 viewport.
  Playwright's `Desktop Chrome` preset is 1280×720, which would audit the touch
  render and pass.
- **Where the code differs from what was first written, the code is what
  holds.** The 2026-08-29 rules said touch targets are at least 44px on every
  layout. Button, Input and Select are 44px (`h-11`) below `lg` but drop to
  40px (`lg:h-10`) from 1024px wide by width alone, so a 1280px landscape
  tablet gets 40px controls. The rules also said line height 1.7 and a measure
  near 62 characters. The `body` step is 28/17 (about 1.65), and the default
  reading spacing sets 1.6. Raising either is a change to make deliberately,
  with the visual baseline.

## How we got here

- **2026-08 (before the 29th).** The brand-token layer was already one source
  shared by both clients. Measured that month: gold text at 2.16:1, dark-mode
  error text at 4.19:1, control borders at 1.39:1 across about ninety forms,
  and `primary` at 3.48:1 on a raised card. The palette had been authored as
  twenty-nine appearances, with contrast left to be checked afterwards.
- **August 2026.** To give the Fire HD 10 the phone layout, `sm` and `md` both
  moved to 1281px, one above its 1280px landscape width, because CSS
  `min-width: N` matches at exactly N. `lg` moved to 1440, and a `roomy` step
  was added at 640. This was verified in Chromium at 800×1280 and 1280×800.
  The cost: every window narrower than 1281px, including most non-maximised
  laptop windows, got the touch layout. Nothing laid out between 640 and 1281,
  and nothing responded above 1440.
- **2026-08-29.** The legibility system was adopted. 1,164 visual captures
  were taken before any token moved; `pnpm design:drift` counted 441 bypasses
  across 102 files; 62 contrast pairings verified across both themes. The same
  day the breakpoints went back to Tailwind's defaults, with the pointer gate.
  392 prefixes across 164 files were remapped in one pass. No element set the
  same property at both `sm:` and `md:`, checked before the two collapsed. The
  1,164 captures were re-taken at six viewports in both themes.
- **2026-08-29, correction.** The floor was stated and not held. The shipped
  scale had `body` at 16 and a `label` step at 11. A migration moved 47
  arbitrary sizes, 10px and 9px among them, onto that 11px step, and was
  reported as a win. Wiring the scale into Tailwind had sat beside the stock
  scale rather than replacing it, so `text-sm` (802 uses, 14px) and `text-xs`
  (499 uses, 12px) went on rendering. Three guards were watching and none fired:
  the type-scale test was bounded by the scale's own smallest step, the drift
  scanner counts only arbitrary values, and the theme-parity test compared the
  palette with a CSS mirror that shared the same inverted dark ladder. `label`
  was deleted, and the stock keys were redefined onto the floors.
