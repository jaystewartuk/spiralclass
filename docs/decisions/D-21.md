# D-21. Lesson-insights voice data: keep-on-opt-in retention + consent model (2026-06-25)

**Status: Proposed.** Pins the retention + consent **model** that D-19 §6 left
open. Builds on [D-19](./D-19.md) (the pipeline policy); the per-student consent
enforcement that backstops this model is [D-22](./D-22.md).

**What is proposed.**

1. **Retention = keep-on-opt-in.** The default is **derive-then-discard**: once a
   lesson's transcript exists, the raw per-speaker audio is deleted. A teacher may
   opt in (`Teacher.lessonAudioRetentionOptIn`) to **keep** that audio for
   playback instead. This confirms D-19 §6's "delete unless the user opts to keep"
   as the standing model and pins the mechanism.
2. **Consent surface = the recording indicator + a per-student recorded consent.**
   Capture only happens when the teacher starts recording, where both parties
   already see a visible recording indicator (Phase A rides the Record action).
   The indicator is **necessary but not sufficient** on its own: capture is
   additionally gated on an explicit, recorded per-student consent (D-22). There
   is no silent or always-on capture; the thornier
   auto-capture-every-lesson question stays out of scope.
3. **Phase B ships gated.** Storing a derived transcript and sending a student's
   voice to an external ASR vendor is the highest-sensitivity step in the
   pipeline, so Phase B transcription (built disabled in #277) **remains gated**
   behind both a flag and a vendor key.

**Why.** Phase B was the first phase to store a derived record of a student's
voice and to send that voice to a third party. The learning value lives in the
derivatives (text + scores), so
shedding the high-sensitivity asset by default — while letting a teacher keep it
when they have a reason — is the smallest liability that still delivers the
product.

**What is affected.** The Phase B gate is **NOT** lifted. The code ships dormant
(Phase A log-only): set `LESSON_INSIGHTS_TRANSCRIPTION_ENABLED` and a vendor key
(`DEEPGRAM_API_KEY`) to lift it. No teacher→student payment or booking-state
logic is touched. The per-student consent gate (D-22) ships now as a code-level
safety backstop and is independent of the flag.

**Unresolved risks.**

- **Vendor bake-off still pending.** Deepgram ships as the default behind a
  swappable seam; the Deepgram-vs-AssemblyAI comparison on real Phase-A clips
  (Spanish accuracy, word-timing, cost) should run before or at enable and may
  swap the adapter. It needs real captured audio, so it follows Phase A's
  first production captures.
- **Cross-border specifics ride on the vendor's processing region** — the
  configured vendor's data residency is recorded in the sub-processor register
  ([D-128](./D-128.md)).
- **Minors consent granularity** is addressed by [D-22](./D-22.md): a per-student
  consent surface with an explicit minor/guardian flag gates capture, rather than
  the teacher's recording consent standing in.
