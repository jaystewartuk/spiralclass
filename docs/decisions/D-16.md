# D-16. The class call is ours, on LiveKit behind a provider seam, self-hosted on one free machine with no egress

The in-class video call is SpiralClass's own, reached only through the
`VideoProvider` seam ([`lib/video/provider.ts`](../../apps/web/src/lib/video/provider.ts)),
whose one implementation is LiveKit. Production's LiveKit server is one Always
Free Compute Engine `e2-micro` at `wss://livekit.spiralclass.com`, running
`livekit-server` and Caddy and nothing else
([`infra/gcp-livekit/`](../../infra/gcp-livekit/README.md)). It cannot carry
egress, so class recording is off (`CLASS_RECORDING_ENABLED` is commented out
in both [runtime env files](../../config/env/production.runtime.env)); when on,
the recording is audio-only.

## Why

Owning the call lets the teacher's private notes and the student's
instructions sit on top of the video on one screen, which a WhatsApp call
beside the app cannot, and it is the only way to get a class's words into
lesson insights ([D-185](./D-185.md)). The transport is commodity, so it sits
behind an interface: every move of production's server since has changed
`LIVEKIT_URL` and the key pair, and no application code.

Where the server runs is set by cost and measured capacity. LiveKit Cloud's
free plan covers 5,000 participant-minutes a month (about 41 two-person
class-hours) and bills recording per minute on top. The `e2-micro` is Always
Free; its only charge is the static IPv4 address, $0.005 an hour (about $3.65
a month).

## Options considered

- **Peer-to-peer WebRTC** — cheapest, but caps at 1:1 and makes recording and
  group classes painful.
- **LiveKit Cloud as the resting state** — lost on cost. It stays the
  rollback: its line is kept as a comment in `production.runtime.env`, and the
  CSP allows both hosts.
- **The Oracle Always-Free box** — ran production until 2026-09-19, then could
  not be relaunched for host capacity.
- **A paid `e2-medium` with egress (about $30 a month)** — the size the
  measurements support for calls plus recording; the operator chose the free
  box with recording off. (`infra/gcp-livekit/README.md` says about $25.)
- **Egress on a separate machine started around booked classes** — needs
  egress to reach the call server's Redis privately and an Inngest start-up
  schedule: real work for a feature one teacher used.

## What it cost

- **No recording.** Recordings already in R2 still play; nothing new is made.
- **One free VM, no SLA, no alert** on `livekit.spiralclass.com`. A reboot
  drops a class in progress, so the box is changed outside lesson hours.
- **Preview has no video**, so the first real LiveKit server a change to the
  call, captions or transcript meets is production's.
- **Cloudflare is in the path of every call's signalling.**
- **The load test was simulated**, TURN on but unexercised: a student behind
  a UDP-blocking network relies on TCP 7881 and TURN's UDP 3478, untested.

## What it constrains

- **No media SDK call from a page or component**; add a `VideoProvider`
  implementation. The call page receives a `{ url, token }` grant; the
  websocket URL travels in it, never in a `NEXT_PUBLIC_` variable.
  `livekit-client` is browser-only and loads with `ssr: false` through
  [`class-call-client.tsx`](../../apps/web/src/components/video/class-call-client.tsx).
- **The booking is the room**: `class-<bookingId>`, no table, a token minted
  per page visit (`apps/web/tests/video/provider.test.ts`). The call is gated
  on the teacher's Pro plan (`gateProFeature(…, "lesson_notes")`) for both
  parties and not by a time window; a non-Pro teacher's student is told it is
  not enabled, never shown an upgrade. With no provider configured, the call
  pages say video is not switched on yet.
- **Do not add egress to this box.** Recording comes back as a bigger machine,
  the flag and the privacy policy in one change.
  [`ai-marketing-claims.test.ts`](../../apps/web/tests/config/ai-marketing-claims.test.ts)
  fails if the flag and the policy's "switched off" sentence disagree.
- **`LIVEKIT_URL` moves to a new server only when all three hold:** it serves
  LiveKit through its own certificate, a real class has been booked and
  joined through the app on it, and production's pair in Infisical is its own.
- **Two overlapping classes is the graduation trigger.** At about 0.12 core
  a class, a second concurrent one reaches the `e2-micro`'s sustained ceiling.
- **Preview holds no LiveKit key pair** while the only server is
  production's: a pair is valid for its whole server and cannot be scoped to
  one environment's rooms. Preview gets video back only through a server of
  its own, recorded as a new decision.
  [`env-config.test.ts`](../../apps/web/tests/scripts/env-config.test.ts)
  checks the env file and the activity probes; nothing can check Infisical.
- **Keep `livekit.spiralclass.com` proxied by Cloudflare**, SSL mode Full,
  "Always Use HTTPS" off for the hostname: Caddy's http-01 challenge on :80
  is the certificate's only renewal path. Only wss signalling resolves the
  name; media uses the box's own address (`--node-ip`). livekit-server sees
  Cloudflare's address as `client_ip`. `local-gate.test.ts` ("the LiveKit cert
  probe checks the ORIGIN, not Cloudflare's edge").
- **The recording is audio-only** (MP4/AAC `.m4a`; WebKit only gained Ogg in
  Safari 17.5). The key's extension decides the replay player, so legacy
  `.mp4` rows still play. For a screen-share after the fact, record that track
  rather than restore a full composite (`apps/web/tests/video/recording.test.ts`).
- **Auto-record decides who starts a recording, never what it captures.** It
  starts at most once per booking (any `CallRecording` row blocks it, so a
  Stop sticks across reconnects), only with both people in the room, through
  `startBookingRecording` and its Pro gate. Both always see the indicator.
  Voice analysis stays behind the student's own consent ([D-22](./D-22.md))
  (`apps/web/tests/video/auto-record.test.ts`).
- Recordings are deleted when the teacher's account closes ([D-22](./D-22.md)).

## How we got here

- **June 2026 (undated).** Classes had happened on WhatsApp. The call was
  built behind the seam on LiveKit Cloud. A class-window limit on the
  student's join was lifted: the room is just empty until the other joins.
- **2026-07-21 — production onto the self-hosted Oracle box** preview used (2
  OCPU, 12 GB), with no SLA and a ceiling of about 15–20 concurrent
  two-person rooms before packet loss, measured in the LiveKit spike.
  Recording, captions and transcription were turned on.
- **Recording off 2026-08-08** ahead of the first promotion, **on 2026-08-26**
  with a setting to auto-start it, because a pipeline hanging off a
  mid-lesson tap mostly did not happen.
- **2026-08-27 — Cloudflare proxy.** Fifteen joins from the teacher's iPhone
  between 08:48 and 08:53 each closed the signalling socket (code 1006) 30–130
  ms after opening, while her student and her Android tablet joined. The
  hostname was the product's only bare A record. Proxying fixed it at once;
  the cause on the phone was never identified.
- **2026-08-27 — audio-only.** The first recorded class, 51 minutes, made an
  846 MB file and dropped 2,586 video frames with one class on the box.
  Capacity and the heavier retention duty of video decided it; storage cost
  did not (R2 has no egress fees).
- **2026-09-16 — preview's key pair removed**, production's rotated.
- **2026-09-19 — LiveKit Cloud.** The Oracle box was terminated to free its
  storage for a rebuild; 56 relaunches between 13:38 and 22:14 were each
  refused `Out of host capacity` (the retry loop's log). Classes were booked
  for Monday. A Pay As You Go upgrade requested on 2026-09-20 was still
  pending four days later.
- **2026-09-24 — the `e2-micro`, recording off.** Measured on a throwaway box
  from the same boot script, `lk load-test` from outside Google, `mpstat` and
  `docker stats` from the serial console each minute. A class (two 720p
  simulcast publishers, one subscriber, ten minutes): 0 packet loss, 2.2 Mbps,
  `livekit-server` at 10–12% of a core, the VM about 0.12 core, about 375 of
  953 MB RAM. Adding the app's three recordings: within a minute egress killed
  two of them with `CPU exhausted`, iowait hit 44%, participants reconnected
  and video fell to its lowest layers. So the box hosts the call, not the
  capture; the August reason for recording stands.
