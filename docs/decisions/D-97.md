# D-97. Three lesson-insights follow-ups: vocabulary flashcards, speaking-time analytics, in-call bookmarks

**What changed.** Three additive features layered on the D-94 self-hosted
LiveKit / lesson-insights pipeline:

1. **Vocabulary flashcard study mode** (student-facing). The existing
   `VocabularyReview` SM-2 queue and grading API are unchanged — no new data
   model. The one-at-a-time review UI becomes a flip card: the term on the
   front, and on the back, the confirming lesson's evidence/suggestion,
   recovered by joining back to the originating `LessonInsight` row
   (`category: "vocabulary"`, same teacher/student, matching normalised term
   — `lib/lesson-notes/vocab-context.ts`). If no match is found the back
   just says so; grading behaves exactly as before.
2. **Speaking-time / participation analytics** (teacher-facing). A pure
   `computeSpeakingTime()` (`lib/lesson-notes/speaking-time.ts`) derives
   teacher/student talk time and share of the lesson from `LessonAudio.durationMs`
   (anchors the lesson's total length) and `LessonTranscript.utterances`
   (gives per-speaker segments) — no new columns. Surfaced per-booking on the
   class detail page/screen, and rolled into `StudentLearningProfile` as an
   averaged `speakingBalance` alongside the existing confirmed-insights
   rollup. This required loosening `recomputeStudentProfile`'s
   delete-when-empty guard: a profile now survives with only speaking data
   and no confirmed insights, instead of being deleted whenever there's
   nothing insight-derived to show.
3. **In-call bookmarks.** A `LessonNote` row with a new `kind` discriminator
   (`text` | `bookmark`, migration `20260723000000_add_lesson_note_kind`) —
   deliberately NOT a new model, and deliberately NOT a stored timestamp. A
   bookmark's replay-relative offset is derived at read time as
   `note.createdAt − min(LessonAudio.startedAt)` for the booking, the exact
   same 0-basis `normalizeTimeline` already rebases transcript utterances
   onto (`lib/transcription/merge.ts`). This means the live call client
   never has to track or sync a "recording start" clock of its own — a
   bookmark's jump point is just as accurate as a transcript row's, for
   free. Bookmarks are excluded from every "normal notes" surface (the notes
   panel, the live cue overlay/teleprompter, the AI post-class summary
   source, copy-notes-from-last-class) via a `kind: "text"` filter, and
   surfaced instead as tap-to-seek jump points on the replay view.

**Why it likely changed.** User-requested follow-up work on the D-94
pipeline, not a risk-acceptance or architecture pivot — logged here because
two of the three (bookmarks' derived-timestamp design, the profile's
delete-guard loosening) are non-obvious enough to constrain future work: an
agent reaching for a stored `atMs` on bookmarks, or restoring the
"no-insights ⇒ delete the profile" rule to a strict equality, would be
undoing a deliberate choice.

**What was affected.** `apps/web/prisma/schema.prisma` (+migration),
`lib/lesson-notes/{bookmarks,speaking-time,vocab-context,profile}.ts`,
the class detail + replay pages, the in-call control row (`class-call.tsx`),
the student progress
pages/screens, `packages/shared/src/api.ts` (wire types) and the three
locale catalogs.

**Unresolved risks.**

- A bookmark's derived `atMs` assumes the recording's egress start and the
  transcript's egress starts are close enough in practice to share one
  basis — true today because both are triggered at call join, but nothing
  enforces it structurally. If they ever diverge (e.g. recording starts
  later than lesson-audio capture), a bookmark's seek point drifts by
  exactly that skew.
- `speakingBalance` is a simple average across every lesson with a
  transcript — no recency weighting, no minimum-lesson-count floor before
  showing it. A single unusually one-sided lesson can swing the number.
